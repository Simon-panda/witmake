## 二、选型：OpenWork vs QM（决策依据）

| 维度 | OpenWork | **QM ✅** |
|---|---|---|
| 定位 | 开源版 Claude Cowork，桌面+能力分发 | Multiplayer agent harness，多租户协作框架 |
| 成熟度 | 19.9k⭐（2026-01） | 3.9k⭐（2026-07-29，极新） |
| 许可 | 未明确 | **MIT**（可 private fork） |
| 部署 | 依赖厂商云 | **完全自部署**，数据不出域 |
| 核心抽象 | workspace+能力包 | **scope 级隔离**（记忆/文件/密钥/权限/cron/sandbox） |
| harness | opencode | 可换：Pi/OpenCode/Codex/Claude Code |
| 后台任务 | 无 | cron+watch 一等公民 |
| 安全 | 桌面策略 | 三档 posture + 命令硬拒绝 + 审计 |

**决定性理由**：scope 隔离与"40 骨干人手一 Agent"直接对应；layers 定制分离支持版本冷冻（年升级≤4 次）；全接口化不被锁定。**验证期至 2027-02**（观察上游活跃度与 breaking 频率）。

## 三、架构决策（三入口+四层）

- **入口**：微信小程序（一线）+ 企微授权（告警/审批）+ 网页密码（管理层）——统一身份联邦，identity_map 是地基（38/40 微信已绑）
- **四层**：入口层 → 统一接入网关（auth/映射/路由/审计）→ QM Core（40 scope）+ 主动智能层引擎（独立）→ MCP 共享数据平面
- **权限不下沉**：通道只是身份载体，dept_level 行级过滤只在 MCP 层执行一次
- **告警**：三分发（严重度×角色）、反馈一闭环（任何入口回写同一反馈表）

### 踩坑全记录（下次省 2 小时）

| 坑 | 现象 | 解法 |
|---|---|---|
| curl 写盘被拦 | `curl -o` 任何扩展名任何盘都 exit 23 | **下载用 PowerShell IWR / BitsTransfer** |
| EDB 下载慢断流 | IWR 330MB 只下 9MB 误判完成 | BitsTransfer（断点续传，一次成功） |
| Windows 二进制不认 MSYS 路径 | initdb 把 pgdata 建到 `C:\e\qm-lab\` | Windows 程序传 `E:\...` 反斜杠路径 |
| 前台超时杀树 | `pg_ctl start` 的 60s 超时杀掉 postgres | 服务全部用 background / Start-Process |
| Node 后台静默退出 | core 三次 code=1/127 无栈退出 | Start-Process 解耦 shell 生命周期 + `--trace-exit --report-on-fatalerror` 布控（待抓现场） |
| .bin/opencode spawn ENOENT | Windows 不能执行无扩展 shim | 补丁：`opencode-ai/bin/opencode.exe` + win32 PATH 继承 |
| curl 内联中文乱码 | 模型收到乱码 | `--data-binary @文件`（UTF-8） |
| heredoc/复合命令审批超时 | 多次被拦 | 用 write_file 建脚本再执行 |
| QM 启动慢 | ~25-30s 才监听 | 健康检查要等够 |

## 五、模型接入突破（国产模型必经之路）

**根因**：opencode 内置 openai provider 走 **Responses API** 方言，Moonshot/DeepSeek 只有 **chat/completions**。
**解法**：harness 注入自定义 provider `npm: "@ai-sdk/openai-compatible"` + baseURL 指向国产端点。

**QM 审批模型目录机制**：`MODEL_REGISTRY`（pi-models.ts）+ harness 审批列表，不在目录的模型 refuse。clone 机制：注册条目克隆内置模板拿元数据。生产可用它**锁死只准国产模型**（成本控制抓手）。

已注册：`deepseek/deepseek-chat`（默认）+ `moonshot/kimi-k3`。

## 六、三项测试证据

### 测试 1：scope 隔离 ✅

| 检查 | 结果 |
|---|---|
| 会话列表隔离 | niu 看到 0 条张迪会话 ✅ |
| 越权访问 | 拿他人会话 ID 访问 → `not_found`（不泄露存在性）✅ |
| 跨用户记忆泄露 | 金丝雀 Alpha-7749：niu 的 agent 完全无知 ✅ |
| 会话内记忆 | 同会话准确回忆 ✅ |

**重要发现**：跨会话长期记忆**需 agent 主动写 scope 记忆**（非自动）——治理优点（不偷囤记忆），但部署时需 skill 化"记住我"类指令。

### 测试 2：skill 晋升流 ✅

- 个人 skill（baogong-slang-dict 报工黑话词典）→ niu 不可见 → 晋升 org → niu 可见**且 agent 实际引用词典回答"放飞机=机床空跑"**
- 可见性解析顺序：`personal → shared → teams → org`（可只共享给特定团队，不必全员）
- 晋升三重门：**ADMIN_GRANTS 白名单 + liveActor 真人（cron 不能晋升）+ 审计落库**
- 命名必须 ASCII；存储为 (id,json) 文档表+signature 签名
- 注：正规 agent 晋升路径需 Docker sandbox，本次 DB 层演示最终态（scopeId 翻转）

### 测试 3：Strict 安全档 ✅

- `HARNESS_SECURITY_POSTURE=strict`：execute、write **逐工具拦截**
- 审批三粒度：`once`（本次）/`session`（本会话）/`always`（按 approvalKey 同类放行）
- 关键洞察：**审批发生在工具执行前**，无 Docker 也完整验证了审批流
- 40 人放权映射：lv6 班长=Strict / lv5 主管=Auto / lv4+=Auto 或 Dangerous

## 七、MCP 接 fuadmin（数据平面验证）

**实现**：`E:\qm-lab\mcp-fuadmin\server.py`（stdio MCP，pymysql 直连 E 盘库）——`list_tables`/`describe_table`/`query`（只读 SELECT 强制+LIMIT 200 守卫），harness config 注册 local MCP。

**实测**：问"最新一天治通报工汇总"→ agent 自主调 MCP 答：计划 18,037 / 实产 29,039 / 达成率 161%。

**⚠️ 口径教训**：161% 是裸加总（plan=0 追加单全计入），正式简报口径 83.2%（机加类过滤）。**管道通了之后，口径必须沉淀进 MCP 工具/skill**——否则 40 个班长问出 40 个口径。

## 八、Docker sandbox 要点（Simon 要求重点解释）

- **定位**：core 是大脑，MCP 是数据管道，**sandbox 是手和工作台**——execute/read/write/publish 四工具的执行地
- **持久计算机**：每 scope 一个长寿命容器（`qm-sbx-*`+独立网络 `qm-net-*`），装的工具/文件/cron 现场跨 turn 保留——"长期员工"而非"一次性外包"
- **四层隔离**：文件/进程/凭证（keychain 视图）/网络 + 资源限额——爆炸半径锁死在单 scope
- **与 posture 互补**：姿态管"能不能做"，沙箱管"做了能坏多大事"
- **publish 是被低估的武器**：agent 直接发布 scope 可见的内部 web 应用（看板/小工具），一线自生长
- **40 人资源**：空闲容器 50-200MB/个，8C16G ECS 可装 40 个；生产必上 Linux（Docker 原生）

## 九、账号/预算/用量（Simon 三问）

1. **账号≈零配置**：邮箱一次性链接登录即自动建 scope；本厂走统一网关身份断言，员工不感知 QM 账号；实质工作=identity_map（38/40 微信已绑）
2. **一个 API key 全公司共用**（部署级持有，永不下发浏览器）：双层预算帽（个人/组织）+ 模型白名单 + 限流。建议档位：lv6 $0.5/天、lv5 $1、lv4+ $2、org 总帽 $50/天
3. **用量管控三层**：admin 界面（users/model-providers/observability）+ credentialUsage 台账（Postgres 逐笔）+ 预算硬帽
