## 二、scope 与 strict 概念精解（官方文档+源码）

### scope = 数据/资源「隔离边界」
- 每个 scope 独立：memory / files / keychain / permissions / crons / web apps / durable sandbox
- 每轮对话先解析 **principal（身份）+ scope（作用域）** 再放行
- 安全目标：阻止未经授权跨 scope 读/写/投递；凭据只在授权 scope 内有效
- 制造业类比：个人 scope=张工的工作台+工具柜+私人工艺文件柜；共享房间=公共会议室；grant=唯一跨 scope 通道
- ⚠️ 官方自我声明局限（SECURITY.md）：admin 可审计性读取任何 scope（有记录不需审批）；命令策略可被混淆绕过（减速带非保险柜）；不是多租户公共边界

### strict = 行为执行「审批档位」
| 档位 | 行为 | 类比 |
|---|---|---|
| **Strict** | 每个 tool call 暂停等人工批准（仅两个无副作用 turn ender 例外） | 动火作业审批制：每次动火开动火证 |
| **Auto**（默认） | 分类器筛查带来源标记的外部数据/工具结果 | 巡检制：抽查危险信号 |
| **Dangerous** | 无筛查、无暂停 | 无人值守夜班 |

- ⚠️ 预声明命令政策（硬拒绝递归删除/破坏性 SQL）**所有档位生效**，Dangerous 也不例外
- 理解要点：Strict 不是「更严的 Auto」，而是换协作模式——agent 变提议者、人变执行者；成本是吞吐
- **安全模型 = scope（谁能看见）+ posture（要不要人批）+ 审计（一切有记录）**，三者正交

## 三、部署形态与认证（关键澄清）

### QM 是服务器端部署，不是笔记本安装
- 用户误区：QM ≠ OpenClaw/Hermes 本地安装模式
- 三种部署形态：**Docker**（单机/内网，Postgres 本地容器）/ **Fly.io** / **AWS**（ECS+RDS+CloudFront）
- agent 执行发生在服务器 per-scope sandbox（持久计算机），用户笔记本只是浏览器/Slack 客户端
- 登录：email 一次性链接（内置 auth broker，需 SMTP/Resend）

### Admin 批准流程（Strict 下）
1. 部署层配置 approvals/deny 规则 → CLI 编译进 command policy floor（静态授权，全档位生效）
2. Strict 下 agent 要执行工具调用 → core 暂停 → 推送「待审批动作」到 Web UI/Slack
3. 人类（发起用户或指定审批人）在浏览器点批准/拒绝 → agent 继续
- 类比：OA 审批流——流程挂服务器，经理手机点同意

### 微信登录：需要桥接层
- QM 认证只有两条路：内置 email broker / 外部 IdP（**标准 OIDC**，注册 `<publicUrl>/auth/callback`）
- 微信/企微扫码是 OAuth 2.0 **非标准 OIDC**（无标准 ID Token/JWKS）→ 需桥接 IdP（Keycloak/Logto/Authing）转 OIDC
- 三方案：①桥接 IdP（1-2天部署，正规）②内部账号直连（绕开邮箱）③dev 模式（仅测试，`WEB_UI_PRINCIPALS` 不设置时任意 principal 登录）
- 本机当前即 dev 模式：`{"user":"simon","org":"zhiji","mode":"dev"}`

### 服务器存储：QM 无内置配额（官方承认）
- 存储构成（本机实测）：Postgres 71M / docstore **142M** / workspaces 0
- SECURITY.md 原文："File artifacts have **no expiry**... can **accumulate indefinitely**"
- 方案：①磁盘水位监控+清理脚本（80% 告警）②文件不进 QM 只存引用 ③外部对象存储限额（S3 生命周期）
- 估算基准：10 人 × 50MB/人/周 ≈ 26GB/年；500GB 够 1-2 年，必须配清理策略

## 四、文件上传后能否做 RAG 问答（源码分析结论）

**结论：能问答，但 QM 机制不是传统 RAG——源码 grep `embedding|vector|rag|semantic` 零命中。**

### QM 实际的两套知识机制
| 机制 | 实现 | 类比 |
|---|---|---|
| ① 按需读文件 | agent 用 `execute` 在沙箱 cat/grep 文件，内容进上下文 | 助理去档案室拿文件读 |
| ② LLM 笔记式记忆 | `memory/strategies/`：per-turn（每轮总结）/consolidation（合并）/scratch-promote（草稿晋升），摘要写 Postgres 笔记，后续注入 prompt | 助理把讨论纪要记笔记本 |

### 规模边界
- ✅ ≤几十份文件：原生够用（工艺卡/质量报表/SOP 问答没问题，记忆笔记自动沉淀）
- ❌ 数百份以上：上下文塞爆（一次问答只能翻 ~30-50 份/200K tokens）、无相关性检索、质量退化

### 真 RAG 三方案
| 方案 | 做法 | 适用 |
|---|---|---|
| ① 轻量 | 定期让 agent 把文件总结进 memory 笔记（原生 consolidation 方向） | ≤200 份 |
| ② 外部 RAG | 自建 embedding+向量库（pgvector/Chroma），QM 部署层加 tool 查询 | 文件多、要精确检索 |
| ③ 现成平台 | Dify/RAGFlow 做后端知识库，QM 做前端 agent API 桥接 | 全厂级 |

**一句话：QM 文件是「档案室」不是「搜索引擎」——小档案室助理够用，大档案馆要配检索系统。**

### ✅ 已验证：文件上传链路（无需 Docker）
```
创建工艺卡(ZK-2026-045, 1386B) → POST /api/blobs?sha=...（sha256 校验）
→ POST /api/files/upload?scope=personal:simon → 注册成功
→ GET /api/files/:id/content 内容完整读回
```
- 关键坑：ScopeId 格式是 `personal:simon`（冒号），不是文件系统目录名 `personal__simon`（首次 403 由此导致）
- 上传成功：file id=76ade1ff65c5e48d3acb2433dafaa80f, ownerScopeId=personal:simon
- 附件链路：turn 支持 `attachments: [{name,mimetype,sizeBytes,blobId}]`，文件随 turn 进上下文不走沙箱

### ❌ 阻塞点：Agent 问答链路需要 Docker
- core.log 实锤：`[swallowed] worker: background run crashed: SANDBOX_BACKEND=local requires a running Docker daemon (is Docker Desktop running?)`
- QM 三种沙箱后端：local（Docker）/ sprites（云端 API）/ aws（Lambda）——**无免 Docker 纯本地执行模式**
- agent 思考路径正确：先 grep `/root/workspace` → 再读 global/shared，沙箱一开即可读到上传文件
- 附带：OpenCode harness 有 `prompt failed` 报错（安全屏调用），需一并排查

### ✅ turn_request.json 验证（ad-hoc 临时脚本，9/9 PASS）
| 检查项 | 结果 |

| JSON 语法 / text 非空 / threadRef `web:` 前缀 / scopeId `personal:` 格式 | ✅ |
| attachments 列表 / name+blobId / sizeBytes=1386 / blobId 匹配 / 中文无乱码 | ✅ |
