## 第二部分：API 建设科普

### 一句话理解 API

**API = 系统之间的"插座"**。你拿一根数据线（API 调用），把 A 系统（比如刀具管理系统）的数据接到 B 系统（Agent 引擎），B 系统就能用 A 的数据做判断。

在这个项目里，API 建设就是把 5-6 个已有系统（MES、刀具管理、三坐标、对刀仪、HR、SPC）的数据，统一格式接到 Agent 引擎里。

---

### 具体要建的 API（= MCP Server）

每个 MCP Server 就是一个小盒子，把老系统的数据库/接口包装成统一的 JSON 格式。

#### 1. 刀具管理 MCP Server

`
输入  → "查 T-2031 号刀在 CNC-03 上的数据"
输出  → {
    "tool_id": "T-2031",
    "machine": "CNC-03",
    "installed_at": "2026-06-28 08:15",
    "total_parts_cut": 847,
    "rated_life": 1200,
    "remaining_life_pct": 29.4,
    "preset_value": 125.00,
    "current_wear_um": 18.2,
    "last_measured_at": "2026-06-28 14:00"
  }
`

**对接方式**：直接连刀具管理系统的数据库（只读），一条 SQL → 返回 JSON。

#### 2. 三坐标 MCP Server

`
输入  → "查 BR-2031-A 零件孔径尺寸，最近 48 小时"
输出  → {
    "part_no": "BR-2031-A",
    "feature": "bore_diameter",
    "nominal": 35.000,
    "upper_tol": 0.015,
    "lower_tol": 0.000,
    "measurements": [
      {"time": "2026-06-28 08:30", "value": 35.008, "tool": "T-2031"},
      {"time": "2026-06-28 09:00", "value": 35.009, "tool": "T-2031"},
      {"time": "2026-06-28 09:30", "value": 35.011, "tool": "T-2031"}
    ]
  }
`

**对接方式**：三坐标报告通常是数据库（如 SPC 系统的子表），也可能是文件（PDF/CSV）。如果有数据库直接查最快；如果是 PDF，需要 OCR 解析——但建议推动三坐标厂商开放 API，这是你作为客户的权利。

#### 3. 对刀仪 MCP Server

`
输入  → "查 T-2031 过去所有测量记录"
输出  → {
    "tool_id": "T-2031",
    "history": [
      {"date": "2026-06-20", "preset": 125.00, "wear": 0},

**对接方式**：对刀仪通常自带数据库（SQLite 或本地 MySQL），或者通过 RS232/网口输出 CSV。IT 需要写一个中间程序把文件/串口数据解析入库，然后 MCP Server 从库读。

#### 4. MES 工序流转 MCP Server

`

`

**对接方式**：MES 一般有 SQL Server / MySQL / Oracle 数据库，直接只读查询。

#### 5. HR 技能矩阵 MCP Server

`
输入  → "查员工王某某在工序精镗孔的技能状态"
输出  → {
    "employee": "王某某",
    "process": "精镗孔",

    "last_assessment": "2026-05-15"

`

**对接方式**：如果技能矩阵在 HR 系统里，直接查。如果在 Excel 里（很多工厂确实如此），需要先把它导入一个结构化数据库——这是 IT 和 HR 的第一步合作。

## 第三部分：刀具磨损→尺寸分析深度拆解

这是用户具体提出的场景：**用刀具更换记录 + 三坐标测量记录 + 对刀仪数据，实现四条分析能力。** 逐一拆解。

---

### 场景设定

CNC-03 机床上，T-2031 镗刀在加工 BR-2031-A 零件的孔径（名义值 Φ35.000，公差 +0.015/-0.000）。刀具每加工一件零件会磨损一点，导致孔径逐渐变大。当孔径接近公差上限（Φ35.015），就需要调整刀补（让刀多往内偏一点），或者在磨损过快时提前换刀。

**你已有的数据**：

| 数据来源 | 有什么 | 粒度 |
|---|---|---|
| 刀具更换记录 | 什么时候换刀、换的什么型号、旧刀加工了多少件 | 每次换刀一条记录 |
| 三坐标报告 | 每件/每 5 件的孔径实测值 | 逐件或按频次 |
| 对刀仪数据 | 每次测刀的预设值和实际磨损量 | 每次测刀一条记录 |

---

### 分析 1：刀具更换之后，对刀补的自动调整

**通俗理解**：换了一把新刀，刀尖位置和旧刀不一样（新刀比旧刀长/比旧刀短）。如果还按旧刀的补偿值加工，第一件就可能超差。系统要自动算出一个新补偿值。

**算法逻辑**：

`
换刀事件发生 →
  ① 从对刀仪拿新刀的预设值（preset = 125.00mm）
  ② 从对刀仪拿旧刀最后一次的实测值（actual = 124.82mm，磨损了 0.18mm）
  ③ 从 MES 拿换刀前三坐标最近 5 件的孔径均值（35.010mm）
  ④ 计算：
     目标孔径 = 35.000（名义值）
     当前偏移 = 35.010 - 35.000 = +0.010mm（孔偏大了 10μm）
     旧刀磨损引起的偏移 = 0.18mm × 磨损系数（经验值，比如 0.7）= 0.126mm
     说明在旧刀生命周期末段，刀补已经"帮"磨损做了补偿
     新刀没有磨损 → 需要把旧刀生命周期积累的补偿"归零"
     新刀补 = 旧刀末次刀补 - 磨损引起的补偿值

  ⑤ 推送给操作工："T-2031 已更换，建议刀补从 -0.12 调整到 +0.05"
     或直接通过机床接口自动写入刀补表（需要机床支持）
`

**数据流（伪代码）**：

`python
def compute_new_offset(tool_id, machine_id):
    # 1. 从刀具 MCP 拿换刀记录
    tool_change = tool_mcp.get_last_change(machine_id)

    # 2. 从对刀仪拿新旧刀数据
    preset_new = presetter_mcp.get_preset(tool_change.new_tool_id)
    wear_old = presetter_mcp.get_last_wear(tool_change.old_tool_id)

    # 3. 从三坐标拿换刀前最后 5 件的尺寸
    last_parts = cmm_mcp.get_recent_measurements(
        part_no=tool_change.part_no,
        feature=tool_change.feature,
        before=tool_change.changed_at,
        limit=5
    )
    avg_deviation = mean(p.actual - p.nominal for p in last_parts)

    # 4. 计算新刀补
    wear_factor = 0.7  # 工艺工程师给定，或从历史数据拟合
    offset_from_wear = wear_old * wear_factor
    new_offset = tool_change.old_offset - offset_from_wear + avg_deviation

    return {
        "new_offset": round(new_offset, 3),
        "confidence": 0.85,
        "basis": f"旧刀磨损{wear_old}μm，末段孔径偏差{avg_deviation}μm"
    }
`

**需要多少数据**：每次换刀都能算。冷启动用 wear_factor = 0.7（通用经验值），积累 30 次换刀后可以回归出精确系数。

### 分析 2：刀具寿命情况

**通俗理解**：一把刀从新刀用到报废，中间经历多少次"正常"和"异常"。历史数据能告诉你这把刀"一般用多久"，然后和当前对比——如果当前用得太短（异常磨损），提前预警。

**算法逻辑**：

`
① 从刀具更换记录里，拉出 T-2031 型号过去 3 个月所有的"上刀→卸刀"周期

② 计算每个周期的加工件数：
   T-2031, 周期1: 上刀 05-01 → 卸刀 05-08, 加工 1200 件
   T-2031, 周期2: 上刀 05-09 → 卸刀 05-15, 加工 1100 件
   T-2031, 周期3: 上刀 05-16 → 卸刀 05-19, 加工  600 件  ← 异常短！
   ...

③ 统计分布：
   P50 = 1150 件（一半的刀能用到 1150 件以上）
   P10 =  850 件（只有 10% 的刀用到 850 件以下就挂了）

④ 当前这把刀已经加工了 847 件 → 还剩 (850-847)/850 = 0.35% 到 P10 线
   → 触发 TOOL_LIFE_CRITICAL 告警

⑤ 如果某型号刀的 P10 突然下降（30 天均值 × 75%）：
   → 触发 TOOL_LIFE_ABNORMAL_SHORT 告警
   → 提醒工艺工程师检查来料硬度 / 切削参数
`

**动态阈值 vs 固定阈值**：

`
固定阈值（不好）：
  "剩余寿命 < 15%" → 一刀切，不区分刀具型号、加工材料、季节

动态阈值（好）：
  T-2031 加工铝合金 → P10=850 → 阈值设在 850×1.05=893 → 893 件时预警
  T-1542 加工铸铁   → P10=420 → 阈值设在 420×1.05=441 → 441 件时预警
`

**数据需求**：至少 30 天刀具更换记录（≥ 50 条更换事件）。初期用固定阈值，数据够了再切动态。

### 分析 3：磨损对尺寸产生的影响

**通俗理解**：刀在加工过程中磨损，刀尖位置会变化 → 加工出的零件尺寸跟着漂移。如果能定量描述"每磨损 1μm → 孔径变大多少"，就能从磨损量预测尺寸走向。

**核心发现**：这个关系不是线性的。一把刀从新到报废，磨损对尺寸的影响有三个阶段：

`
阶段 1（初期快磨）：前 20% 寿命，磨损快但影响小（刀具涂层在"磨合"）
阶段 2（稳态磨损）：中间 60% 寿命，线性关系——每加工 100 件，孔径稳定变大 ~0.5μm
阶段 3（末期加速）：最后 20% 寿命，磨损加速，尺寸漂移也加速
`

**拟合方法**：

1. 把对刀仪数据和三坐标数据按时间对齐——同一把刀、同一时间段
2. 横轴 = 刀具累计加工件数（代替时间）
3. 纵轴 = 尺寸偏差（三坐标实测值 - 名义值）
4. 分段线性回归，找出每个阶段的斜率

`python
def fit_wear_to_dimension(tool_id, life_cycle_id):
    # 拉对齐数据
    wear_data = presetter_mcp.get_wear_curve(tool_id, life_cycle_id)
    dim_data = cmm_mcp.get_deviation_curve(tool_id, life_cycle_id)
    aligned = align_by_part_count(wear_data, dim_data)  # 按加工件数对齐

    # 分段
    n = len(aligned)
    p1 = aligned[:int(n*0.2)]   # 前 20%
    p2 = aligned[int(n*0.2):int(n*0.8)]  # 中间 60%
    p3 = aligned[int(n*0.8):]   # 后 20%

    # 稳态段（最重要的部分）
    slope_p2 = linear_regression(p2.x, p2.y).slope
    # slope_p2 = 0.005 μm/件  → 每加工 100 件，孔径大 0.5μm
    r2_p2 = linear_regression(p2.x, p2.y).r_squared

    return {
        "phase1_slope": slope_p1,
        "phase2_slope": slope_p2,         # 这个最关键
        "phase3_slope": slope_p3,
        "phase2_r2": r2_p2,
        "transition_point_2_to_3": aligned[int(n*0.8)].part_count
    }
`

**输出给工艺工程师看的东西**：

`
┌─────────────────────────────────────────────┐
│  T-2031 镗刀 | BR-2031-A 孔径 | 最近 10 个周期 │
│                                              │
│  稳态磨损系数: 0.0052 μm/件 (R²=0.89)         │
│  含义: 每加工 100 件，孔径增大 0.52μm          │
│  末期加速点: 约 960 件（P10=850 件之后）       │
│                                              │
│  结论:                                        │
│  - 公差带 15μm，稳态磨损每 100 件吃 0.52μm     │
│  - 如果不调刀补，2885 件后超差                 │
│  - 但实际 P10=850 件，刀具寿命先到，尺寸容      │
│    忍度不是瓶颈                                │
└─────────────────────────────────────────────┘
`

**数据需求**：至少 30 个完整的刀具生命周期（上刀→工作→卸刀），且每个周期至少有 10 个三坐标测量点分布在过程中。

### 分析 4：基于磨损情况拟合出最佳刀补时间

**通俗理解**：知道磨损会让尺寸漂移之后，什么时候去调刀补最划算？调太早——浪费产能（停机调整耗时）；调太晚——尺寸超差风险高。找一个时间点，让"不调刀补的风险"和"调刀补的成本"平衡。

**这不是"预测什么时候该换刀"——换刀是刀具寿命问题。刀补调整是在刀具寿命内，微调补偿值来维持尺寸精度。**

**算法逻辑**：

`
已知：
  稳态磨损系数 = 0.005 μm/件（从分析 3 得来）
  公差带宽度 = 15μm
  当前偏差 = 10μm
  停机调整耗时 = 15 分钟
  单件节拍 = 3 分钟
  超差一件的损失 = ¥200（报废/返工）

计算：
  不调刀补，还能坚持多久？
    剩余公差 = 15 - 10 = 5μm
    剩余件数 = 5 / 0.005 = 1000 件
    → 从尺寸角度，还能加工 1000 件
    但刀具寿命 P10 = 850 件，当前已加工 700 件 → 只剩 150 件
    → 刀具寿命先到瓶颈，不需要从尺寸角度调刀补

但如果换个场景：刀具寿命够长，但公差很紧：
  剩余公差 = 5μm, 还能加工 1000 件
  但每 300 件就去调一次刀补，可以"吃满"刀具寿命
  建议：当前立刻调刀补，然后每 300 件再调一次
`

**最优刀补时机计算公式**：

`
目标函数：min(停机损失 + 超差风险损失)

设：
  C_stop = 每次停机调整的成本（时间 × 机时费）
  C_scrap = 每件超差的损失
  μ = 磨损系数（μm/件）
  T = 公差带宽度（μm）
  current_dev = 当前偏差
  remaining_tool_life = 刀具剩余寿命（件）

经验规则（可以先用规则，再换 ML）：
  当 偏差(t) > T × 0.65 且 剩余刀具寿命 > 调整后再加工 50 件 → 立即调整
  当 偏差(t) > T × 0.80 且 还未到换刀时机 → 必须调整（无论代价多大）
`

**分场景推荐**：

| 场景 | 策略 | 为什么 |
|---|---|---|
| 磨损慢 + 公差宽 | 换刀时一起调刀补，刀具寿命期不再单独调 | 尺寸漂移不是瓶颈 |
| 磨损慢 + 公差窄 | 每 200-300 件调一次，不等换刀 | 公差是瓶颈，要主动维持 |
| 磨损快 + 公差窄 | 查来料/参数，可能根本原因不在刀 | 刀补调整治标不治本 |
| 磨损加速（末期） | 提前 50 件换刀，不在末期调刀补 | 末期斜率陡，调了也很快偏掉 |

**模型进阶**：积累足够数据后，可以用一个简单的回归模型预测每把刀的最优干预点：

`
训练特征：
  - 刀具型号
  - 工件材料
  - 切削参数（转速/进给/切深）
  - 冷却液类型
  - 历史磨损系数（从分析 3 来）

预测目标：
  - 最佳刀补时机（加工件数）
  - 置信区间（±20 件）

模型选型：XGBoost → 理由：表格特征 + 非线性关系 + 可解释
`

**业务上先跑规则，再跑 ML**。规则版可以直接上线，ML 版需要 6 个月以上训练数据。
