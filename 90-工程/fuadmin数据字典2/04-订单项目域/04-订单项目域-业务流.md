# A5 订单项目+人事系统域 业务流（规则引擎锚点版，待agent精修替换）

## 1. 客户订单→项目→交付链
表链路: generator_customer_order（客户订单, count=box_number×number 总数量=总箱数×装箱量, order_state True=已完成/False=未完成） → generator_project_info（项目） → generator_project_schedule（项目进度） → 生产 → generator_qrcode_sendout（扫码发货, customer_order_id 软外键回链）
说明: 客户订单为发货判定主表（行内注释"实际的发货订单表用于判断是否已经发货完成"）；customer_order_number 客户订单号可空勿当唯一键；sendout 发货时回写订单状态完成交付闭环。

## 2. 项目物料与人员链
表链路: generator_project_info（项目） → generator_project_material_summary + generator_project_material_summary_detail（项目物料汇总/明细） → generator_project_personal（项目人员, project_info 字段为 varchar 存项目code非FK）
说明: 项目物料汇总支撑领料出库（warehouse 出库按 project_qrcode 匹配项目物料）；detail_copy1 存在订单头/明细行两版口径并存（沿用旧锚点，待代码复核）。

## 3. 权限体系（用户-角色-菜单-部门-岗位）
表链路: system_users（用户, gender 0=女/1=男, user_type 0=后台/1=前台） → system_users_role（M2M） → system_role（角色, data_range 0=仅本人/1=本部门/2=本部门及以下/3=全部/4=自定义） → system_role_menu（M2M） → system_menu（菜单, type 0=目录/1=菜单）；system_dept（部门）/ system_post（岗位, status 0=离职/1=在职）
说明: RBAC 标准模型：用户经 M2M 挂角色，角色经 M2M 挂菜单；data_range 五级数据权限；system_role_dept/system_role_column/system_role_permission 为角色-部门/列/权限细粒度授权中间表；django_admin_log.user_id→system_users 为硬FK锚点。

## 4. 人事全周期链
表链路: generator_roster（花名册, health_report 有/无/异常） → generator_employment_registration（入职登记） → att_transaction（考勤打卡, punch_time 打卡时间≠入库时间） → generator_salary（薪酬） / generator_kpi（绩效）
说明: 考勤由外部考勤机对接（verify_type 验证方式、terminal_sn 终端）；temperature/mask_flag 为疫情期遗留字段；日报 dailyreport/dailytask/monthlytask 代码已移除（历史遗留表）。

## 5. 财务补贴与规则
表链路: generator_finance_rule（财务规则） → generator_finance_subsidies（补贴记录）
说明: 规则驱动补贴核算；finance 模块仅 2 表，主财务口径在 payment（付款）与 settlement（结算，未启用）。
