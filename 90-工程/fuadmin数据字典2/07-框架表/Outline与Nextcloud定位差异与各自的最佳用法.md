一句话概括：**Outline 管"知识"，Nextcloud 管"文件"。** 两者重叠度比你想象的低——它们不是竞品，经常互为补充。 --- ## 一、本质区别 | 维度 | Outline | Nextcloud | |---|---|---| | 核心对象 | **文档**（富文本块，结构化知识） | **文件**（字节流：xlsx / psd / mp4 / zip…） | | 设计目标 | 团队 wiki：可搜索、可协作、可长期维护的文字知识 | 自建云盘：同步、共享、版本、客户端挂载 | | 主入口 | 浏览器 + Markdown 快捷键 + `Ctrl/Cmd+K` 搜索 | 桌面/移动客户端同步、WebDAV、浏览器 | | 访问模型 | 在线读写，文档是"活的" | 本地文件为副本，靠同步协议保持一致 | | 版本管理 | 文档编辑历史（每次改动可回溯、可回滚） | 文件版本（按时间/空间策略保留）+ 回收站 | | 协作 | 多人实时协同编辑、评论、@提及、草稿/发布状态 | 文件锁 + OnlyOffice/Collabora 在线协同；无"段落级"讨论 | | 搜索 | 全文检索（默认基于 PostgreSQL），标题+正文 | 文件名/基础全文（大文件、二进制依赖索引配置） | | 权限模型 | Collection / Group 分级 + 公开分享链接 | 用户目录 + 共享 + Group Folders + 外部共享 | | 接口 | REST API + Webhooks，适合自动化写文档 | OCS API + WebDAV，适合自动化传/取文件 | | 扩展能力 | 相对单一、专注 | 套件：Talk、日历、通讯录、Office、表单、备份等 | | 存储后端 | DB + 附件存储（本地/S3） | data 目录（本地/NFS/S3/SMB/外部存储挂载） | | 资源画像 | Node + PostgreSQL(+Redis)，内存敏感 | PHP-FPM + DB + Cron，**更重、更吃 IO 和后台任务** | | 典型误用 | 当网盘传大附件 | 当 wiki 写长文档 | **判断口诀（决策树）：** 1. 这份东西会被**反复阅读、修订、引用**，内容本身就是资产 → **Outline** 2. 这份东西是**要下载/用专业软件打开**的文件（表格、图纸、素材、合同扫描件、视频）→ **Nextcloud** 3. 两者都需要 → **文件进 Nextcloud，Outline 里放一份带链接的索引/说明**（这是最健康的模式） --- ## 二、Outline 的最佳实践 **信息架构** - 按**团队/领域**建 Collection（如 `产品`、`运维`、`客户交付`），**不要按人建**——知识会随人员流动而失联。 - 每个 Collection 首页放一篇"导航页"（目录 + 常用链接），新人从这一页进入。 - 用 **Template** 固化高频文档结构（周报、复盘、SOP、事故报告），保证格式一致、可批量检索。 - 用 **Draft → Published** 做审阅流程；过时文档用 **Archive** 而不是删除（保留可搜索的历史）。 - 标题写**具体关键词**（"MySQL 主从切换 SOP" 而非 "切换流程"），因为抓取主要靠全文检索。 **权限与分享** - 权限授予 **Group，而不是个人**；尽量在 Collection 层配置完，避免逐篇文档零散授权（后期无法治理）。 - 对外分享集中在 **一个 public Collection**，统一走分享链接（设只读，必要时设过期与密码）。 - 敏感文档（薪酬、密钥、客户数据）单独隔离 Collection，**永不进公开分享**。 **集成** - 接 **OIDC/SAML/LDAP SSO**，与 Nextcloud 共用同一身份源，避免两套密码。 - 用 **API Token + Webhooks** 做自动化：CI 结果、值班记录、发布说明自动生成为文档。 - 用 Embed 嵌 Figma / Loom / 图表 / **Nextcloud 公开分享链接**，让知识页成为"入口"而不是"仓库"。 **内容边界（重要）** - **不要把大文件往 Outline 传**：附件上限、备份体积、导出能力都会变差。视频、安装包、素材一律走 Nextcloud 或对象存储，只在文档里留链接。 - 不在 Outline 里维护"表格型数据"（清单超过几十行就该去专门系统或 Nextcloud 表格）。 **运维备份** - 必须一起备份：**PostgreSQL dump + 附件存储（本地 uploads 或 S3）+ 环境密钥（`SECRET_KEY` / `UTILS_SECRET`）**。只备数据库、丢了 secrets，等于恢复不出来。 - 升级：先备份再滚动镜像版本；大版本注意迁移脚本。 - 健康检查：`/api/health`（或 `_health`），加监控。 --- ## 三、Nextcloud 的最佳实践 **目录与权限治理（最容易失败的地方）** - 用 **Group Folders（团队文件夹）** 做共享，**不要靠"个人目录逐个分享"**——那是权限失控的根源。 - 配额（Quota）按组设置，个人默认给一个够用但不夸张的值；定期跑占用报告。 - 外部共享默认**关闭或加密码+有效期**；对外交付用有时限的分享链接。 - 建立命名与目录规范（如 `部门/项目/年度-类型-版本`），并写进入职文档。 **客户端与访问方式** - 桌面客户端开**选择性同步**，别让全员全量落盘（SSD 和带宽都会哭）。 - 服务器/脚本用 **WebDAV**（rclone / davfs2 / Windows 映射驱动器），不要用客户端做自动化。 - 移动端按需开"自动上传照片"，并注意它产生的存储与隐私问题。 **版本与空间** - 配置版本保留策略与回收站保留期（`versions_retention_obligation`、`trashbin_retention_obligation`）。 - 记住：**删除 ≠ 释放空间**，还在回收站里，需要按策略清理。 - 重要目录保留更长版本历史，临时目录短一点。 **上限与性能** - 大文件三处都要放开：Nginx `client_max_body_size`、PHP `upload_max_filesize`/`post_max_size`/超时、以及使用分片上传。任一处没改，用户只会看到"上传失败"。 - **Cron 必须是系统 cron（AJAX cron 只适合玩具环境）**，否则后台任务、通知、扫描全堆着。 - OnlyOffice / Collabora 提供在线协同，Talk 负责沟通——但每加一个套件都加一份运维成本，按需上。 **安全与运维** - 强制 HTTPS、全员 2FA、开启暴力破解防护（配合 fail2ban）。 - 常用维护命令：`occ status`、`occ files:scan`、`occ maintenance:mode --on/--off`；升级**逐大版本**进行。 - 备份遵循 3-2-1：**DB dump + data 目录 + config**，且在 maintenance mode / 停容器下做一致性备份；**定期做恢复演练**（没演练过的备份等于没有备份）。 - 后台"安全与设置警告"面板要定期清零，它是这类自建服务最常见的隐患入口。 --- ## 四、两者如何配合（推荐架构） ``` 统一身份（Keycloak/Authentik/LDAP + OIDC） │ ├── Outline → 知识：SOP、架构、决策记录、复盘、新人手册 └── Nextcloud → 文件：交付物、素材、合同、表格、备份归档 ▲ Outline 文档内嵌 Nextcloud 分享链接（附件索引） Nextcloud 各项目目录放 README，指向 Outline 对应页面 ``` - **双向链接**：文件在网盘，说明在知识库；两边各留一个"入口文件/入口页"，避免出现"文件找不到、文档不知道配哪份文件"。 - **域名与入口统一**：同一主域下的子域 + 内部门户书签，团队不必记两个地址体系。 - **反模式清单**：Outline 当网盘 ❌ / Nextcloud 当 wiki ❌ / 靠个人分享堆积权限 ❌ / 两套独立账号体系 ❌ / 只有备份没有恢复演练 ❌。 --- ## 五、30 天落地清单（可直接执行） | 周 | Outline | Nextcloud | |---|---|---| | 1 | 按团队建 Collection + 导航页；拉一份文档模板 | 梳理 Group Folders 与配额；关闭不必要的外部共享 | | 2 | 接入 SSO；配置公开分享规范 | 放开上传上限；确保系统 cron；桌面端选择性同步 | | 3 | 迁移核心 SOP/复盘；建立归档规则 | 配置版本/回收站策略；WebDAV 用于自动化 | | 4 | 备份脚本 + 恢复演练；API 自动化试点 | 备份脚本 + 恢复演练；安全警告清零；升级到稳定版 | --- 如果你把服务器上的实际情况给我（比如两者的部署方式 `docker-compose`/版本号、SSO 用的是什么、用户规模与总数据量、是否已接 S3），我可以把它变成**针对你这套环境**的具体配置项和核对清单——包括权限模型的具体映射、上传/超时参数、备份脚本和恢复演练步骤。 需要的话也告诉我：你现在最想解决的是**权限混乱**、**搜索找不到东西**、还是**备份/升级风险**？这三个方向的处方差别很大。
