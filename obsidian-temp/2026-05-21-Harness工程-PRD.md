# Harness工程实施PRD：提升开源模型工具调用能力

> 来源：Simon分享（Cloud加的PRD版本）
> 时间：2026-05-21
> 关系：与核心方法论互补，为工程实施层面

---

### 一、核心认知

| # | 洞察 | 说明 |
|---|------|------|
| ① | **问题本质** | 90%"模型不会调工具"实为Harness问题，非模型能力缺陷 |
| ② | **核心痛点** | 开源模型因训练数据局限易犯固定格式错误，闭源模型靠统计分布"蒙对" |
| ③ | **错误分类** | 四种跨模型一致错误 |
| ④ | **特殊案例** | DeepSeek Markdown链接泄漏（两行正则解决） |
| ⑤ | **架构原则** | "先校验再修复"：合法输入永不触碰 |
| ⑥ | **关系处理** | "推断意图+透明告知"：偏移量缺省=0，行数限制缺省=2000 |
| ⑦ | **工程本质** | 为每个模型定制"错误地图"，非通用中间件 |
| ⑧ | **遥测体系** | 模型×工具维度修复率监控，早期预警 |
| ⑨ | **工作流** | "接入-观察-修复"循环 |
| ⑩ | **核心价值** | 快速探测模型边界的能力 > 修复规则本身 |

---

### 二、四种基础错误

| # | 错误类型 | 修复思路 |
|---|----------|----------|
| 1 | 可选字段传 `null` | 删除 null 字段 |
| 2 | 数组写成字符串 | 解析字符串为 JSON 数组 |
| 3 | 期望数组传裸字符串 | 单值包装为数组 |
| 4 | 期望数组传空对象 `{}` | 替换为 [] |

### 三、实施关键路径

| 阶段 | 操作 | 代码量 |
|------|------|--------|
| Phase 1 | 部署校验器驱动的基础框架 | 50行 |
| Phase 2 | 用标准任务集跑目标模型，收集首周修复数据 | — |
| Phase 3 | 根据错误地图定制模型专属修复模块 | ~30行/模块 |
| Phase 4 | 配置模型×工具维度的监控看板 | — |
| Phase 5 | 每两周迭代错误地图数据库 | — |

### 六、金句

> **Harness工程不是写代码，而是绘制模型能力边界的导航图——真正的工程智慧不在于修复了多少错误，而在于用最小代价精准定位哪些错误值得修复。**

> **当你面对一个"不会调工具"的模型时，先别急着换模型，试试用300行代码给它装上翻译器。**
