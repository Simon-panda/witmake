# 2026-05-21 笔记

## Harness工程：工具调用修复的核心方法论

> 来源：Simon分享的技术笔记
> 核心命题：300行代码让开源模型达到商业模型性能的关键

---

### 一、核心认知（10条洞察）

| # | 洞察 | 说明 |
|---|------|------|
| ① | **问题本质** | "模型不会调工具"——90%是Harness问题，非模型能力问题 |
| ② | **错误模式** | 跨模型一致的四种格式错误 |
| ③ | **特殊案例** | Markdown链接泄漏——DeepSeek后训练分布泄漏至工具调用边界 |
| ④ | **正确流程** | "先校验再修复"——合法输入永不触碰，仅对校验器指出的问题精确修复 |
| ⑤ | **关系处理** | "推断意图+透明告知"原则，如默认偏移量=0 |
| ⑥ | **工程本质** | 高度模型定制化，需为每个模型绘制"错误地图"并针对性修复 |
| ⑦ | **可迁移方法** | "先校验再修复"架构、四种形状修复分类框架、关系不变量处理原则是通用方法论 |
| ⑧ | **遥测机制** | 按模型×工具维度建立修复率监控体系，实现问题早期预警 |
| ⑨ | **工作流** | 真实工作流是"接入-观察-修复"循环，而非设计完美通用系统 |
| ⑩ | **核心能力** | 快速探测模型边界并针对性修复的能力 > 修复规则本身的价值 |

---

### 二、四种跨模型一致的格式错误（错误模式）

| # | 错误类型 | 描述 |
|---|----------|------|
| 1 | 可选字段传 `null` | 模型将可选参数显式传 null |
| 2 | 数组写成字符串 | JSON 数组被序列化为字符串 |
| 3 | 期望数组传裸字符串 | 数组字段传入单个字符串值 |
| 4 | 期望数组传空对象 `{}` | 数组字段传入空对象 |

---

### 三、特殊案例：Markdown链接泄漏

- **现象**：DeepSeek后训练分布泄漏至工具调用边界
- **表现**：模型在工具调用中输出 Markdown 格式的链接文本
- **本质**：模型训练数据中的格式习惯污染了结构化输出边界

---

### 四、"先校验再修复"工作流（7步）

```
接收原始输入 → 校验 → 修复 → 再校验 → 执行 / 重试
```

| 步骤 | 操作 |
|------|------|
| 1 | 搭建工作流：接收原始输入→校验→修复→再校验→执行/重试 |
| 2 | 建立四种基础修复规则覆盖常见格式错误 |
| 3 | 为Markdown链接泄漏等模型特定问题添加针对性修复 |
| 4 | 对关系不变量问题实施默认值策略（偏移量=0，行数限制=2000） |
| 5 | 按模型×工具维度统计修复率，建立监控预警机制 |
| 6 | 设计标准任务集，快速探测新模型的边界和失败模式 |
| 7 | 优化"接入-观察-修复"循环速度，降低模型切换成本 |

---

### 五、可迁移的通用方法论

| 组件 | 说明 |
|------|------|
| 🏗️ **"先校验再修复"架构** | 合法输入不触碰，仅修复校验器指出的问题 |
| 🧩 **四种形状修复分类框架** | 统一的错误分类和修复策略 |
| 🔗 **关系不变量处理原则** | 推断意图 + 透明告知，设定安全的默认值 |
| 📊 **模型×工具监控仪表盘** | 修复率遥测，阈值告警 |
| 📋 **标准任务集** | 快速探测新模型的边界和失败模式 |
| 🔄 **标准化工作流文档** | "接入-观察-修复"循环 |
