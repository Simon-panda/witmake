## 0. 为什么这份文档比模型本身更重要

> **没有干净的数据,再好的模型都是 garbage out。模型代码占总工作量 30%,数据基础设施占 60%,业务流程改造占 10%——多数项目失败在第一项被严重低估。**

本方案分两大块:
1. **刀具 ID 体系**(P0,M1-M2 必须完成)——是刀具寿命预测的数据底座
2. **工艺参数库**(P0,M3-M6)——是参数智能推荐的数据底座

## 1. 刀具 ID 体系建设

### 1.1 编码规则(强制规范)

每把刀具上机前必须有唯一 ID。编码格式 14 位:

```
T C - M F - T Y - S Z - S N - C K
│ │   │ │   │ │   │ │   │ │   │ │
│ │   │ │   │ │   │ │   │ │   └─┴─ 校验位 (mod 36)
│ │   │ │   │ │   │ │   └─┴─ 流水号 (00-ZZ,base36)
│ │   │ │   │ │   └─┴─ 规格代码 (D10/D20 等)
│ │   │ │   └─┴─ 类型 (ML铣/DR钻/RM铰/TP丝攻/BR镗)
│ │   └─┴─ 厂家代码 (SD山特/IS伊斯卡/MT三菱/CM国产合金/ZZ自定义)
└─┴─ 固定前缀 TC (Tool Code)
```

**示例**:`TC-IS-ML-D10-001A-7`(伊斯卡铣刀,直径 10mm,第 26 把,校验位 7)

### 1.2 物理标识方案

| 方案 | 单价 | 适用 | 推荐度 |
|------|-----|-----|-------|
| 激光打标 DMC 二维码(刀柄) | <2 元/把 | 全部刀具 | ⭐⭐⭐⭐⭐ |
| RFID 标签 | 30-80 元/把 | 仅高价值刀具(>2000 元/把) | ⭐⭐⭐ |
| 物理刻字 | <1 元/把 | 不推荐(易模糊) | ⭐ |

**推荐方案**:DMC 二维码全覆盖 + RFID 仅高价值刀具(预计 200 把以内)。

DMC 打标设备:工业激光打标机 1 台(约 3-5 万),委外代工也可(0.5-1 元/把)。

### 1.3 全生命周期状态机

每把刀具的状态严格按下图流转,每次状态变化必须扫码记录:

```
                    ┌──────────┐
                    │   入库    │
                    └─────┬────┘
                          ▼
                   ┌────────────┐
                   │  待领用     │ ← 仓库系统
                   └─────┬──────┘
                         ▼
                  ┌─────────────┐
                  │   已领用     │ ← 操作工/班长扫码
                  └──────┬──────┘
                         ▼
                  ┌─────────────┐
                  │    上机      │ ← 工位平板扫码 + SCADA 关联
                  └──────┬──────┘
                         ▼
                  ┌─────────────┐
            ┌────►│   加工中     │ ← SCADA 自动累计件数/时长
            │     └──────┬──────┘
            │            ▼
            │     ┌─────────────┐
            │     │   下机       │ ← 换刀触发(扫码或自动检测)
            │     └──────┬──────┘
            │            ▼
            │     ┌─────────────┐
            │     │   待检       │ ← 检验员判定
            │     └──────┬──────┘
            │            ▼
            │     ┌─────┴─────┬─────────────┐
            │     ▼           ▼              ▼
            │  ┌──────┐  ┌────────┐    ┌──────────┐
            └──│ 重磨 │  │ 重新待用│    │   报废    │
               └──────┘  └────────┘    └──────────┘
                                              │
                                              ▼
                                       (含报废原因分类)
```

### 1.4 状态转换数据采集规范

每次状态转换都必须记录,字段如下:

| 字段 | 类型 | 必填 | 来源 |
|------|------|-----|------|
| tool_id | string | ✅ | 扫码 |
| event_type | enum | ✅ | 状态码 |
| event_time | timestamp | ✅ | 系统时钟(NTP 同步) |
| operator_id | string | ✅ | 工卡/账号 |
| machine_id | string | 视情况 | 上机/下机时必填 |
| workpiece_id | string | 视情况 | 上机时必填 |
| cumulative_parts | int | 视情况 | 下机时必填,SCADA 自动 |
| cumulative_cut_time_min | float | 视情况 | 下机时必填,SCADA 自动 |
| dispose_reason | enum | 视情况 | 报废时必填 |
| remark | text | 否 | 自由文本 |

**报废原因分类(必须强制选择)**:
- A. 正常磨损到寿
- B. 崩刃(异常)
- C. 精度超差(检测后判废)
- D. 工件干涉撞断
- E. 其他(必须填备注)

**为什么强制分类**:模型训练时 A 类是正样本,B-D 类是异常样本,合在一起会污染数据。

### 1.5 异常告警规则

数据采集阶段就要设异常检测,否则脏数据会污染模型:

| 规则 | 阈值 | 处置 |
|-----|-----|-----|
| 已领用但 N 小时未上机 | 4 小时 | 推送班长 |
| 上机但无下机记录 | 24 小时 | 推送工艺主管 |
| 累计件数远超基线寿命 | 1.5 倍 | 强制人工审查再使用 |
| 同一刀具同时被多机使用 | 任意 | 系统拒绝 + 告警 |
| 报废理由 E 占比 | >10%/月 | 数据治理介入 |

### 1.6 试点 → 推广 SOP

**Week 1-2:试点 1 条产线(10 台机)**

任务清单:
1. 选试点线(建议主力线之一,数据多但风险可控)
2. 试点线刀具盘点 → 全部打标 DMC
3. 仓库系统接入(出入库扫码)
4. 工位安装平板 + 扫码枪(每台机 1 套,约 3000 元/套)
5. 操作工培训(40 分钟,含演练)
6. 数据校验:连续 5 天数据完整率 ≥95%

**Week 3-4:数据治理审查**

- 抽查 100 条全生命周期记录,人工核对真实性
- 修订规则 / 流程
- 形成正式 SOP 文档

**Week 5-8:推广全厂**

- 每周 50 台速度推进,4 周覆盖全 200 台
- 每周一次进度会
- 推广末期数据完整率必须 ≥98% 才算推广成功

### 1.7 试点期间常见坑(提前避免)

| 坑 | 表现 | 解决 |
|---|------|------|
| 操作工不扫码 | 数据缺失 | 把扫码作为 MES 报工的前置条件,不扫不能报工 |
| 二维码污损看不清 | 扫码失败 | 打标位置选刀柄上侧(不接触切削液),DMC 比 QR 抗污 |
| 多人换刀谁扫码不清 | 多次重复扫码 | 默认"上机操作工"=负责人,系统去重 |
| 老刀具补打标累 | 进度慢 | 老刀正常用完报废即止,只对新入库的强制打标 |
| 班组长抵触流程 | 数据造假 | 第一个月给奖励(全班数据完整率 ≥98% 给班组奖) |

## 2. 工艺参数库建设

### 2.1 数据模型(核心 6 张表)

```sql
-- 表 1:工件主表
CREATE TABLE workpiece (
    wp_id              VARCHAR(20) PRIMARY KEY,
    wp_name            VARCHAR(100),
    customer           VARCHAR(50),
    material           VARCHAR(50),       -- HT250/QT600/AlSi9Cu/45# 等
    geometry_features  JSONB,              -- 体积/最大尺寸/特征数等
    tolerance_grade    VARCHAR(10),        -- IT6/IT7 等
    surface_finish_ra  FLOAT,
    created_at         TIMESTAMP
);

-- 表 2:加工工序
CREATE TABLE operation (
    op_id              VARCHAR(20) PRIMARY KEY,
    wp_id              VARCHAR(20) REFERENCES workpiece,
    op_seq             INT,                -- 工序号
    op_type            VARCHAR(20),        -- 粗铣/精铣/钻/铰/镗/攻
    machine_type       VARCHAR(50),        -- 三轴卧加/五轴/卧式车 等
    fixture_id         VARCHAR(20),
    target_feature     VARCHAR(100)        -- 加工部位描述
);

-- 表 3:参数版本(核心)
CREATE TABLE parameter_version (
    pv_id              VARCHAR(30) PRIMARY KEY,
    op_id              VARCHAR(20) REFERENCES operation,
    version_no         INT,
    spindle_rpm        INT,
    feed_rate_mmpm     FLOAT,
    depth_of_cut_mm    FLOAT,
    width_of_cut_mm    FLOAT,
    coolant_type       VARCHAR(20),
    tool_class         VARCHAR(50),        -- 刀具类型(不绑定具体 tool_id)
    cycle_time_sec     FLOAT,
    is_recommended     BOOLEAN,
    confidence         FLOAT,              -- 推荐置信度 0-1
    created_by         VARCHAR(50),
    created_at         TIMESTAMP,
    notes              TEXT
);

-- 表 4:试切/生产实绩
CREATE TABLE production_actual (
    pa_id              VARCHAR(30) PRIMARY KEY,
    pv_id              VARCHAR(30) REFERENCES parameter_version,
    machine_id         VARCHAR(20),
    tool_id            VARCHAR(20),
    actual_cycle_time  FLOAT,
    quality_result     VARCHAR(10),        -- PASS/FAIL/REWORK
    measured_dim       JSONB,              -- 实测尺寸
    surface_actual_ra  FLOAT,
    tool_wear_state    VARCHAR(20),        -- 正常/早期磨损/严重磨损
    operator_id        VARCHAR(20),
    actual_at          TIMESTAMP
);

-- 表 5:工件向量索引(用于相似度召回)
CREATE TABLE workpiece_embedding (
    wp_id              VARCHAR(20) PRIMARY KEY REFERENCES workpiece,
    feature_vector     VECTOR(128),        -- pgvector 扩展
    updated_at         TIMESTAMP
);

-- 表 6:推荐反馈
CREATE TABLE recommendation_feedback (
    rf_id              VARCHAR(30) PRIMARY KEY,
    wp_id_query        VARCHAR(20),
    pv_id_recommended  VARCHAR(30),
    engineer_action    VARCHAR(20),        -- ACCEPTED/MODIFIED/REJECTED
    final_pv_id        VARCHAR(30),        -- 最终采用的版本
    feedback_at        TIMESTAMP
);
```

### 2.2 推荐算法(从简到繁,分阶段)

**阶段 1(M3-M4):基于规则 + 相似度召回**
- 工件向量化:`[材料 one-hot, 体积 log, 最大尺寸 log, 公差等级数, 粗糙度 log, ...]` → 128 维向量
- 召回 Top-5 相似工件 → 取其历史 `is_recommended=TRUE` 的参数版本
- 输出:推荐参数 + 置信度(基于召回相似度)

**阶段 2(M5-M6):多目标优化**
- 优化目标:cycle_time ↓ + tool_wear ↓ + quality_result PASS率 ↑
- 在召回结果上做帕累托前沿,推荐多组方案

**阶段 3(M7+,可选):LLM Copilot 形态**
- 工艺工程师自然语言询问:"HT250 缸盖粗铣,刚换了把新刀,怎么调参数?"
- LLM 先 RAG 检索参数库,再用工艺常识填补,最后给方案 + 解释
- 这是模块七产品化的雏形

### 2.3 闭环机制(最容易被忽视但最关键)

每次推荐后必须形成闭环,否则参数库会僵化:

```
推荐 → 工艺工程师审核 → 修改/采纳/拒绝 → 试切 → 实绩回流 → 更新参数版本
```

具体规则:
- 工艺工程师每次必须在推荐界面点击 ACCEPTED/MODIFIED/REJECTED 之一
- MODIFIED 必须填修改原因(下拉框 + 自由文本)
- 试切结果(quality_result)必须 24h 内回流
- 系统每月自动 review:`is_recommended=TRUE` 的版本若 PASS 率 <90%,自动降级为 `is_recommended=FALSE` + 推送工艺主管

### 2.4 冷启动数据来源

新建库,数据从哪来?

| 来源 | 数量 | 质量 | 工作量 |
|-----|-----|-----|-------|
| 现有工艺卡片(纸质/Word) | 200-500 个工件 | 中(老化数据) | 高(需要 OCR/手工录入) |
| 工艺工程师"经验脑" | 任意 | 高 | 高(访谈+录入) |
| MES 历史工单 | 视积累 | 中(只有部分参数) | 中 |
| **建议组合** | 50 个高频工件优先 | | 2 人 × 1 月 |

**冷启动 SOP**:
- 选 TOP 50 工件(产值占比 80%+)
- 工艺工程师 + IT 软件小组 1 人配对录入
- 每个工件 0.5-1 天工作量,2 人 4 周完成
- 录入完成后才上推荐功能

## 3. 模型训练:刀具寿命预测

### 3.1 数据准备(假设刀具 ID 体系建好后 2 个月)

每把刀产生一条"完整生命样本":
- 输入特征:加工件数、累计加工时间、平均主轴功率、功率方差、振动 RMS、温升均值/峰值、工件类型分布
- 标签:剩余可加工件数(连续值)或"是否会在下 N 件内异常"(分类)

### 3.2 模型选型

| 模型 | 特点 | 何时用 |
|-----|-----|-------|
| LightGBM | 训练快,可解释,强基线 | 优先,M2-M3 上线 v0.5 |
| LSTM/TCN | 时序信号建模强 | M4-M6 对比,优胜则替换 |
| Transformer | 长序列,大数据 | 24 个月数据可考虑,但 ROI 不高 |

**强烈建议先 LightGBM 跑通**,80% 场景下它已够用,且工艺工程师能看懂特征重要度。

### 3.3 模型评估指标

不要只看 RMSE/MAE,业务上更关心:
- **早期误判率**(预测寿命 << 实际):浪费刀具,应 <10%
- **后期漏判率**(预测寿命 >> 实际,等到崩刃):风险事故,应 <2%
- **平均预警提前量**:能否在崩刃前 N 件提前告警,目标 ≥10 件

### 3.4 部署形态

```
SCADA → 边缘工控机(每条产线 1 台)
         │
         ├─ ONNX Runtime 推理
         ├─ 每加工 1 件触发一次预测
         └─ 推理结果 → MES 弹窗 / LED 看板
              │
              └─ 中央 GPU 服务器(每周重训)
```

边缘工控机推荐配置:Intel i5 + 16G 内存 + 256G SSD(无 GPU,LightGBM CPU 推理足够,约 5000 元/台)。
