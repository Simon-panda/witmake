# 仓库盘点视觉AI — 技术POC方案

> 创建日期：2026-06-01 | 基于 Grounding DINO（Apache 2.0，商业可用）

---

## 一、背景与目标

### 场景定义

| 场景 | 说明 | 频次 |
|:-----|:-----|:-----|
| **库位盘点** | 员工走到指定货架，拍照确认物料箱/托盘位置与ERP一致 | 日/周 |
| **固定区位巡查** | 指定区域（如A5区）拍照→AI比对标准布局→标记异常 | 日 |
| **物料摆放合规** | 物料箱是否在指定区域、标签朝外、堆叠不超高 | 抽查 |
| **数量清点** | 货架上某种物料箱的数量核对 | 月末盘点 |

### 技术路线选择

| 候选 | 模型 | 授权 | 速度 | 精度 | 判选 |
|:-----|:-----|:---:|:---:|:---:|:---:|
| LocateAnything-3B | NVIDIA | ❌ 非商用 | 12框/秒 | 高 | 否决 |
| Grounding DINO | IDEA Research | ✅ Apache 2.0 | 10-20 FPS | 中高 | **选用** |
| YOLOv11+自训练 | Ultralytics | ⚠️ AGPL | 30+ FPS | 需标注 | 备选 |
| OWLv2 | Google | ✅ Apache 2.0 | 3-5 FPS | 中 | 太慢 |

## 二、模型选型：Grounding DINO

### 两个可选版本

| 参数 | Tiny | Base |
|:-----|:-----|:-----|
| 参数量 | ~172M | ~733M |
| 模型大小 | ~1.5 GB | ~4.9 GB |
| 推理速度(RTX 3090) | ~20 FPS | ~10 FPS |
| 推理速度(RTX 4090) | ~30 FPS | ~18 FPS |
| 推理速度(Jetson Orin) | ~8 FPS (FP16) | ~3 FPS (FP16) |
| 显存需求 | ~3 GB | ~8 GB |
| 零样本检测 | ✅ | ✅ |
| 中文提示词 | ⚠️ 需验证 | ⚠️ 需验证 |
| HuggingFace ID | `IDEA-Research/grounding-dino-tiny` | `IDEA-Research/grounding-dino-base` |

**POC 建议：Tiny 起步，Base 兜底。**

Tiny 足够覆盖你们的场景——仓库盘点不是实时视频流，是拍照后处理。20 FPS 对单张照片来说意味着 < 100ms 推理延迟，完全够用。

### 中文提示词处理

Grounding DINO 基于 BERT 文本编码器（英文为主），中文提示词需要处理：

```
方案1：提示词英文化（推荐，零成本）
  "蓝色周转箱" → "blue crate"
  "MX11缸盖托盘" → "MX11 cylinder head pallet"
  
方案2：中英双语提示词（实测可行度待验证）
  "蓝色周转箱 . blue crate . 物料箱" → 文本编码器取 CLIP embedding，多语言混合可能有效
  
方案3：中文CLIP替换文本编码器（改动大，POC不做）
  将BERT替换为Chinese-CLIP → 需改模型结构，工程量大
```

**POC 先上方案1**（英文映射表），后续验证方案2效果。

## 三、系统架构

### 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    手机端（拍照+显示）                      │
│  员工App → 选择盘点区域 → 拍照 → 上传 → 接收结果 → 显示    │
└─────────────────────┬───────────────────────────────────┘
                      │ WiFi / 4G
┌─────────────────────▼───────────────────────────────────┐
│                  推理服务器（本地机房）                     │
│                                                         │
│  ┌──────────────┐   ┌──────────────┐   ┌─────────────┐ │
│  │ 图像预处理     │   │ Grounding    │   │ 比对引擎     │ │
│  │ 缩放/归一化    │──▶│ DINO 推理    │──▶│ ERP对比      │ │
│  │ 960×960      │   │ GPU推理      │   │ 差异标注     │ │
│  └──────────────┘   └──────────────┘   └─────────────┘ │
│                                                         │
│  GPU: 1× RTX 4090 24GB（或 1× RTX 3090 24GB）          │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│                   返回结果到手机                           │
│  标注图片: 绿色框=匹配 ✅ | 红色框=异常 🔴 | 黄色=待确认 ⚠️ │
└─────────────────────────────────────────────────────────┘
```

### 硬件方案

| 方案 | 配置 | 成本 | 适用 |
|:---:|:-----|:----:|:-----|
| **A（推荐）** | 1× RTX 4090 24GB + 普通PC | ~2.5万 | POC + 小规模生产 |
| B | Jetson Orin AGX 64GB | ~1.5万 | 边缘端，便携但慢 |
| C | 云GPU（AutoDL等） | ~3元/小时 | POC测试，不推荐长期 |

**推荐方案A**：一台PC+4090放机房，手机通过内网WiFi调API。支持 5-10 人并发拍照盘点无压力。

## 四、POC 实施计划

### Phase 1：技术验证（1-2周）

**目标**：验证 Grounding DINO 对你们仓库场景的检测能力。

| 步骤 | 内容 | 产出 |
|:---:|:-----|:-----|
| 1.1 | 搭建推理环境：RTX 4090 + transformers + torch | 可运行demo |
| 1.2 | 拍摄仓库样本照片（50张，覆盖不同货架/光照） | 测试数据集 |
| 1.3 | 定义检测目标词汇表（物料箱、托盘、标签、区域标记等） | 英文映射表 |
| 1.4 | 跑零样本检测，统计准确率 | 准确率矩阵 |
| 1.5 | 验证中文提示词可行性 | 中英文对比结果 |

**通过标准**：
- 物料箱检出率 > 90%
- 误检率 < 15%
- 单图推理 < 500ms

### Phase 2：比对引擎开发（2-3周）

**目标**：实现"拍照→检测→比对ERP→标注差异"的完整链路。

| 步骤 | 内容 | 产出 |
|:---:|:-----|:-----|
| 2.1 | 设计库位-物料映射数据库（SQLite，与ERP同步） | 数据表结构 |
| 2.2 | 实现检测结果→库位比对逻辑 | Python比对模块 |
| 2.3 | 图片标注渲染（画框+标签+状态色） | 可视化模块 |
| 2.4 | REST API接口（接收图片→返回标注结果） | FastAPI服务 |
| 2.5 | 简单Web前端（浏览器拍照→上传→看结果） | POC前端 |

### Phase 3：现场试用（2-4周）

**目标**：员工实际使用，收集反馈。

| 步骤 | 内容 | 产出 |
|:---:|:-----|:-----|
| 3.1 | 培训2-3名仓库员使用流程 | 操作手册 |
| 3.2 | 为期2周的实际盘点试用 | 使用日志+准确率统计 |
| 3.3 | 收集漏检/误检案例→优化提示词/补充规则 | 优化迭代 |
| 3.4 | 评估员工效率提升（盘点耗时对比） | ROI报告 |

## 六、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|:-----|:---:|:---:|:-----|
| **中文提示词不支持** | 中 | 中 | POC Phase1验证；不行就用英文映射（一次翻译，永久使用） |
| **复杂堆叠场景检测差** | 高 | 中 | 先做标准库位（整齐摆放），堆叠场景后续迭代 |
| **暗光环境误检多** | 中 | 中 | 要求开灯拍照；或加闪光灯/补光 |
| **相似物料难区分** | 中 | 高 | 结合二维码/物料卡OCR做二次确认 |
| **GPU同时处理多请求慢** | 低 | 低 | Tiny模型20FPS，5人并发每人<1秒，够用 |
| **模型误检导致盘点错误** | 中 | 🔴 | 所有异常标记为"待确认"，由人工最终裁决 |

## 七、与 LocateAnything 的衔接

当 NVIDIA 开放 LocateAnything 商业 API（Nemotron Nano Omni）后：

```
切换路径：
  Grounding DINO (当前) 
    → 共用同一个API接口（FastAPI）
    → 替换推理后端（换模型，不改接口）
    → LocateAnything (未来)
```

两套推理后端共存，随时切换，上层应用无感知。
