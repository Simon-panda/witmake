## 1. 项目概述

### 1.1 需求背景

公司当前客户沟通分散在多个渠道：微信个人号、企业微信、电话、邮件、网站表单。存在以下痛点：

| 痛点 | 现状 | 量化影响 |
|------|------|:---:|
| 渠道碎片化 | OEM客户、自动化集成客户通过不同渠道联系，无统一记录 | 客户重复描述问题，体验差 |
| 无服务质量追踪 | 谁回复了、多久回复、是否解决——全靠 Excel 或人脑记 | IATF 16949 审核无完整客诉闭环记录 |
| 知识未沉淀 | 相同问题（交期、规格、保修）被问 20 次，每次重新回答 | 人力浪费 |
| 售后响应慢 | 自动化产线故障报修靠打电话，找不到人时产线停着等 | MTTR 不可控 |
| 数据出境风险 | 如果用 SaaS 客服工具（Intercom/Zendesk），客户图纸/报价存在美国服务器 | 合规风险 |

### 1.2 核心目标

| 目标 | 指标 | 当前基线 | 目标值 | 达成时间 |
|------|------|:---:|:---:|:---:|
| 统一客户入口 | 渠道收敛率 | 5个孤立渠道 | 1个统一工作台 | 上线日 |
| AI 拦截常见问题 | AI 自动应答率 | 0% | ≥40% | 上线后 3 个月 |
| 缩短首次响应 | 平均首次响应时间 | ~2小时（电话未接通计为等待） | ≤5分钟（工作时间） | 上线后 1 个月 |
| 客诉闭环可追溯 | 客诉记录完整率 | <30%（仅大事件记录） | 100%（所有渠道自动记录） | 上线日 |
| 零现金支出 | 许可证费用 | — | ¥0/年 | 全周期 |

### 1.3 使用人群

| 角色 | 来源 | 典型场景 | 预计日咨询量 |
|:---|:---|------|:---:|
| **主业 OEM 客户** | 采购/质量工程师 | 订单交期查询、质量投诉、新项目询价 | 10-30条 |
| **副业自动化客户** | 工厂设备经理/厂长 | 产线故障报修、进度咨询、备件采购 | 5-15条 |
| **内部协作** | 跨部门沟通 | 生产异常通报、设备维修协同 | 5-10条 |

### 2.2 消息处理 SLA

| 消息类型 | 首次响应 | 解决时限 | 超时动作 |
|:---|:---:|:---:|------|
| 一般咨询 | ≤5分钟 | ≤4小时 | 自动提醒坐席 |
| 质量投诉 | ≤15分钟 | ≤24小时 | 升级至质量主管 |
| 产线故障报修 | ≤5分钟 | ≤2小时 | 自动电话通知二线 |
| 新项目询价 | ≤30分钟 | ≤2工作日 | 升级至销售负责人 |


## 3. 详细功能说明

### 3.1 多渠道接入

#### 3.1.1 网站在线聊天（一期 D1）

| 项目 | 规格 |
|------|------|
| 功能描述 | 在公司官网嵌入 Chatwoot 聊天窗口，访客无需登录即可发起咨询 |
| 触发方式 | 页面右下角悬浮按钮，点击展开聊天窗口 |
| 交互规则 | 输入消息→排队分配坐席→实时对话→满意度评价 |
| 前端技术 | Chatwoot 原生 Web Widget（Vue.js），一行 `<script>` 标签嵌入 |

#### 3.1.2 企业微信接入（一期 D7-14）⚠️ 需开发

| 项目 | 规格 |
|------|------|
| 功能描述 | 客户通过企业微信发送消息 → 适配器转发至 Chatwoot API → 坐席在 Chatwoot 回复 → 适配器回传企微 |
| 开发方式 | 自建 Chatwoot Channel Adapter（遵循 Chatwoot Channel API 规范） |
| 技术栈 | Python（FastAPI）+ Chatwoot REST API + 企业微信回调 API |
| 关键能力 | 消息收发、图片/文件传输、客户身份识别、会话保持 |
| 开发量 | 约 2-4 周 × 1 人（IT软件小组） |

适配器架构：

```
企业微信服务器 ←→ WeCom Adapter (Python FastAPI) ←→ Chatwoot REST API
                        │
                   PostgreSQL（会话映射表）
```

#### 3.1.3 微信个人号接入（一期 D14-21）⚠️ 需开发

| 项目 | 规格 |
|------|------|
| 功能描述 | 客户通过微信个人号发消息 → 同适配器架构接入 Chatwoot |
| 技术方案 | 微信个人号 → WeCom Adapter 扩展 → Chatwoot |
| 注意 | 微信个人号 API 有封号风险，建议优先推企业微信给客户 |

#### 3.1.4 邮件接入（一期 D1）

| 项目 | 规格 |
|------|------|
| 功能描述 | Chatwoot 原生支持 IMAP/SMTP 邮件渠道 |
| 配置 | 在 Chatwoot 后台添加邮箱渠道 → 填入 IMAP/SMTP 信息即可 |

#### 3.1.5 电话（二期）

| 项目 | 规格 |
|------|------|
| 说明 | Chatwoot 不自带呼叫中心，可通过 Twilio/阿里云语音 API 扩展。一期不纳入 |

### 3.2 Captain AI 自动应答

#### 3.2.1 AI 模型策略（一期不走 Chatwoot 积分体系）

采用 **自建 LLM 后端** 替代 Captain 积分体系——你有 AI 应用小组，直接用自己模型：

| 项目 | 规格 |
|------|------|
| 模型 | DeepSeek-V3 / 通义千问（国内 API，低延迟） |
| 接入方式 | Chatwoot 开放 AI Agent API → 转发到自建 LLM 服务 |
| 知识库 | 从 Chatwoot Help Center 读取 → 向量化存入本地 RAG |
| 成本 | API 按量付费，预估 ¥200-500/月（10人团队日咨询量 50-80 条） |

典型 AI 应答场景：

| 场景 | 客户问 | AI 自动答 | 是否需要人工 |
|------|------|------|:---:|
| 订单交期 | "我们的缸体什么时候发货？" | 调 MES API → "您的订单 PO-20260601，缸体 200 件，预计 6/15 发货" | ❌ |
| 产品规格 | "你们的转向节用什么材料？" | 知识库检索 → "42CrMo 锻钢，抗拉强度 ≥1080MPa" | ❌ |
| 保修政策 | "设备保修多久？" | 知识库 → "标准保修 12 个月，可购买延保至 36 个月" | ❌ |
| 复杂投诉 | "这批缸盖有气孔，导致我们产线停线了" | 识别为质量投诉 → 直接转人工 + 标记紧急 | ✅ 人工 |
| 产线报修 | "灌装线机器人不抓料了" | 识别故障关键词 → 转二线技术 + 推送故障排查手册 | ✅ 人工 |

### 3.3 人工坐席工作台

### 4.3 集成清单

| 集成项 | 方式 | 优先级 | 负责 |
|------|------|:---:|------|

### 4.4 数据安全

| 措施 | 说明 |
|------|------|
| 数据不出境 | 全部部署在国内服务器（阿里云/机房），Chatwoot Cloud 版不使用 |
| 访问控制 | Nginx HTTPS + IP 白名单（仅办公网络可访问后台） |
| 审计日志 | Chatwoot 原生记录所有操作，满足 IATF 16949 追溯要求 |
| 备份策略 | PostgreSQL 每日自动备份至 OSS/本地 NAS，保留 90 天 |
| 敏感信息脱敏 | 客户图纸/报价不在聊天中直接传输，转内部 OA |

## 5. 异常场景处理

| 异常场景 | 处理逻辑 |
|------|------|
| 服务器宕机 | Docker Compose `restart: always` 自动拉起；Nginx 显示"客服暂时离线，请拨打电话 XXX" |
| AI 模型不可用 | 自动降级——所有消息直接转人工坐席，不经过 AI |
| 企微适配器断连 | 企微消息暂存企微服务器 → 适配器恢复后补推；超过 5 分钟自动短信通知运维 |
| 高峰并发（大促/集中报修） | Redis 队列缓冲，超过 50 人排队自动通知管理员加人 |
| 非工作时间客户咨询 | AI 自动回复："现在是下班时间，紧急事项请拨 XXX，我们将在上班后第一时间回复" |
| 同一客户多渠道同时咨询 | Chatwoot 以 Contact 维度合并，不会重复分配 |
| 客户发图纸/大文件 | 限制单文件 ≤50MB，引导客户发邮件/网盘 |

## 8. 约束与备注

| # | 约束项 | 说明 |
|:---:|------|------|
| 1 | **微信个人号合规** | 微信个人号 API 非官方开放，有封号风险。上线后优先引导客户迁移至企业微信 |
| 2 | **企微自建应用审核** | 企业微信自建应用需提交审核，预计 1-3 个工作日 |
| 3 | **服务器成本** | 若用阿里云 ECS（4核8G）≈ ¥400/月；若用公司机房现有服务器 = ¥0 |
| 4 | **域名 + SSL** | 需一个子域名（如 support.你的域名.com）+ Let's Encrypt 免费 SSL |
| 5 | **Chatwoot 版本升级** | Docker 部署，升级 = `docker-compose pull && docker-compose up -d`，约 5 分钟停机 |
| 6 | **与现有 Hermes 生态的关系** | Chatwoot 独立部署，不依赖 Hermes。未来可通过 Webhook 将 Chatwoot 事件推送到 Hermes 做智能分析 |
| 7 | **数据迁移** | 一期从零开始，不涉及旧数据迁移 |
| 8 | **英文客户** | Chatwoot 原生支持多语言，Captain AI + DeepSeek 可处理中英文混合场景 |
