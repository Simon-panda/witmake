# 🦞 Hermes精装攻略七步法（可执行版）

> **将聊天AI转化为具备记忆、感知与进化能力的数字分身**
>
> 每步均附：🔍 原理 → ⚙️ 可执行动作 → ✅ 验收标准

---

## ① 定身份 — 用 SOUL.md 定义AI角色

### 🔍 原理
AI没有默认人格，需要通过 SOUL.md 给予明确的角色定位、工作方式和行为边界。没有身份定义的AI就像没有岗位说明书的员工。

### ⚙️ 可执行动作

| # | 行动 | 具体操作 | 产出 |
|---|------|----------|------|
| 1.1 | 创建 SOUL.md | 定义角色名称、服务对象、核心职责、禁止事项 | `SOUL.md` 文件 |
| 1.2 | 创建 IDENTITY.md | 定义AI名称、风格语气、表情偏好 | `IDENTITY.md` 文件 |
| 1.3 | 创建 USER.md | 记录用户画像：姓名、角色、沟通偏好、关注指标 | `USER.md` 文件 |
| 1.4 | 创建 AGENTS.md | 设定行为准则：如何确认意图、如何输出、禁区清单 | `AGENTS.md` 文件 |
| 1.5 | 安装角色模板 | 从 `agency-zh` 中文角色库拉取预置模板（工程/设计/营销等） | 角色模板文件 |
| 1.6 | 校准角色一致性 | 让AI用角色身份自我介绍，检查语气风格是否匹配 | 角色验收对话 |

### ✅ 验收标准
- [ ] 6个核心文件（SOUL.md/IDENTITY.md/USER.md/AGENTS.md/MEMORY.md/TOOLS.md）齐全
- [ ] AI能用角色身份准确自我介绍，不会说"作为AI助手..."
- [ ] 回答问题时使用角色对应的语气和专业术语
- [ ] 用户角色画像至少覆盖姓名、角色、沟通偏好3项

## ② 换记忆 — 长效记忆系统

### 🔍 原理
默认AI每次对话都是"重启"，没有上下文连续性。Hindsight系统自动构建知识图谱，实现跨会话的记忆持久化。

### ⚙️ 可执行动作

| #   | 行动           | 具体操作                            | 产出             |
| --- | ------------ | ------------------------------- | -------------- |
| 2.1 | 备份当前记忆       | 导出当前 `MEMORY.md` 和 `memory/` 目录 | 记忆备份文件         |
| 2.2 | 安装 Hindsight | 部署 Hindsight 记忆服务，配置知识图谱引擎      | Hindsight 运行实例 |
| 2.3 | 配置记忆触发规则     | 设定"什么内容该记住"的触发条件（关键词、频率、重要性评分）  | 记忆规则配置         |
| 2.4 | 导入历史记忆       | 将已有 MEMORY.md 内容结构化导入 Hindsight | 初始知识图谱         |
| 2.5 | 测试记忆召回       | 分轮次对话后，验证AI能引用前文关键信息            | 记忆召回测试报告       |
| 2.6 | 配置记忆衰减       | 设置旧记忆的衰减机制，避免知识图谱膨胀             | 衰减策略配置         |

### ✅ 验收标准
- [ ] Hindsight 服务正常运行
- [ ] 跨5轮以上对话后，AI能准确回忆第1轮的关键信息
- [ ] 新会话能正确引用历史会话中的决策和约定
- [ ] 知识图谱可视化工具可用

## ③ 装网眼 — 让AI读懂全网

### 🔍 原理
AI的信息边界取决于它能"读到"什么。部署多层信息抓取工具，让AI能无障碍获取任何公开网页内容。

### ⚙️ 可执行动作

| # | 行动 | 具体操作 | 产出 |
|---|------|----------|------|
| 3.1 | 部署 Jina Reader | 安装并配置 Jina Reader API，支持单页URL内容提取 | Jina API接入 |
| 3.2 | 部署 Crawl4AI | 安装 Crawl4AI，支持整站爬取与递归爬取 | Crawl4AI 实例 |
| 3.3 | 配置反爬策略 | 部署 Scraping 工具，配置Cookie/Header模拟、代理轮换 | 反爬策略配置 |
| 3.4 | 测试单页抓取 | 输入一个URL，验证Jina能准确提取文章正文和元数据 | 单页抓取测试结果 |
| 3.5 | 测试深度爬取 | 指定起始URL，验证Crawl4AI能递归爬取3层页面 | 深度爬取测试结果 |
| 3.6 | 配置缓存策略 | 设置页面缓存TTL，避免重复请求，节省API消耗 | 缓存策略配置 |

### ✅ 验收标准
- [ ] Jina Reader 可正常返回任意公开URL的结构化内容
- [ ] Crawl4AI 能完成指定网站的3层深度爬取
- [ ] 带反爬的站点（如需要登录或验证码）能正常获取
- [ ] 抓取速度平均<5秒/页

## ④ 研工具 — 专业工具链

### 🔍 原理
仅靠基础搜索和原始文本无法满足专业需求。配置分层搜索+文档转换工具链，拓展AI的信息处理和转换能力。

### ⚙️ 可执行动作

| # | 行动 | 具体操作 | 产出 |
|---|------|----------|------|
| 4.1 | 注册并配置 Tavily | 获取 API Key，配置搜索参数（结果数、时域过滤、内容类型） | Tavily API接入 |
| 4.2 | 安装 DuckDuckGo | 配置免费搜索引擎作为 Tavily 的备选/补充 | DuckDuckGo接入 |
| 4.3 | 安装 Pandoc | 安装Pandoc并配置常见转换模板（MD→PDF, HTML→MD, DOCX→MD） | Pandoc可用 |
| 4.4 | 安装 Marker | 安装Marker工具，配置PDF解析参数（OCR选项、表格提取） | Marker可用 |
| 4.5 | 定义搜索优先级策略 | 设定：专业检索→Tavily, 快查→DuckDuckGo, 深度→Google API | 搜索策略文档 |
| 4.6 | 测试文档转换管线 | 测试MD→PDF、PDF→MD、HTML→DOCX三条管线 | 转换测试通过 |

### ✅ 验收标准
- [ ] Tavily搜索返回结果质量符合专业查询需求
- [ ] Pandoc 能完成5种以上格式互转
- [ ] Marker 能解析带表格和图片的PDF文档
- [ ] 文档转换管线平均耗时<10秒

## ⑤ 多模态 — 多媒体能力

### 🔍 原理
纯文本交互限制了AI的应用场景。增加语音和图像能力，让AI能"听说读写画"全通道交互。

### ⚙️ 可执行动作

| # | 行动 | 具体操作 | 产出 |
|---|------|----------|------|
| 5.1 | 部署 Whisper | 安装Whisper（本地或API），配置语音识别模型大小（base/small/medium/large） | Whisper可用 |
| 5.2 | 配置语音 → 文本管线 | 音频文件 → 转录文本 → AI处理 → 输出响应 | 语音输入管线 |
| 5.3 | 部署 Edge TTS | 配置Edge TTS，选择语音风格和语言 | Edge TTS可用 |
| 5.4 | 配置文本 → 语音管线 | AI输出 → 文本处理 → TTS合成 → 语音输出 | 语音输出管线 |
| 5.5 | 注册 fal.ai | 获取API Key，配置Flux图像生成参数（分辨率、风格、步数） | fal.ai接入 |
| 5.6 | 测试多模态全链 | 语音输入→转录→AI处理→文字回复+TTS朗读；文字描述→图像生成 | 多模态测试通过 |

### ✅ 验收标准
- [ ] Whisper能准确转录中文/英文语音（准确率>90%）
- [ ] Edge TTS输出的语音自然可听（有语调和停顿）
- [ ] Flux能根据文字描述生成合理的图像
- [ ] 全链路延迟：语音输入<3s，图像生成<15s

## ⑥ 控成本 — 精打细算

### 🔍 原理
AI的Token消耗是持续运营成本。只有可视化和压减，才能确保长期可负担。

### ⚙️ 可执行动作

| # | 行动 | 具体操作 | 产出 |
|---|------|----------|------|
| 6.1 | 部署 Tokscale | 安装Tokscale，配置API key，可视化各服务/任务的Token消耗 | Tokscale仪表盘 |
| 6.2 | 建立消耗基线 | 运行一周，产出日均Token消耗和月预估 | 消耗基线报告 |
| 6.3 | 配置 RTK 压缩 | 针对长上下文场景，启用RTK压缩策略，减少冗余输出 | RTK配置生效 |
| 6.4 | 审计 Skill 生态 | 盘点已有Skill清单，标记可复用的，删除废弃的 | Skill审计清单 |
| 6.5 | 建立重写规则 | 对高消耗任务设定：摘要压缩、缓存复用、模型降级策略 | 成本优化规则 |
| 6.6 | 设定预算告警 | 设置月Token预算上限，超阈值自动告警 | 预算告警配置 |

### ✅ 验收标准
- [ ] Tokscale仪表盘正常运行，可按时间段/服务筛选
- [ ] 日均Token消耗数据可查，月度预估误差<20%
- [ ] RTK压缩后输出量减少≥30%（同等信息密度）
- [ ] Skill去重/合并后数量减少≥20%
- [ ] 月Token消耗控制在预算±10%以内

## ⑦ 理生态 — 统一管理工具链

### 🔍 原理
分散的工具无法形成合力。通过统一生态管理，确保各模块协同工作，避免"各自为政"。

### ⚙️ 可执行动作

| #   | 行动                      | 具体操作                                        | 产出      |
| --- | ----------------------- | ------------------------------------------- | ------- |
| 7.1 | 拉取 awesome-hermes-agent | 克隆仓库，按类别梳理可用工具和插件                           | 工具清单    |
| 7.2 | 部署 hermes-ecosystem     | 安装生态系统管理器，注册所有已配置工具                         | 生态管理器   |
| 7.3 | 建立模块依赖图                 | 绘制七步各模块的依赖关系：①角色→②记忆→③感知→④工具→⑤多模态→⑥成本→⑦生态   | 依赖关系图   |
| 7.4 | 配置联动规则                  | 设定模块间数据流转规则（如：Crawl4AI抓取内容→自动进入Hindsight记忆） | 联动配置    |
| 7.5 | 运行全链路测试                 | 模拟完整任务：角色说话→记忆检索→搜索抓取→工具处理→语音输出             | 全链路测试报告 |
| 7.6 | 建立持续优化机制                | 设置月度工具链审计，持续淘汰低效工具、引入新能力                    | 优化SOP文档 |

### ✅ 验收标准
- [ ] 所有已配置工具在生态管理器中有统一入口
- [ ] 七步模块之间的数据流转自动化（无需手动干预）
- [ ] 全链路任务：从语音输入到输出完整执行成功
- [ ] 月度审计有明确记录和改进项

## 🗺️ 实施路线图（建议顺序）

```
第1周：①定身份 + ②换记忆（打好基础）      → 基座搭建
第2周：③装网眼 + ④研工具（扩展能力）      → 能力拓展
第3周：⑤多模态（增强交互）                 → 交互升级
第4周：⑥控成本 + ⑦理生态（优化闭环）      → 持续优化
```

## 💎 精装核心

> **七步法的本质是将 "聊天AI" → "数字分身"**
>
> 聊天AI：一轮对话，用完即忘
> 数字分身：有身份、有记忆、有感知、能进化

**可执行化的关键**：每步不再只是"知道该做什么"，而是"知道怎么做到、做到什么程度算合格"。
