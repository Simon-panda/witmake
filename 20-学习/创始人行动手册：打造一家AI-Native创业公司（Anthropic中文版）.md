## 核心概述

AI 正在重塑创业公司的搭建方式。今天，从未写过一行代码的创始人正在把生产级应用交付给用户，"10 人独角兽"也从草根逆袭故事变成了一份可以认真执行的行动方案。

到 2026 年，AI 可以写生产环境代码、做市场调研、梳理竞争格局、起草投资人材料，并把运营流程自动化跑起来。AI 最大的贡献，是把"谁能开一家创业公司、谁做出一款产品"这件事拉到了同一条起跑线上。

这本手册按照这些新现实，重新画出创业旅程的四个核心阶段：**想法**、**MVP**、**发布**、**规模化**。

---

## 第一章：创业生命周期，为 2026 重新启动

传统的创业增长曲线，默认路径是：验证 → 融资 → 招人 → 搭建 → 再融资 → 增长 → 继续招人 → 循环往复。

现在，AI 已经打破了一个默认预期：创业生命周期里每进入一个新阶段，就必须配上更大的团队、不同的技能组合和新一轮融资。

## 第二章："创始人"这件事正在改变

过去，创始人是被"能做什么"定义的：技术型创始人写代码，非技术型创始人跑业务、谈合同。但 2026 年创始人手上的模型、系统和 AI agent，已经把"能造东西的人"和"有想法值得造的人"之间那堵墙拆掉了。

**AI-Native 创业公司里，创始人不再只是个人贡献者，而更像是一群 agent 的编排者（orchestrator）。**

### AI 为精益创业带来的三种能力

| 能力 | 类比 | 说明 |
|------|------|------|
| **对话式智能与研究** | 随时随到的专家 | 竞品分析、市场规模测算、财务建模、文档起草 |
| **Agentic 编程** | 永远在线、永不卡住的工程师 | 用大白话描述产品，AI 生成、测试、调试、重构生产级代码 |
| **工作流自动化** | 随叫随到的自动化运营团队 | CRM 自动更新、周报自动汇总、文档随产品改动同步 |

## 第三章：想法阶段（Idea）

每一位创始人都从同一个地方出发：一个让你停不下来去想的问题。

**核心纪律：证据不充分之前，不动手造。**

### 目标

以研究为导向的验证——在投入资源开始造之前，攒起扎实证据，证明一个真实问题确实存在，并且你提出的方案确实能解决它。

**关键问题序列：**
1. 这个问题真实、具体、足够高频，值得围绕它做一家公司吗？
2. 到底谁有这个问题？这些人能构成一个市场吗？
3. 有没有人在解决？他们怎么做的，做得多好？
4. 一个真正解决这个问题的方案需要做到什么？我的想法做到了吗？

### 退出标准：问题-方案匹配（Problem-Solution Fit）

三个"是"才能离开想法阶段：
- 这个问题真实且具体吗？
- 你的方案对应的是真实问题吗？
- 你有足够信号去开干吗？

### 三大失败模式

| 失败模式 | 表现 | 解药 |
|----------|------|------|
| **把"造"误当作"验证"** | 42%的创业公司失败是因为做了没人想要的东西 | 先验证假设，再开始造。对话本身才是真正的证据 |
| **过早规模化** | 执行速度远超业务真正需要的水平 | 让判断力始终走在建造之前 |
| **客观性丧失** | 确认偏误配上AI研究引擎 | 用同一个工具做压力测试，而不是找支持证据 |

### Claude 如何帮助想法阶段的创始人

**Chat、Claude Cowork、Claude Code 的选择矩阵：**

| 你要做的是… | 为什么这样选 | 用什么 |
|-------------|-------------|--------|
| 一次快速头脑风暴 | 快、对话式、无需配置 | Chat |
| 研究、分析或产出成型文档 | 文件夹访问、连接器、Skills | Claude Cowork |
| 写、测或交付软件 | 代码库访问、diff、git | Claude Code |

**核心练习：**
- 和 Claude 一起反复打磨问题陈述，直到变成可测试的假设
- 让 Claude 反过来论证你的想法，去找反证
- 按层级绘制竞争格局：直接竞品、间接竞品、潜在收购方
- 构建 TAM/SAM/SOM 模型并压力测试背后的假设
- 设计客户发现访谈框架，分析访谈后数据
- 用 Claude Code 搭轻量原型用于客户和投资人对话

## 第四章：MVP 阶段

不少创始人把 MVP 阶段当成"开工建设"，但它本质上还是一次收集证据的过程——只是这次收集的是关于解决方案的证据，不再是问题本身。

### 目标

把已经验证过的问题，转化成一款真实用户愿意使用的可运行产品。同时：
- **跑得快，但不要背上会复利的技术债**
- **从第一天起建设持久上下文**（CLAUDE.md、架构文档、范围文档）

### 退出标准：产品-市场匹配（PMF）

- 一个具体用户群觉得产品有价值，愿意回头再用（留存）、付费（收入）、或推荐给别人
- Sean Ellis 测试：超过 40% 活跃用户"非常失望"如果没有这个产品
- 努力测试：产品开始"被拉"而不是"被推"

### 四大失败模式

| 失败模式 | 表现 | 解药 |
|----------|------|------|
| **Agentic 技术债** | 缺乏一致心智模型，架构漂移复利 | 架构约束写进 AI 能读到的地方（CLAUDE.md） |
| **误把假 PMF 当成真 PMF** | 发布期热度来自短暂因素 | 发布前建立度量框架，设定留存基准 |
| **零摩擦的范围蔓延** | 每个新功能看起来都合理 | 先写范围文档，明确做什么和不做什么 |
| **因经验不足而不安全** | Agentic 编程生成的不是天然安全的代码 | 任何用户上手前先做安全审查 |

### Claude 如何帮助 MVP 阶段创始人

1. **动手前先定架构** — 创建 CLAUDE.md 作为项目持久记忆
2. **定义并执行 MVP 范围** — 用 Claude 写范围文档并做压力测试
3. **用 Claude Code 做 MVP** — 遵守已制定的架构和范围约束
4. **安全审查** — 部署前用 Claude 扫描认证、API、输入校验等
5. **建立度量框架** — 在第一个用户出现前，定义留存、激活、假阳性指标
6. **管理反馈环** — Claude Cowork 处理触达、排期、bug 分诊

## 第五章：发布阶段（Launch）

如果说 MVP 阶段是要证明你的产品值得存在，那么发布阶段就是要证明你的生意值得长大。

### 目标

把早期势头转化成一台可重复、可持续的增长引擎。同时搭建运营系统，把创始人注意力从琐事中释放出来。

### 退出标准

1. **增长是可重复、由渠道驱动的** — CAC、LTV、回收周期心里有数
2. **产品扛得住生产工作负载** — 基础设施已加固
3. **运营在没有创始人瓶颈的情况下也能跑** — 自动化已部署

### 四大失败模式

1. **技术债到期** — MVP 的捷径开始算利息
2. **创始人成了瓶颈** — 从亲自做事到设计系统的转变失败
3. **安全与合规不能再往后拖** — 真实数据等于真实风险
4. **还没准备好就扩张** — 新市场可能成为 PMF 的死地

### Claude 如何帮助发布阶段创始人

- 用 Claude Code 跑架构审查，识别结构性弱点
- 用 Claude Cowork 审计当前运营负荷，设计自动化工作流
- 安全合规做成产品工作流（SOC 2、GDPR、HIPAA）
- 建立轻量可重复的产品管理流程

## 第六章：规模化阶段（Scale）

在规模化阶段，创始人的角色从建造者转向面向公众的高管。

### 目标

搭建由成熟组织运营支撑的系统化增长。用累积深度建出防御性护城河：
- 嵌入产品的领域专业知识
- 与用户生态系统的深度整合
- 专有系统数据和工作流

### 退出标准

- 不需要外部资本的规模化可持续盈利
- IPO 就绪或被收购
- 回答："如果一个资金充足的在位者今天复制了你的产品，你的用户会留下来吗？"

### Claude 产品矩阵部署策略

| Claude 产品 | 主要阶段 | 角色定位 |
|-------------|---------|----------|
| Claude apps (Chat) | 想法/发布 | 创始人顾问、客服入口 |
| Claude Code | MVP/规模化 | 工程主力、多 Agent 编排 |
| Claude Cowork | 发布/规模化 | 团队协作、知识库 |
| Claude Platform | 规模化 | 后端 API、自定义 Agent |

## 七条核心洞见

1. **创始人角色的转变**：从个人贡献者 → Agent 编排者 → 面向公众的高管
2. **AI-Native 的护城河不是代码**，而是专业知识 + 工作流锁定 + 数据复利
3. **不要过早自动化**——一个还没手工跑通的工作流，不应交给 Agent 自动执行
4. **确认偏误是隐形的杀手**——AI 会沿着你的方向走，不解药就是问反问题
5. **CLAUDE.md 是第一份产物**——架构约束写进 AI 能读到的地方，防止架构漂移
6. **超精益创业模型可行**——当 Claude Code 构建产品、Claude Cowork 构建公司运营，小团队也能像大公司一样运行
7. **最佳起点不是搭建宏伟的 AI 工作流**，而是选择一件重复耗时最多的任务，让 AI 出第一版
