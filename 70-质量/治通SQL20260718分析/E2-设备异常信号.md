# E2-设备异常信号检测

> 分析日期：2026-07-17
> 数据来源：zt_server_data（MySQL 8.0），zt_cyl_block_seal / zt_cyl_block_brk_core_1~3
> 方法：从检测记录反推设备健康状态，识别异常信号 → 产出需点检设备清单

## ① 记录空洞检测（停机/故障线索）

### 分析目的

检测各设备相邻检测记录间隔 >24h 的时段。长时间无检测记录通常意味着设备停机、故障或维修，可作为设备健康预警信号。

### SQL

```sql
-- 以 zt_cyl_block_seal 为例（10台设备，含"设备编号"列）
SELECT `设备编号`, `检测时间`,
  TIMESTAMPDIFF(HOUR, 
    LAG(`检测时间`) OVER (PARTITION BY `设备编号` ORDER BY `检测时间`),
    `检测时间`) as gap_h
FROM `zt_cyl_block_seal`;

-- 汇总各设备的空洞次数与总时长（外层过滤 gap_h > 24）
SELECT `设备编号`,
  COUNT(*) as gap_cnt,
  ROUND(SUM(gap_h)) as total_h,
  ROUND(MAX(gap_h)) as max_h
FROM (
  SELECT `设备编号`,
    TIMESTAMPDIFF(HOUR, 
      LAG(`检测时间`) OVER (PARTITION BY `设备编号` ORDER BY `检测时间`),
      `检测时间`) as gap_h
  FROM `zt_cyl_block_seal`
) t WHERE gap_h > 24
GROUP BY `设备编号` ORDER BY total_h DESC;

-- 断芯三表（每表一台设备，无"设备编号"列）
SELECT TIMESTAMPDIFF(HOUR, LAG(`时间`) OVER (ORDER BY `时间`), `时间`) as gap_h
FROM `zt_cyl_block_brk_core_1`;
```

## ② 合格率突变检测

### 分析目的

按设备+ISO周统计合格率，检测单周合格率较前一周下跌 >5 个百分点的突变事件，定位质量异常发生的精确时间窗口。

### SQL

```sql
SELECT `设备编号`, YEARWEEK(`检测时间`,3) as yw,
  COUNT(*) as total,
  SUM(CASE WHEN `整体检测结果`='合格' THEN 1 ELSE 0 END) as pass,
  ROUND(100*SUM(CASE WHEN `整体检测结果`='合格' THEN 1 ELSE 0 END)/COUNT(*),1) as pass_rate
FROM `zt_cyl_block_seal`
WHERE `整体检测结果` IN ('合格','不合格','可修复')
  AND `检测时间` >= '2026-01-01'
GROUP BY `设备编号`, yw HAVING total >= 10
ORDER BY `设备编号`, yw;
```

## ③ 断芯三台设备同名测量列均值系统性偏差

### 分析目的

`zt_cyl_block_brk_core_1` 与 `_2` 共享 57 列检测数据（F301/F302/F305 各点、定位孔径、孔中心距等），对比两台设备对同一测量特征的读数均值，判断是否存在系统性偏差（标定差异或传感器漂移）。`_3` 表结构与 `_1/_2` 完全不同，无可直接对比的同名列。

### SQL

```sql
-- 断芯1# 和 2# 的月度均值对比
SELECT DATE_FORMAT(`时间`,'%Y-%m') as mon,
  AVG(CAST(`F301_点1` AS DECIMAL(10,3))) as F301_1,
  AVG(CAST(`F302_点1` AS DECIMAL(10,3))) as F302_1,
  AVG(CAST(`F305_点1` AS DECIMAL(10,3))) as F305_1,
  AVG(CAST(`定位孔径` AS DECIMAL(10,3))) as dia,
  COUNT(*) as cnt
FROM `zt_cyl_block_brk_core_1`
WHERE `时间` >= '2026-01-01' AND `测量结果` IN ('合格','不合格')
  AND `F301_点1` != ''
GROUP BY mon ORDER BY mon;
-- 断芯2# 同上
```

## ④ 密封设备泄漏量基准漂移

### 分析目的

从 `zt_cyl_block_seal` 的"箱体检测数据"文本字段中提取泄漏量（cm³），按设备分组追踪月度平均泄漏量的变化趋势，检测基准漂移——即同一设备在相同工况下泄漏量系统性上升（密封老化）或下降（传感器灵敏度衰减）。

数据格式：`02>:  2.04 bar:(OK):  6.55 cm3/`

### SQL

```sql
SELECT `设备编号`, DATE_FORMAT(`检测时间`,'%Y-%m') as mon,
  ROUND(AVG(CAST(REGEXP_SUBSTR(`箱体检测数据`,
    '[0-9]+\\.?[0-9]*(?= *cm3)') AS DECIMAL(10,3))),1) as avg_leak,
  COUNT(*) as cnt
FROM `zt_cyl_block_seal`
WHERE `检测时间` >= '2026-01-01' AND `箱体检测数据` != ''
  AND `设备编号` IN ('3','5','6','7')
GROUP BY `设备编号`, mon HAVING cnt >= 10
ORDER BY `设备编号`, mon;
```

### 数据结果

**月度平均泄漏量（cm³）— 仅设备3/5/6/7 有可解析的泄漏数据：**

| 月 | 设备3 | 设备5 | 设备6 | 设备7 |
|:---|:---:|:---:|:---:|:---:|
| 01 | 10.8 | 22.5 | 5.3 | 12.1 |
| 02 | 13.6 | 31.7 | 10.1 | 11.1 |
| 03 | 15.0 | 43.1 | 7.9 | 14.3 |
| 04 | 13.9 | 49.0 | 11.2 | 46.2 ⚠️ |
| 05 | 13.2 | 21.9 | 6.7 | 15.0 |
| 06 | 8.7 | 30.0 | 8.2 | 18.4 |
| 07 | 10.8 | 41.7 | 20.8 ⚠️ | 14.5 |

**设备4、8、9 的"箱体检测数据"字段为 NULL**，无法提取泄漏量数值（数据格式不同或为空）。

### 结论

1. **设备5 泄漏量异常高且大幅震荡**：月均值在 21.9~49.0 cm³ 之间波动（振幅 27cm³），远高于设备3/6/7 的水平（5~15 cm³）。设备5 是同一产品族的试漏工位，泄漏量高二可能因产品型号不同而正常，但 22.5→49.0→21.9→41.7 的 M 形震荡需核实是产品切换还是密封件老化。
2. **设备7 04月突增至 46.2 cm³**：是正常水平的 3~4 倍，06月仍高于基线。建议检查该设备的密封夹具是否磨损。
3. **设备6 07月泄漏量突增至 20.8 cm³**：从历史 5~11 区间跃升（+150%），需立即点检。
4. **设备4/8/9 数据格式不同**："箱体检测数据"为空或格式与设备3/5/6/7不同（可能不包含 cm3 泄漏量字段），无法用同一正则提取。需确认这些设备的试漏数据存储在哪个字段。

## 数据局限性

1. **泄漏量覆盖不全**：设备 4/8/9 的"箱体检测数据"字段为空或格式不同，无法提取 cm³ 值。涉及约 26 万条记录。需确认这些设备的泄漏数据存储位置或改用其他字段（如"水道检测数据"）。
2. **断芯3# 无法对比**：其表结构与 1#/2# 完全不同（无可比同名列），无法纳入③的系统性偏差分析。该设备需独立评估。
3. **合格率突变仅2026年**：历史年份的突变未在本次分析中覆盖。若需趋势性分析，可扩展时间范围。
4. **空洞检测的"终点"问题**：设备3在07-01后无记录，当前方法只检测相邻记录间隔，不检测"最后一条记录距今"的空洞。设备3的当前空洞（16天无记录）需由监控系统捕获。
5. **evo_seal / 375t_seal / 50t_seal 等密封表未纳入**：这些表的数据格式、设备数量和检测类型与 zt_cyl_block_seal 不同，需单独分析。
