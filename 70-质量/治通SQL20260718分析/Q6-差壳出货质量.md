# Q6 差壳出货质量事件分析

> 数据源：`zt_diff_hous_shipment`（715,414 条，2022-08-25 ~ 2026-07-17）
> 分析日期：2026-07-17
> 执行者：quality Agent

---

## 一、分析目的

差壳出货检测表存在多种异常结果类型（重码、二维码错误、直径超差、不合格），本次分析旨在：
1. 量化各类异常的规模与占比
2. 定位重码的时间/人员聚集模式
3. 对比各差壳型号的不良率差异
4. 还原尺寸类质量事件（直径38超差）的完整事实
5. 评估视觉检测与最终判定的一致性

---

## 三、重码记录的时间聚类

### 3.1 月度分布（2022-08 ~ 2026-01）

```sql
SELECT DATE_FORMAT(`时间`,'%Y-%m') AS 月份, COUNT(*) AS 重码数

GROUP BY DATE_FORMAT(`时间`,'%Y-%m')
ORDER BY 月份;
```

**峰值月份 Top 5：**

| 月份 | 重码数 | 特征 |
|------|--------|------|
| 2022-09 | 558 | 单日峰值282（09-02），疑似系统切换 |
| 2023-08 | 498 | 单日峰值262（08-07） |
| 2023-12 | 432 | 跨多日分散（12-05~12-13） |
| 2024-09 | 246 | 单日峰值65（09-24） |
| 2024-03 | 234 | 跨多日分散 |
| 2025-07 | 207 | 本月仍在高位（截至17日） |

**趋势特征**：重码不是均匀分布的"背景噪声"，而是以**事件型爆发**（单日数十~数百条）集中在特定月份。2022-09、2023-08、2023-12 三轮爆发占全部重码的 31.1%。

## 四、分差壳类型不良率对比

```sql
SELECT `差壳类型`,
  COUNT(*) AS 总数,
  SUM(CASE WHEN `结果`='不合格' THEN 1 ELSE 0 END) AS 不合格数,
  SUM(CASE WHEN `结果`='重码' THEN 1 ELSE 0 END) AS 重码数,
  SUM(CASE WHEN `结果`='二维码错误' THEN 1 ELSE 0 END) AS 二维码错,
  SUM(CASE WHEN `结果`='直径38尺寸超差' THEN 1 ELSE 0 END) AS 尺寸超差,
  ROUND(SUM(CASE WHEN `结果`!='合格' THEN 1 ELSE 0 END)/COUNT(*)*100,2) AS 不良率
FROM zt_diff_hous_shipment
WHERE `差壳类型` IN ('DCT300','DCTeco','E38H','E28A','E38Q')
GROUP BY `差壳类型`
ORDER BY 总数 DESC;
```

| 差壳类型 | 总数 | 合格 | 不合格 | 重码 | 二维码错 | 尺寸超差 | **综合不良率** |
|----------|------|------|--------|------|----------|----------|---------------|
| DCT300 | 369,257 | 367,166 | 103 | 1,863 | 104 | 21 | **0.57%** |
| DCTeco | 212,644 | 211,695 | 115 | 724 | 110 | 0 | **0.45%** |
| E38H | 71,039 | 69,571 | 0 | 1,227 | 241 | 0 | **2.07%** |
| E28A | 49,162 | 48,370 | 0 | 651 | 141 | 0 | **1.61%** |
| E38Q | 12,700 | 12,401 | 0 | 277 | 22 | 0 | **2.35%** |

### 关键发现

1. **E 系列（E38H/E28A/E38Q）不良率是 DCT 系列的 3~5 倍**，但不良类型完全不同：
   - DCT 系列：有不合格（尺寸/外观问题）+ 重码 + 二维码错误
   - E 系列：**零不合格**，但重码率、二维码错误率显著偏高
2. E 系列的"不良"几乎全部是**识别层面的问题**（扫码/打码），不是产品本身的质量缺陷。
3. E38H 二维码错误 241 条（占其不良的 16.4%），远超 DCT300（104 条，5.0%）。E 系列二维码格式更复杂或读码设备兼容性差。

## 六、视觉结果与最终结果一致性核对

### 6.1 视觉系统覆盖情况

```sql
SELECT
  CASE WHEN `视觉结果` IS NULL THEN 'NULL(未启用)'
       WHEN `视觉结果`='' THEN '空字符串'
       ELSE `视觉结果` END AS 视觉状态,
  `结果`, COUNT(*) AS cnt
FROM zt_diff_hous_shipment
GROUP BY
  CASE WHEN `视觉结果` IS NULL THEN 'NULL(未启用)'
       WHEN `视觉结果`='' THEN '空字符串'
       ELSE `视觉结果` END,
  `结果`
ORDER BY cnt DESC;
```

| 视觉状态 | 最终结果 | 数量 | 一致性 |
|----------|----------|------|--------|
| NULL(未启用) | 合格 | 559,147 | — |
| 已检测 | 合格 | 150,196 | ✅ 一致 |
| NULL(未启用) | 重码 | 4,784 | — |
| NULL(未启用) | 二维码错误 | 658 | — |
| 空字符串 | 合格 | 390 | ⚠️ 视觉异常 |
| 未检测 | 不合格 | 187 | ⚠️ 视觉跳过 |
| 已检测 | 不合格 | 30 | ✅ 一致(捕获) |
| NULL(未启用) | 直径38超差 | 21 | — |

### 6.2 一致性评估

| 指标 | 数值 |
|------|------|
| 有视觉记录的总数 | 150,413（21.0%） |
| 视觉=已检测 且 结果=合格（正确通过） | 150,196 |
| 视觉=已检测 且 结果=不合格（正确拦截） | 30 |
| 视觉=未检测 且 结果=不合格（漏检风险） | 187 |
| **视觉覆盖率（全量）** | **21.0%** |
| **视觉覆盖率（不合格件）** | **13.8%（30/218）** |

### 关键发现

1. **78.9% 的记录没有视觉检测数据**（视觉结果=NULL），视觉系统并非全线覆盖。
2. 218 条不合格中，仅 30 条（13.8%）经过了视觉检测。其余 187 条（85.8%）的视觉结果为"未检测"——系统在视觉检测前就已判定不合格。
3. **30 条"已检测+不合格"记录为近期（2026-03~07）新增**，涉及 4 名操作人员（田俊丽、白志明、黄明飞、陈小兰），表明 2026 年起视觉系统开始对不合格件进行复检确认。
4. 未发现"视觉判定为合格但最终结果为不合格"的漏判案例。

## 七、数据质量问题（额外发现）

查询过程中发现以下数据污染：

1. **差壳类型列混入非类型值**：
   - 二维码内容（如 `00D0245A97A8`、`2309070000143/201306/...`）
   - 系统标识（`startrecord`、`Operator2`）
   - 重复拼接（`DCTecoDCTeco`、`E38HDCTeco`）
   - 共涉及约 30 条脏数据

2. **操作人员列混入二维码**：
   - `朱220830/201306/0000046/NE4C-7905-AA海艳`（操作人员名与二维码拼接）
   - 共涉及约 44 条脏数据

3. **二维码列含非二维码值**：
   - `Operator1`、`Operator4`、`6953666300875`（纯数字）、`startrecord`

这些数据污染可能指向**扫码枪配置或缓冲区溢出问题**，建议 IT 排查扫码设备固件。

## 八、结论与管理建议

### 8.1 质量风险评级

| 风险项 | 严重度 | 趋势 | 行动优先级 |
|--------|--------|------|-----------|
| 重码系统误报 | 中 | 波动，2025-07 抬头 | P1 |
| 二维码识别失败（E系列） | 中 | 持续存在 | P1 |
| 直径38尺寸批量超差 | **高** | 2025-08 单次事件 | P0（复盘） |
| 视觉覆盖率不足 | 中 | 2026 年改善中 | P2 |
| 数据列污染 | 低 | 偶发 | P3 |

### 8.2 具体管理行动

**P0 — 尺寸超差复盘（品质部/生产部）**
- 调取 2025-08-15 工位 1 DCT300 线的**刀具寿命记录**和**SPC 控制图**，确认刀具磨损是否为根因（21 件连续超差高度指向刀具/夹具问题）。
- 检查当时的**在线测量频次**：为什么 15 分钟内连续 21 件超差未被拦截？在线检测间隔应 ≤ 检测节拍 × 3。

**P1 — 重码消减（IT + 品质部）**
- 工位 1 扫码枪排查：**全部 4,784 条重码均来自工位 1**，工位 2 从未出现。优先检查工位 1 扫码枪型号/配置/缓存设置差异。
- 12:00 重码峰值（578 条/小时）可能与午间**扫码枪休眠/系统待机恢复**有关，建议测试并消除。

**P1 — E 系列二维码识别优化（IT）**
- E38H（241 条二维码错误）/ E28A（141 条）的识别失败率显著高于 DCT 系列。检查 E 系列二维码的**打印质量、对比度、打码位置**是否与 DCT 系列存在差异。
- 建议与二维码供应商确认 E 系列打码参数。

**P2 — 视觉系统扩展（品质部）**
- 当前仅 21% 记录有视觉检测，不合格件仅 13.8% 有视觉复检。2026 年起已在改善。
- 目标：将不合格件的视觉覆盖率提升至 80% 以上。

### 8.3 一句话总结

> 差壳出货质量的核心矛盾不是产品不合格（仅 218 条/0.03%），而是**识别系统的可靠性问题**（重码 4,784 条 + 二维码错误 658 条，合计占异常 95.7%）。工位 1 的扫码系统需要重点排查，E 系列二维码格式需要优化，2025-08-15 DCT300 直径超差事件必须完成根因复盘。

## 九、数据局限性

1. **视觉结果覆盖不全**：78.9% 记录无视觉数据（NULL），无法对全部不合格件做视觉交叉验证。
2. **直径超差根因无法从数据库确定**：表中无刀具编号、夹具编号、SPC 实测值（如直径 38.01mm），只能定位到"时/人/机/料"层面，无法确认为刀具磨损还是夹具偏移。
3. **重码的真伪无法区分**：重码可能是同一工件被重复扫描（操作问题），也可能是两个不同工件被打上相同二维码（打码问题）。表中 `重码` 列恒为 NULL，无法区分。
4. **差壳类型列存在数据污染**，约 30 条记录的类型值不符合规范，相关统计中已排除。
5. **E 系列（E38H/E28A/E38Q）无不合格记录**需要关注：是 E 系列确实质量好，还是检测标准/判定逻辑不同？此表无法回答。
