```sql
SELECT CASE 
    WHEN TOTAL_TIME < 30 THEN '<30s'
    WHEN TOTAL_TIME < 60 THEN '30-60s'

    WHEN TOTAL_TIME < 120 THEN '90-120s'

ORDER BY FIELD(耗时区间,'<30s','30-60s','60-90s','90-120s','120-180s','180-300s','>=300s(瓶颈)');
```

**结论**:
- 左工位：50.3% 的检测在 60-90s 完成，分布集中，节拍稳定。瓶颈件（>=300s）占 3.6%（233件），需单独排查。

- **管理行动**: 导出左工位 233 件瓶颈件（>=300s）和右工位 269 件瓶颈件的 `START_DATETIME`，对照 MES 班次记录判断是否为特定时段/班次问题。

## 四、AREA_RESULT 不合格集中区域分析

### 重要发现：AREA_RESULT ≠ 合格/不合格

AREA_RESULT 取值是 `已检测` / `未检测` / `NULL`，反映的是**该区域是否被执行了检测**，而非检测结果的 pass/fail。真正的合格/不合格在 `RESULT` 列。

### 不合格记录的"未检测"模式

**左工位**（96 件不合格）：不合格记录的特点是**大面积未检测**。

| 区域 | 不合格件中的未检测率 |
|------|---------------------|
| AREA_19 | 80.2% |
| AREA_11/13/14/16 | 79.2% |
| AREA_1~8, 12, 15, 17, 18 | 74-77% |
| AREA_21~34 | 74% |
| **AREA_9** | **6.3%** |
| **AREA_10** | **6.3%** |

**右工位**（14 件不合格，样本小）：

| 区域 | 不合格件中的未检测率 |
|------|---------------------|
| AREA_12 | 35.7% |
| AREA_11 | 28.6% |
| AREA_10 / AREA_7 | **0.0%** |

```sql
-- 不合格记录各区未检测率
SELECT 'AREA_1' AS 区域, 
  ROUND(SUM(CASE WHEN AREA_RESULT_1='未检测' THEN 1 ELSE 0 END)*100.0/COUNT(*),1) AS 未检测率
FROM left_front_wheel_housing_detection_system WHERE RESULT='不合格'
UNION ALL SELECT 'AREA_2', ... -- 34个UNION ALL
ORDER BY 未检测率 DESC;
```

**结论**:
- 不合格 ≠ 发现缺陷。不合格的根因是**检测系统未能完成扫描**（大面积未检测），而非工件本身有质量问题。
- 左工位：AREA_9 和 AREA_10 的未检测率仅 6.3% —— 这两个区域对系统异常具有最强鲁棒性，几乎总是能完成检测。其余 32 个区域在异常发生时 74-80% 的概率无法完成。
- 不合格件的 CONCENTRATION 均值仅 27.0，远低于合格件的 90.8 —— 浓度偏低是系统未正常扫描的直接信号。
- **管理行动**:
  1. 建立实时监控：当 CONCENTRATION < 50 时触发预警，提前拦截潜在不合格。
  2. 排查导致大面积未检测的系统性原因（光照异常、工件定位偏移、相机通讯中断），优先从 AREA_9/10 的差异入手——分析为什么这两个区域在同样条件下能完成检测。

### 月度趋势

| 月份 | 左检测数 | 左合格率 | 左均耗 | 右检测数 | 右合格率 | 右均耗 |
|------|---------|---------|--------|---------|---------|--------|
| 2026-03 | 2,101 | 93.5% | 87.1s | 1,809 | 96.7% | 90.0s |
| 2026-04 | 1,634 | 96.1% | 94.5s | 1,476 | 94.5% | 110.1s |
| 2026-05 | 2,194 | **97.7%** | 82.0s | 2,317 | 96.2% | 107.3s |
| 2026-06 | 59 | **72.9%** | 148.9s | 0 | — | — |
| 2026-07 | 452 | 89.6% | 110.5s | 0 | — | — |

```sql
-- 月度汇总
SELECT DATE_FORMAT(d,'%Y-%m') AS 月份,
  SUM(CASE WHEN t='L' THEN cnt ELSE 0 END) AS 左检测数,
  CONCAT(ROUND(SUM(CASE WHEN t='L' THEN pass ELSE 0 END)*100.0/NULLIF(SUM(CASE WHEN t='L' THEN cnt ELSE 0 END),0),1),'%') AS 左合格率,
  ROUND(SUM(CASE WHEN t='L' THEN total ELSE 0 END)/NULLIF(SUM(CASE WHEN t='L' THEN cnt ELSE 0 END),0),1) AS 左均耗,
  SUM(CASE WHEN t='R' THEN cnt ELSE 0 END) AS 右检测数,
  CONCAT(ROUND(SUM(CASE WHEN t='R' THEN pass ELSE 0 END)*100.0/NULLIF(SUM(CASE WHEN t='R' THEN cnt ELSE 0 END),0),1),'%') AS 右合格率,
  ROUND(SUM(CASE WHEN t='R' THEN total ELSE 0 END)/NULLIF(SUM(CASE WHEN t='R' THEN cnt ELSE 0 END),0),1) AS 右均耗
FROM (
  SELECT DATE(START_DATETIME) d, 'L' AS t, COUNT(*) AS cnt, SUM(CASE WHEN RESULT='合格' THEN 1 ELSE 0 END) AS pass, SUM(TOTAL_TIME) AS total
  FROM left_front_wheel_housing_detection_system GROUP BY DATE(START_DATETIME)
  UNION ALL
  SELECT DATE(START_DATETIME) d, 'R' AS t, COUNT(*) AS cnt, SUM(CASE WHEN RESULT='合格' THEN 1 ELSE 0 END) AS pass, SUM(TOTAL_TIME) AS total
  FROM right_front_wheel_housing_detection_system GROUP BY DATE(START_DATETIME)
) sub GROUP BY 月份 ORDER BY 月份;
```

**结论**:
- 左工位效率持续优于右工位（快 13-15%），且 5 月达到峰值（97.7% 合格率，82s 均耗）。
- 左工位 6-7 月明显恶化：合格率骤降至 72.9%~89.6%，均耗升至 110-149s。需排查 6 月 27 日恢复生产后的设备状态变化。
- 右工位 5 月底停线，6 月至今零数据。需确认：① 是产线调整暂停还是采集故障？② 若已停用，左工位是否承担了全部产能？
- **管理行动**:
  1. 左工位：追溯 6/27 前后的设备维护记录，对比维护前后的 AREA_TIME 和未检测率变化。
  2. 右工位：确认停线原因和恢复计划。若长期停用，评估左工位单线产能是否满足节拍要求（当前左工位日均约 60 件，按 3-5 月产能推算月均约 1,800 件）。

## 九、数据局限性

1. **右工位数据中断**：2026-05-28 后无数据，6-7 月的右工位状态完全未知，左右对比结论不适用于近两个月。
2. **AREA_RESULT 语义有限**：仅有 `已检测/未检测` 二元状态，无法区分"检测了但发现缺陷"和"检测了且合格"。真正的缺陷检出率无法计算。
3. **RESULT_TYPE 全 NULL**：无法按异常类型分类分析。
4. **AREA_21~34 零数据**：无法判断是硬件未配置还是采集程序未实现，影响对系统完整性的判断。
5. **6 月数据稀疏**：左工位仅 6/27 一天 59 条记录，5/29~6/26 完全空白（间隔 29 天），可能是产线停产或数据采集中断，此期间的趋势推断不可靠。
6. **CONCENTRATION 语义未确认**：平均值差异显著（合格 90.8 vs 不合格 27.0），但具体物理含义需与设备供应商确认后才能作为正式判异标准。
