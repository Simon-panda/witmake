# E3 — 打码设备健康度对比分析

> 分析日期：2026-07-17 | 数据源：zt_cyl_block_las_mark（64.3万条）+ zt_dct_las_mark（42.3万条）

---

## 一、分析目的

对比缸体打码（9条线）和 DCT 差壳打码（5条线）的设备健康度，聚焦四个维度：
1. **错误率排名** —— 哪些打码机错误率最高
2. **错误类型分类** —— 主要故障模式是什么
3. **报警通知时效** —— 通知是否及时送达
4. **工作量与错误率相关性** —— 高负荷是否导致更多错误

---

## 二、使用的 SQL

### 2.1 错误率排名（缸体）

```sql
SELECT 
  device_name,
  COUNT(*) AS total,
  SUM(CASE WHEN error_info IS NOT NULL AND error_info != '' THEN 1 ELSE 0 END) AS errors,
  ROUND(SUM(CASE WHEN error_info IS NOT NULL AND error_info != '' THEN 1 ELSE 0 END) / COUNT(*) * 100, 2) AS error_pct,
  MIN(timestamp), MAX(timestamp),
  COUNT(DISTINCT DATE(timestamp)) AS active_days
FROM zt_cyl_block_las_mark
GROUP BY device_name
ORDER BY error_pct DESC;
```

### 2.2 DCT 错误率确认

```sql
SELECT device_name, COUNT(*) AS total,
  SUM(CASE WHEN error_info IS NOT NULL AND error_info != '' THEN 1 ELSE 0 END) AS errors
FROM zt_dct_las_mark
GROUP BY device_name;
```

### 2.3 错误文本分类

```sql
SELECT 
  CASE 
    WHEN error_info LIKE '%二维码格式错误%' THEN '二维码格式错误'
    WHEN error_info LIKE '%MP产品年份编码错误%' AND error_info LIKE '%流水号超出%' THEN '年份编码+流水号超限'
    WHEN error_info LIKE '%MP产品年份编码错误%' AND error_info LIKE '%只能在生产线%' THEN 'MP线号+年份编码'
    WHEN error_info LIKE '%MP产品年份编码错误%' THEN 'MP产品年份编码错误'
    WHEN error_info LIKE '%MP缸体%只能在生产线%' THEN 'MP缸体线号错误'
    WHEN error_info LIKE '%未知的零件号%' THEN '未知零件号'
    WHEN error_info LIKE '%设备与线号不匹配%' AND error_info LIKE '%流水号超出%' THEN '设备线号不匹配+流水号超限'
    WHEN error_info LIKE '%设备与线号不匹配%' THEN '设备与线号不匹配'
    WHEN error_info LIKE '%流水号超出%' THEN '流水号超出允许范围'
    ELSE '其他'
  END AS error_type,
  COUNT(*) AS cnt
FROM zt_cyl_block_las_mark
WHERE error_info IS NOT NULL AND error_info != ''
GROUP BY error_type
ORDER BY cnt DESC;
```

### 2.4 报警通知响应时效

```sql
SELECT 
  device_name,
  COUNT(*) AS error_total,
  SUM(CASE WHEN notification_status = 1 THEN 1 ELSE 0 END) AS notified,
  ROUND(AVG(CASE WHEN notified_at IS NOT NULL 
    THEN TIMESTAMPDIFF(SECOND, timestamp, notified_at) END), 0) AS avg_sec,
  ROUND(MAX(CASE WHEN notified_at IS NOT NULL 
    THEN TIMESTAMPDIFF(SECOND, timestamp, notified_at) END), 0) AS max_sec
FROM zt_cyl_block_las_mark
WHERE error_info IS NOT NULL AND error_info != ''
GROUP BY device_name;
```

### 2.5 日工作量与错误率

```sql
SELECT 
  device_name,
  COUNT(DISTINCT DATE(timestamp)) AS active_days,
  COUNT(*) AS total_marks,
  ROUND(COUNT(*) / COUNT(DISTINCT DATE(timestamp)), 0) AS daily_avg,
  SUM(CASE WHEN error_info IS NOT NULL AND error_info != '' THEN 1 ELSE 0 END) AS errors,
  ROUND(SUM(CASE WHEN error_info IS NOT NULL AND error_info != '' THEN 1 ELSE 0 END) / COUNT(*) * 100, 4) AS error_pct
FROM zt_cyl_block_las_mark
GROUP BY device_name
ORDER BY error_pct DESC;
```

### 2.6 错误月度趋势

```sql
SELECT device_name, DATE_FORMAT(timestamp, '%Y-%m') AS month, COUNT(*) AS errors
FROM zt_cyl_block_las_mark
WHERE error_info IS NOT NULL AND error_info != ''
  AND device_name IN ('缸体3线', '缸体7线', '缸体9线')
GROUP BY device_name, month
ORDER BY device_name, month;
```

## 四、结论与管理行动

### 结论1：打码错误本质是配置管理问题，非设备硬件故障

83.9% 的错误（312/372）是**设备与线号不匹配**或**流水号超限**——这是线号配置/流水号段分配不一致导致的软件层问题，不是激光头、传感器等硬件故障。真正的打标内容异常（二维码格式、年份编码）仅占 13.7%。

### 结论2：DCT 差壳打码健康度满分，缸体打码两极分化

DCT 差壳 5 条线 42.5 万件零错误，说明打码系统本身是成熟的。缸体 9 条线中 5 条（1/4/5/6 线）也是零或接近零错误，问题集中在 3/7/8/9 线。

### 结论3：报警通知机制在用但存在批量延迟

372 条错误全部触发了通知（100%），平均响应 3-6 分钟。但缸体7线出现一次 7.8 小时延迟（3 条年份编码错误批量推送）。这是通知系统架构问题（批量轮询 vs 实时推送）。

### 结论4：错误与产品切换强相关，与产能负荷无关

数据分析明确否定了"高负荷导致更多错误的假设"——日均 171 件的缸体4线零错误。错误集中出现在产品类型切换时（尤其是 MP 缸体上线），说明线号/流水号配置在换型时未同步更新。

## 五、数据局限性

1. **error_info 仅为打码系统自身记录的校验错误**，不包含硬件层错误（如激光功率衰减、镜头污染、通信中断等）。无法判断是否存在"打码成功但质量下降"的隐性退化。
2. **缸体9线样本量过小**（946条/25天），错误率 8.67% 可能被小样本放大。且该线已于 2026-03 停用，无法验证当前状态。
3. **notified_at 字段**在 372 条错误中仅 290 条有值（缸体7线 119 条中仅 70 条有值），通知时效分析可能低估了实际延迟。
4. **DCT 差壳打码零错误**可能意味着 error_info 字段未被使用（而非真的零故障），需现场确认 DCT 打码系统是否接入了同样的错误上报逻辑。
5. **缺少设备维保记录关联**：无法判断错误是否与维保事件（换激光头、校准、固件升级）在时间上吻合。
