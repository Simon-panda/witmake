# P4 — 差壳出货物流与视觉拦截效能分析

> 数据源：`zt_diff_hous_shipment`（715,414行，2022-08-25 ~ 2026-07-17）
> 分析日期：2026-07-17

---

## 一、分析目的

1. **箱码维度**：每箱装件量、箱码命名规则与流转节奏
2. **视觉检测拦截效能**：视觉系统上线后的拦截率，以及未检漏过的风险面

4. **重码追溯**：同一二维码多次出货的规模与模式

## 三、箱码维度分析

### 3.1 箱码覆盖率

```sql
SELECT `差壳类型`, COUNT(*) AS 总合格数,
  SUM(CASE WHEN `箱码` IS NULL OR `箱码`='' OR `箱码`='PASS' THEN 1 ELSE 0 END) AS 无箱码,
  SUM(CASE WHEN `箱码` IS NOT NULL AND `箱码`!='' AND `箱码`!='PASS' THEN 1 ELSE 0 END) AS 有箱码
FROM zt_diff_hous_shipment WHERE `结果`='合格'
GROUP BY `差壳类型` ORDER BY 总合格数 DESC;
```

| 差壳类型 | 总合格数 | 有箱码 | 箱码覆盖率 |
|----------|---------|--------|-----------|
| DCT300 | 367,166 | 71,098 | 19.4% |
| DCTeco | 211,695 | 79,471 | 37.5% |
| E38H | 69,571 | 0 | 0% |
| E28A | 48,370 | 17 | 0.04% |
| E38Q | 12,401 | 0 | 0% |

**关键发现**：仅DCT300和DCTeco使用箱码追溯，E38H/E38Q/E28A完全无箱码。DCTeco箱码覆盖率(37.5%)高于DCT300(19.4%)，但两者均远未达到100%。

### 3.2 箱码命名规则

箱码格式示例：`UNDeco20260715103`

- `UN` = 前缀（固定）
- `Deco` = 产品简称（DCTeco→Deco；DCT300→D300）
- `20260715` = 生产日期
- `103` = 当日箱序号（3位流水号）

箱码自带日期信息，可用于追溯生产批次。

### 3.3 每箱容量与件数

```sql
SELECT `差壳类型`, COUNT(DISTINCT `箱码`) AS 箱数,
  ROUND(AVG(箱容量),0) AS 均件每箱, MAX(箱容量) AS 最大箱容
FROM (
  SELECT `箱码`, `差壳类型`, MAX(CAST(`容量` AS UNSIGNED)) AS 箱容量
  FROM zt_diff_hous_shipment
  WHERE `结果`='合格' AND `容量` REGEXP '^[0-9]+$'
    AND `箱码` IS NOT NULL AND `箱码`!='' AND `箱码`!='PASS'
  GROUP BY `箱码`, `差壳类型`
) t GROUP BY `差壳类型`;
```

| 差壳类型 | 箱数 | 均件/箱 | 最大箱容 |
|----------|------|---------|---------|
| DCT300 | 396 | 180 | 180 |
| DCTeco | 443 | 179 | 180 |

**结论**：标准箱容为180件（6层×30件或类似排列），两类差壳一致。`检测数量`列为全局累加计数器（从1号~74630+），跨箱连续递增，不是单箱数量；`容量`列才是箱内序号（1-180循环）。

### 3.4 箱内流转节奏

```sql
SELECT `差壳类型`,
  AVG(TIMESTAMPDIFF(SECOND, prev_time, `时间`)) AS 均间隔秒,
  MIN(TIMESTAMPDIFF(SECOND, prev_time, `时间`)) AS 最小区隔秒
FROM (
  SELECT `时间`, `差壳类型`, `箱码`,
    LAG(`时间`) OVER (PARTITION BY `箱码` ORDER BY `时间`) AS prev_time
  FROM zt_diff_hous_shipment
  WHERE `结果`='合格' AND `箱码` IS NOT NULL AND `箱码`!='' AND `箱码`!='PASS'
) t WHERE prev_time IS NOT NULL
GROUP BY `差壳类型`;
```

| 差壳类型 | 均间隔 | 最短间隔 |
|----------|--------|---------|
| DCT300 | 234秒 (3.9分) | 4秒 |
| DCTeco | 208秒 (3.5分) | 4秒 |

极值可到4秒（连续扫码），中位数约3.5-4分钟一件。一箱180件约需10.5-11.7小时完成。

## 四、视觉检测拦截效能

### 4.1 视觉检测上线时间线

```sql
SELECT DATE_FORMAT(`时间`,'%Y-%m') AS 月份, COUNT(*) AS 总出货,
  SUM(CASE WHEN `视觉结果`='已检测' THEN 1 ELSE 0 END) AS 视觉已检,
  ROUND(SUM(CASE WHEN `视觉结果`='已检测' THEN 1 ELSE 0 END)*100.0/COUNT(*),1) AS 覆盖率
FROM zt_diff_hous_shipment WHERE `结果`='合格'
GROUP BY 月份 ORDER BY 月份;
```

**关键时间节点**：
- **2022-08 ~ 2025-12**（40个月）：视觉覆盖率为 **0%**，559,537件合格品**全部未经视觉检测**即出货。
- **2026-01**：视觉系统试运行，覆盖率51.9%（过渡期）。
- **2026-02 ~ 至今**：视觉覆盖率 **100%**，所有合格品均有视觉检测记录。

### 4.4 漏检风险评估

| 风险类别 | 数量 | 说明 |
|----------|------|------|
| 历史未检出货 | 559,537件 | 2025年底前全部无视觉检测，已交付客户 |

**核心问题**：0.02%的拦截率极低，有两种可能：(1)差壳终检质量确实极高；(2)视觉系统判罚阈值过于宽松，存在漏检。目前数据无法区分这两种情况。

## 六、重码分析

### 6.1 重码标识字段说明

表中两个重码相关字段：

| 字段 | 含义 | 值分布 |
|------|------|--------|
| `重码` | 系统实时检测到二维码已存在 | NULL:564,610 / 否:138,472 / 是:12,332 |
| `结果` | 最终出货判定 | 重码:4,784（实际拦截） |

**关键矛盾**：系统检测到重码（`重码`='是'）12,332次，但最终仅4,784次被判定为`结果`='重码'。另有12,312次**重码='是'但结果='合格'**——检测到重复但仍放行。

### 6.2 同一二维码的出货记录数

```sql
SELECT 结果链, COUNT(*) AS 码数
FROM (
  SELECT `二维码`, GROUP_CONCAT(DISTINCT `结果` ORDER BY `时间` SEPARATOR '→') AS 结果链
  FROM zt_diff_hous_shipment GROUP BY `二维码` HAVING COUNT(*) > 1
) t GROUP BY 结果链 ORDER BY 码数 DESC;
```

| 结果链 | 二维码数 | 风险等级 |
|--------|---------|---------|
| 合格→合格→... | 11,727 | ⚠️ 同一码多次合格出货 |
| 合格→重码 | 3,883 | ✓ 正常拦截 |
| 二维码错误→重码 | 377 | ✓ 正常 |
| 不合格→合格 | 186 | △ 返工后放行 |
| 合格→不合格 | 14 | ⚠️ 先合格后否定 |
| 重码→合格 | 3 | 🔴 拦截后翻案放行 |
| 直径38尺寸超差→重码 | 14 | ✓ 正常 |

### 6.3 重码频次分布

| 重复次数 | 二维码数 |
|----------|---------|
| 2次 | 15,604 |
| 3-5次 | 614 |
| 6-10次 | 26 |
| 11-20次 | 8 |
| 21次以上 | 2（最高22次） |

**极端案例**：`230605/201306/0000069/LD2C-7911-AA` 被扫描22次（2023-06-05 ~ 2023-06-06），全部为合格→重码链，属正常拦截行为。

### 6.4 重码核心发现

11,727个二维码存在"合格→合格"链——同一码多次以合格状态出货。这意味着：
- 可能情景A：同一物理件被重复扫描登记（系统未去重）
- 可能情景B：不同物理件被赋予了相同二维码（标签管理问题）
- 可能情景C：出货后返工、重新上线但码未更新

实际出货物理量可能被高估——11,727个码对应至少23,454条合格记录（最少2次），实际可能更多。

## 七、结论与管理建议

### 7.1 箱码追溯：当前仅覆盖DCT系列且覆盖率不足

**事实**：E38H/E38Q/E28A完全无箱码（合计13万件无法按箱追溯）；DCT系列也仅19%-38%有箱码。

**建议**：
- **立即**：对E38H/E38Q/E28A出货工位加装箱码扫描，实现全产品线追溯
- **1周内**：排查DCT300/DCTeco为何仅19-38%有箱码——是否为工艺路线不统一？固定扫码工位是否为必经节点？
- **目标**：1个月内箱码覆盖率达到100%

### 7.2 视觉检测：拦截率0.02%需要基准验证

**事实**：视觉系统上线6个月仅拦截30件，拦截率0.020%。559,537件历史出货完全未经视觉检测。

**建议**：
- **1周内**：抽取100件视觉"已检测合格"的差壳，人工复检确认视觉系统判罚准确性。如果人工检出率>0.1%，说明阈值需收紧。
- **建立基准**：由质量部定义视觉检测的"可接受漏检率"（如目标拦截率≥0.1%），按月监控。
- **追溯历史风险**：由于2022-2025年559K件无视觉数据，客户端的差壳相关投诉是否异常？如有集中投诉，需排查是否为视觉可检测类缺陷。

### 7.3 人员绩效：异常率极差35倍，需标准化

**事实**：朱海艳异常率4.55% vs 刘沐晨0.13%，差距35倍。

**建议**：
- **本周**：质量主管与朱海艳（4.55%）、夏尚尚（2.48%）、李顺东（0.88%）逐一回顾异常类型分布，确定是操作问题还是工位/产品差异。
- **2周内**：以彭福林(0.22%)和刘沐晨(0.13%)为标杆，制定标准操作流程图，全员培训。
- **持续**：建立个人周异常率看板，异常率>1%自动触发主管复核。

### 7.4 重码治理：11,727个码被重复放行，需堵漏洞

**事实**：系统检测到重码12,332次（`重码`='是'），但仅拦截4,784次（`结果`='重码'）。12,312次重码检测后仍以"合格"放行。

**建议**：
- **立即**：追查12,312次"检测到重码但放行合格"的原因——是系统逻辑漏洞（重码检测和结果判定解耦），还是人工覆盖？
- **规则建议**：`重码`='是'应强制触发`结果`≠'合格'，至少进入人工复核队列。
- **标签管理**：排查是否存在不同工件共用同一二维码标签的情况（11,727个码多次合格）。

## 八、数据局限性

1. **视觉结果仅记录"已检测/未检测"，不存储具体合格/不合格判定**——无法区分"视觉通过"和"视觉拦截后人工放行"。视觉系统的详细判定结果(各区域OK/NG)可能在其他表（如`left/right_front_wheel_housing_detection_system`仅适用于轮罩，差壳视觉的详细结果表未找到）。

2. **箱码覆盖率低**（仅DCT系列有，且不完整），基于箱码的流转分析仅代表约21%的出货量（150K/710K）。

3. **2026-01为视觉过渡期**（覆盖率51.9%），该月数据混合了有检和无检记录，统计时需注意。

4. **差壳类型列存在脏数据**（约100条产品类型为二维码串、系统指令等），虽已排除但说明数据录入校验不足。

5. **检测数量和容量列为VARCHAR**，需要CAST转换，极少数非数字值（如'PASS'）被排除。

6. **无法直接验证"视觉结果无不合格但实际有缺陷"**——需要人工抽检数据或客户端投诉数据才能校准视觉拦截率的真实性。
