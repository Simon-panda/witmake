## 一、二维码格式跨表一致性

### 1.1 分析目的

检查各表二维码字段的长度分布、前缀模式、空格/大小写差异，判断能否直接跨表 JOIN。重点验证打码表 mark_code 与密封表二维码的匹配率。

### 1.2 使用 SQL

```sql
-- 各表长度分布
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_block_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(mark_code) AS len, COUNT(*) AS cnt FROM zt_cyl_block_las_mark GROUP BY LENGTH(mark_code);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_head_50t_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_head_nf1_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_head_evo_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_head_gl31_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_head_gb6_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_cyl_head_375t_seal GROUP BY LENGTH(二维码);
SELECT LENGTH(二维码) AS len, COUNT(*) AS cnt FROM zt_diff_hous_shipment GROUP BY LENGTH(二维码);
SELECT LENGTH(mark_code) AS len, COUNT(*) AS cnt FROM zt_dct_las_mark GROUP BY LENGTH(mark_code);

-- 前缀分布
SELECT LEFT(二维码,4) AS prefix, COUNT(*) AS cnt FROM zt_cyl_block_seal WHERE LENGTH(二维码)=31 GROUP BY prefix;
SELECT LEFT(二维码,4) AS prefix, COUNT(*) AS cnt FROM zt_diff_hous_shipment WHERE LENGTH(二维码)=34 GROUP BY prefix ORDER BY cnt DESC LIMIT 15;
SELECT LEFT(二维码,4) AS prefix, COUNT(*) AS cnt FROM zt_cyl_head_nf1_seal WHERE LENGTH(二维码)=30 GROUP BY prefix ORDER BY cnt DESC LIMIT 10;

-- 空格检测
SELECT SUM(CASE WHEN 二维码 LIKE '% %' THEN 1 ELSE 0 END) AS has_space, COUNT(*) AS total FROM zt_cyl_head_nf1_seal;

-- 打码表 vs 密封表 JOIN
SELECT COUNT(*) FROM zt_cyl_block_las_mark m INNER JOIN zt_cyl_block_seal s ON m.mark_code = s.二维码;
SELECT COUNT(*) FROM zt_cyl_block_las_mark m LEFT JOIN zt_cyl_block_seal s ON m.mark_code = s.二维码 WHERE s.二维码 IS NULL;
SELECT COUNT(*) FROM zt_cyl_block_seal s LEFT JOIN zt_cyl_block_las_mark m ON s.二维码 = m.mark_code WHERE m.mark_code IS NULL;
```

### 1.4 结论

1. **V210前缀体系（缸体+部分缸盖）格式统一**：block_las_mark、block_seal、brk_core、evo_seal 均为31位 V210 前缀，无空格，可直接 JOIN。实测打码↔密封精确匹配率良好（99.3万对匹配）。

2. **缸盖家族格式分裂严重**：6个缸盖密封表使用不同长度（16/17/24/25/26/30），前缀各不相同，无法跨型号直接 JOIN。

3. **nf1_seal 存在严重空格污染（P0级别）**：51.5%记录二维码含前置空格，且该表二维码分裂为30位和16位两种格式。任何 nf1 相关的跨表分析必须先 `TRIM(二维码)` 并统一长度。

4. **打码表与密封表有双向缺口**：约19.3万条打码记录无对应密封记录（可能漏检或未同步），约14.5万条密封记录无对应打码记录（可能手工录入或时序差异）。

## 二、产品型号字典归一化

### 2.1 分析目的

zt_cyl_block_seal.产品类型 存在同一型号多种写法（LPNA/LP_NA/MP-LP_NA），建立归一化映射表供所有后续分析引用。

### 2.2 使用 SQL

```sql
SELECT `产品类型`, COUNT(*) AS cnt FROM zt_cyl_block_seal GROUP BY `产品类型` ORDER BY cnt DESC;
```

### 2.3 全部取值

| 原始值 | 记录数 | 占比 | 归一化型号 | 说明 |
|--------|--------|------|-----------|------|
| PFI | 565,766 | 49.7% | **PFI** | 标准 |
| MP | 212,429 | 18.7% | **MP** | 标准 |
| LPNA | 207,339 | 18.2% | **LPNA** | 标准（推荐格式） |
| LP | 75,063 | 6.6% | **LP** | 标准 |
| TDC | 30,284 | 2.7% | **TDC** | 标准 |
| LP_NA | 26,400 | 2.3% | **LPNA** | ⚠️ 下划线变体，归一化到 LPNA |
| MPNA | 13,025 | 1.1% | **MPNA** | 标准 |
| MP/LP_NA | 4,598 | 0.40% | **LPNA** | ⚠️ 混写脏数据，从上下文判为 LPNA |
| MP_NA | 2,737 | 0.24% | **MPNA** | ⚠️ 下划线变体，归一化到 MPNA |
| 0 | 2 | 0.0002% | **NULL** | 脏数据，无法判定 |

### 2.4 归一化映射表（后续所有分析必须引用）

```sql
-- 标准映射：本表中查询使用
CASE `产品类型`
  WHEN 'PFI'       THEN 'PFI'
  WHEN 'MP'        THEN 'MP'
  WHEN 'LPNA'      THEN 'LPNA'
  WHEN 'LP_NA'     THEN 'LPNA'
  WHEN 'MP/LP_NA'  THEN 'LPNA'
  WHEN 'LP'        THEN 'LP'
  WHEN 'TDC'       THEN 'TDC'
  WHEN 'MPNA'      THEN 'MPNA'
  WHEN 'MP_NA'     THEN 'MPNA'
  ELSE NULL
END AS 归一化产品类型
```

| 归一化型号 | 合并记录数 | 合并占比 |

| PFI | 565,766 | 49.7% |
| LPNA | 238,337 | 21.0% |
| MP | 212,429 | 18.7% |
| LP | 75,063 | 6.6% |

## 四、db_table_mapping 覆盖核对

### 4.1 分析目的

核对 db_table_mapping（52条元数据记录）与数据库实际 35 张表的对应关系，找出缺失映射和悬空引用。

### 4.2 使用 SQL

```sql
SELECT original_table_name FROM db_table_mapping ORDER BY original_table_name;
SELECT TABLE_NAME FROM information_schema.TABLES WHERE TABLE_SCHEMA='zt_server_data' ORDER BY TABLE_NAME;
```

### 4.3 核对结果

| 指标 | 数值 |
|------|------|
| 数据库实际用户表（排除元数据表/视图） | 33 张 |
| db_table_mapping 条目数 | 52 条 |
| 映射正确（mapping→实际表存在） | **28 条** |
| 缺失映射（表存在但无 mapping） | **3 张** |
| 悬空引用（mapping指向不存在的表） | **24 条** |

### 4.4 缺失映射（P1 — 有表无记录）

| 缺失的表 | 行数 | 业务含义 |
|---------|------|---------|
| **zt_cyl_head_gb6_seal** | 249,300 | GB6缸盖密封检测 |
| **zt_cyl_head_nf1_seal** | 767,232 | NF1缸盖密封检测 |
| **zt_cyl_head_gs6_las_mark** | 1,628 | GS6缸盖打标 |

> 三张表合计超过100万条记录却无元数据映射，后续所有按 product_code/process_code 筛选分析都会漏掉这些表。

### 4.5 悬空引用（P2 — mapping指向不存在表）

| left_rear_wheel_housing_detection_system | 云服务器 | 左后轮罩 |
| right_rear_wheel_housing_detection_system | 云服务器 | 右后轮罩 |
| zt_cyl_head_*_ext_insp (6张) | 云服务器 | 各型号缸盖外检 |
| zt_diff_hous_ext_insp | 云服务器 | 差壳外检 |
| zt_struc_part_*_ext_insp (2张) | 云服务器 | 结构件外检 |

**B. 娄塘工厂表，本地不存在（5条）**

| 悬空表名 | server_name | 业务 |
|---------|-------------|------|
| lt_struc_part_557h_* (2张) | 云服务器(LT/娄塘) | 557h结构件 |

> 这些映射指向云服务器上的表（`server_name='云服务器'`），本地 zt_server_data 库中没有。属于跨服务器数据同步未完成。

**C. 本地 copy1 表无映射（2张）**

| 表 | 行数 |
|----|------|
| zt_cyl_block_las_mark_copy1 | 584,639 |
| zt_cyl_head_evo_las_mark_copy1 | 51,858 |

> 按 DB_CONTEXT.md 说明，"copy1 是历史快照，分析时用主表"，但缺少映射会导致自动化工具无法识别这些快照表的存在。

### 4.6 结论

1. **3张核心表缺失映射**：合计107万条密封/打标数据无法通过 product_code/process_code 维度正确分类，所有按元数据驱动的分析（按产品/工艺筛选）必须硬编码这3张表名。

2. **24条悬空引用是预期内**：全部指向云服务器或娄塘工厂的外部表，说明 multi-server 架构下的数据同步管线未在本库落地。不是错误，但反映了数据架构现状。

3. **db_table_mapping 不是可信的"全量表清单"**：实际35张表，映射覆盖28张（54%命中率）。分析 Agent 必须始终从 `information_schema.TABLES` 获取真实表名，而非依赖 mapping 表。
