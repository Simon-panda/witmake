## 🧬 四层进化架构

### L1: 反馈日志 — 每一天都在学

```
workspace/hermes-enterprise/feedback/
├── daily_briefing_feedback.jsonl   # 每条记录含 quality/improvements
├── oee_weekly_feedback.jsonl
├── patrol_feedback.jsonl
└── radar_feedback.jsonl
```

**反馈 JSONL 格式**：
```json
{"task":"早间简报","timestamp":"2026-05-07T08:00:00","quality":0.8,
 "completeness":0.6,"actionability":0.7,"latency_ms":3200,
 "issues":["3号线数据缺失"],"improvements":["需要MES API"],
 "data_available":false}
```

### L2: 知识蒸馏 — 把对话变成资产

```
workspace/hermes-enterprise/knowledge/
├── equipment-events.jsonl    # 设备故障/维修事件
├── quality-events.jsonl      # 不良品/客户投诉
├── cost-events.jsonl         # 刀具/能耗异常
├── industry-intel.jsonl      # 技术动态/价格变动
└── decisions.jsonl           # Simon 的管理决策
```

这些数据最终同步到 gbrain 知识图谱，形成结构化查询能力。

### L3: DSPy 优化 — 每周自动进步

进化引擎每周日分析一周反馈，对每条任务 skill 执行：

```
反馈分析 → 识别改进点 → DSPy MIPROv2 优化 → 
生成 Candidate → Simon 审核 → 部署
```

**优化维度**：
| 任务 | 优化目标 |
|------|----------|
| 早间简报 | 异常识别准确率 ↑ 数据覆盖率 ↑ |
| OEE周报 | 瓶颈归因准确率 ↑ 预测精度 ↑ |
| 设备巡检 | 误报率 ↓ 漏报率 ↓ |
| 行业雷达 | 信息相关性 ↑ 噪音过滤 ↑ |

### L4: Skill 自动更新

```
workspace/hermes-enterprise/skills/
├── morning-briefing/SKILL.md      v1.0 → v1.1 → v2.0
├── oee-weekly/SKILL.md
├── equipment-patrol/SKILL.md
└── industry-radar/SKILL.md
```

每次进化生成 `SKILL.md.candidate` → Simon 审核 → 正式部署。

## 🔄 完整进化周期

```
周一 08:00  早间简报 运行 ──→ 写入反馈
周一 22:00  反馈收集器 ──→ 聚合昨日反馈
周二 08:00  早间简报 运行 ──→ 写入反馈（+1天数据）
...全周循环...
周日 02:00  进化引擎 ──→ 分析全周反馈
            ├─ 识别改进点
            ├─ 生成优化方案
            ├─ 产出 Candidate skills
            └─ 生成进化报告 → Simon 审核
周日 08:00  OEE周报 ──→ 可能已经用了优化后的 prompt
```

## 🛡️ 安全护栏

| 护栏 | 说明 |
|------|------|
| 🔒 优化不自动部署 | Candidate 等 Simon 确认 |

| ⚠️ 退化告警 | 新版本质量下降 → 自动暂停 |
