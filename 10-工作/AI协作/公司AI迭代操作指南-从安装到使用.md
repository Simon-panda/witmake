# 公司 AI 迭代操作指南 — 从安装到使用

> **面向对象**：智机工业全体工程师、管理人员  
> **核心原则**：AI 嵌入现有工艺流程，解决真金白银的损失点，不追求「大模型万能」

---

## 一、我们的基础与优势

| 已有资源 | 制造业绩效痛点 | 我们的差异化优势 |
|----------|---------------|-----------------|
| 200 台加工中心 + 高自动化产线 | 老师傅退休 = 工艺诀窍流失 | 可用 AI 固化工艺 Know-how |
| 自动化系统集成团队（机械/电气/AI视觉/IT/AI大模型/现场调试） | 产线改造周期长、试错成本高 | 自研自动化 + AI 可快速闭环 |
| IATF 16949 体系认证 | 质量追溯耗时长、客户审核压力大 | 全链路数据贯通，追溯留痕 |

```
┌─────────────────────────────────────────────┐
│  交互层：Hermes Agent（自然语言对话 + 任务调度）   │
├─────────────────────────────────────────────┤
│  知识层：Obsidian（工艺案例/故障记录/8D报告）      │

├─────────────────────────────────────────────┤

└─────────────────────────────────────────────┘
```

> **关键决策**：核心工艺数据不上云，本地部署模型；非敏感报表可上云。

## 四、核心工作流

### 工作流 1：每日信息捕获

**场景**：现场异常、会议纪要、技术灵感快速入库

**操作方式**：
1. 直接对 Hermes 说：「把以下内容存到 Obsidian 每日日记」
2. 发送现场照片 → Hermes 自动 OCR 识别 → 结构化存入 `00-Inbox/YYYY-MM-DD.md`
3. 发送文件（Excel/PDF/Word）→ Hermes 自动转 Markdown → 归档

**示例**：
```
"今天 3 号加工中心主轴负载异常，峰值到 85%，怀疑刀具磨损，
 已换刀，观察中。记录到 Obsidian。"
```

**效果**：零摩擦录入，不打断工作流。

### 工作流 2：工艺知识沉淀

**场景**：老师傅经验数字化，异常案例结构化

**标准模板**（工程师填写）：

```markdown
---
工艺: 缸体镗孔
设备: Mazak HCN-5000 (FANUC 31i)
材料: HT250 灰铸铁
缺陷类型: 孔径超差 +0.02mm
根本原因: 刀具悬伸过长(120mm)，切削力导致让刀
解决措施: 改用抗震刀柄，悬伸缩短至 85mm
验证结果: CpK 从 0.82 提升至 1.33
关联案例: [[案例-缸体加工振刀]]
---
```

**AI 辅助**：
- 工程师输入当前工况，AI 检索历史相似案例
- 新员工培训：AI 自动生成「缸体常见缺陷 20 问」

**量化目标**：新员工独立上岗从 18 月 → 6 月；同类缺陷复发率 ↓ 40%

### 工作流 3：设备预测性维护

**问题**：200 台加工中心突发故障，单条产线停工一天损失巨大

**方案**：
1. **采集层**：自动化团队在关键设备加装振动/温度/电流传感器（2000-5000 元/台）
2. **边缘推理**：产线工控机部署轻量模型，实时判断「正常/预警/危险」
3. **知识联动**：预警自动生成维修工单，关联历史记录、备件库存

**量化目标**：非计划停机 ↓ 30%；备件周转率 ↑ 20%

### 工作流 4：质量追溯（IATF 16949）

**问题**：客户投诉 → 追溯需翻纸质记录 + Excel + MES，耗时 2-3 天

**AI 追溯流程**：
```
输入批次号 → AI 自动串联：
  原材料批次 → 熔炼炉号 → 加工参数 → 刀具编号 → 三坐标数据
  → 高亮异常节点 → 生成 8D 报告初稿
```

**量化目标**：追溯时间 3 天 → 10 分钟；满足 IATF 16949 审计留痕要求

### 工作流 5：智能排产辅助

**场景**：紧急插单，人工重排 2 小时

**Hermes 交互**：
```
"客户 A 的订单要提前 3 天交付，哪些订单可以后挪？"
→ AI 返回 3 套方案 + 影响面分析
```

**量化目标**：排产调整 2h → 5min；计划达成率 75% → 90%

| 场景 | 怎么说 |

| 存笔记 | 「把这记录下来，存到 Obsidian」 |
| 查资料 | 「搜索知识库里关于缸体镗孔工艺的案例」 |
| 生产简报 | 「今天设备 OEE 汇总」 |
| 质量分析 | 「最近一周不良品原因分析」 |
| 文件归档 | 「把这个 Excel 转成 Markdown 存到工作文件夹」 |
| Kanban 任务 | 通过 `/kanban` 命令创建和跟踪任务 |

### 5.2 Obsidian 日常维护

| 频率 | 任务 | 负责人 |
|------|------|--------|
| 每日 | 清空 `00-Inbox`，归类到对应文件夹 | 各工程师 |
| 每周 | 审查标签一致性，补全 Frontmatter | 知识库管理员（指定 1 人） |
| 每月 | 合并重复笔记，检查知识图谱孤岛 | 知识库管理员 + AI 辅助 |

### 5.3 数据安全红线

| 规则 | 说明 |
|------|------|
| 🔴 工艺参数不上云 | 铸造配方、热处理曲线等核心 Know-how 仅本地模型处理 |
| 🔴 客户图纸隔离 | 不同客户 3D 模型/DWG 物理隔离，AI 检索需权限控制 |
| 🔴 审计留痕 | AI 建议必须记录推理依据，满足 IATF 16949 追溯 |
| 🟡 约束校验 | AI 推荐的工艺参数须经规则引擎校验，不能直通 PLC |
| 🟡 人机确认 | 关键参数调整需工程师在 HMI 确认后方可执行 |

## 八、常见问题

**Q：老师傅不愿意用怎么办？**
A：「AI 是助手而非替代」——先让 AI 帮老师傅写日报、填质量记录（没人喜欢填表），再逐步介入工艺优化。将经验案例命名为「张师傅-缸体气孔处理法」，增强归属感。

**Q：AI 给的建议错了谁负责？**
A：三重防线：① 规则引擎约束校验（如「浇注温度不超过 750℃」）→ ② 工程师 HMI 确认 → ③ A/B 小批量验证后推广。AI 只建议，人做决策。

**Q：MES/ERP 要不要换？**
A：不换。AI 作为「智能层」叠加在现有系统之上，通过 API 读写数据，保护已有投资。

**Q：数据安全怎么做？**
A：三层策略——① 核心工艺本地部署，不上云；② 客户数据物理隔离；③ 所有 AI 操作留痕，满足 IATF 16949。
