# 第4组: 文件与磁盘管理

> 命令行下的文件浏览与磁盘分析工具，让终端操作更直观、更高效。

---

### 31. lsd (LSD - LS Deluxe)

**前世今生**

`lsd` 由 Pierre Rolland（@Peltoche）于 2018 年在 GitHub 上首次发布，使用 Rust 语言编写。它的诞生源于一个简单的痛点：传统的 `ls` 命令虽然功能完备，但输出视觉上不够直观。`lsd` 的设计目标是在保持 `ls` 全部功能的同时，增加图标（Nerd Font 图标）、彩色输出和更人性化的文件类型标识。项目最早称为 `lsd`，意为"LSDeluxe"或"LS Deluxe"。作为一个用 Rust 重写的经典工具，它充分利用了 Rust 的内存安全和性能优势。随着 Nerd Font 图标字体在终端美化社区的流行，`lsd` 迅速成为现代终端配置的标准组件之一，在 GitHub 上获得超过 12k stars。它的成功也带动了更多 Rust 重写传统 Unix 工具的潮流。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install lsd

# Linux (Debian/Ubuntu)
sudo apt install lsd

# Arch Linux
sudo pacman -S lsd

# Windows (Scoop/Chocolatey)
scoop install lsd
# 或
cargo install lsd
```

**基础用法：**

```bash
# 基本列表（带图标，需 Nerd Font 字体支持）
lsd

# 长格式显示，包含权限、大小、日期
lsd -l

# 显示隐藏文件
lsd -a

# 树状显示目录结构
lsd --tree

# 按修改时间排序，最新的在前
lsd -lt

# 仅显示目录
lsd -d */
```

**实战案例一：快速审计项目文件结构**

当你接手一个新项目，需要快速了解文件布局和权限：

```bash
# 递归显示所有文件，带人类可读的大小
lsd -laR --header

# 仅看目录树的前两级深度
lsd --tree --depth 2

# 按文件大小排序，快速定位大文件
lsd -lS --total-size
```

**实战案例二：配置 alias 提升日常效率**

在 `~/.bashrc` 或 `~/.zshrc` 中添加：

```bash
alias ls='lsd'
alias ll='lsd -l'
alias la='lsd -a'
alias lt='lsd --tree'
alias lla='lsd -la'
```

**进阶技巧：**

- 搭配 `--icon-theme` 参数可切换图标主题（`fancy` 或 `unicode`）
- `--date relative` 显示相对时间（如"2 小时前"），比绝对时间更直观
- 配置文件位于 `~/.config/lsd/config.yaml`，可自定义颜色和图标

**避坑指南：**

- 图标显示需要安装 Nerd Font 字体（推荐 `FiraCode Nerd Font` 或 `JetBrainsMono Nerd Font`）
- 在 SSH 到无 Nerd Font 的远程服务器时，图标会显示为乱码方块，此时可用 `lsd --icon never` 关闭图标
- `--tree` 模式在大型目录（如 `node_modules`）下会很慢，加上 `-I node_modules` 忽略特定目录

### 32. eza (exa 的后继者)

**前世今生**

`exa` 由 Benjamin Sago（@ogham）于 2014 年创建，是最早用 Rust 重写 `ls` 的现代化替代品之一。它在终端工具美化运动中扮演了开荒者的角色，引入了颜色、Git 状态集成和树状视图等特性。然而，随着 Benjamin 个人兴趣转移，`exa` 自 2022 年起停止维护。社区不甘心看到这个优秀的工具荒废，于是由 Christina Sørensen（@cafkafk）等人 fork 了 `exa` 代码库，于 2023 年创建了 `eza`。`eza` 不仅延续了 `exa` 的全部功能，还增加了 SELinux 上下文显示、超链接支持、更丰富的 Git 忽略规则等新特性。目前 `eza` 已成为 `exa` 的官方继任者，拥有活跃的社区和持续的更新。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install eza

# Linux (Debian/Ubuntu)
sudo apt install eza

# Arch Linux
sudo pacman -S eza

# Windows (Scoop)
scoop install eza

# 通过 cargo
cargo install eza
```

**基础用法：**

```bash
# 基本列表（自动着色）
eza

# 长格式 + 人类可读大小 + Git 状态
eza -l --git

# 树状显示（默认递归）
eza --tree

# 显示隐藏文件和 Git 忽略状态
eza -a --git-ignore

# 按修改时间排序
eza -l --sort=modified

# 只显示目录
eza -D

# 递归显示所有文件
eza -laR
```

**实战案例一：Git 仓库文件状态一览**

```bash
# 显示 Git 仓库中所有文件的状态（新增、修改、未跟踪等）
eza -la --git --git-repos

# 忽略 .gitignore 中的文件，只看实际跟踪的文件
eza --tree --git-ignore -I '.git'

# 按 Git 状态分组显示
eza -l --git --group-directories-first
```

**实战案例二：配合 fzf 实现交互式文件浏览**

```bash
# 交互式选择文件并用 vim 打开
vim $(eza -a --only-files | fzf)

# 交互式切换目录
cd $(eza -a --only-dirs | fzf)
```

**进阶技巧：**

- `--color-scale` 根据文件大小用渐变色显示，大文件更醒目
- `--icons=always` 强制显示 Nerd Font 图标
- `--hyperlink` 在支持的终端（如 iTerm2、Windows Terminal）中生成可点击链接
- `--no-quotes` 去掉文件名两边的引号，输出更简洁
- 在 `~/.zshrc` 中设置 `alias ls='eza'` 可无缝替换传统 `ls`

**避坑指南：**

- `eza` 不支持 `-h` 帮助参数，正确用法是 `eza --help`
- `--tree` 默认不限制深度，在深层目录中会输出极多内容，建议加 `-L 2` 限制层级
- Git 集成需要当前目录在 Git 仓库内，否则 `--git` 参数无效且不报错

### 33. dust (du + rust = dust)

**前世今生**

`dust` 由 Andy Boot（@bootandy）于 2018 年创建，用 Rust 语言编写。它的名字巧妙地融合了 `du`（disk usage，Unix 磁盘使用量查询命令）和 Rust。传统 `du` 命令输出冗长、缺乏图形化展示，`ncdu` 虽然改善了交互体验但仍基于终端 UI。`dust` 的定位更轻量：给出一个目录，立即用直观的树状缩进图和百分比展示每个子目录的磁盘占用，无需进入交互模式。它在处理大型目录时比 `du` 快得多，因为利用 Rust 的并行遍历能力。目前 `dust` 在 GitHub 上获得超过 8k stars，被许多开发者纳入日常工具箱替代 `du -sh * | sort -h` 的繁琐组合。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install dust

# Linux (通过 snap)
sudo snap install dust

# Arch Linux
sudo pacman -S dust

# Windows (Scoop)
scoop install dust

# 通过 cargo
cargo install du-dust
```

**基础用法：**

```bash
# 分析当前目录
dust

# 指定目录
dust ~/Downloads

# 限制显示深度为 2 层
dust -d 2

# 只显示前 10 个最大的条目
dust -n 10

# 不显示百分比条
dust -b

# 反向排序（小的在前）
dust -r

# 显示完整路径
dust -p
```

**实战案例一：清理磁盘空间**

当你收到"磁盘空间不足"警告时，快速定位占用大户：

```bash
# 从用户主目录开始，深度 2，只看最大的 15 个
dust -d 2 -n 15 ~/

# 发现 ~/Library 很大，深入分析
dust -d 3 ~/Library

# 找出一周内未修改的大文件所在目录
dust -d 2 -X 1w ~/Downloads
```

**实战案例二：对比前后磁盘变化**

```bash
# 安装软件前记录
dust -d 2 -n 20 / > before.txt

# 安装软件后
dust -d 2 -n 20 / > after.txt

# 对比差异
diff before.txt after.txt
```

**进阶技巧：**

- `-X` 参数按时间过滤，如 `-X 1M` 只看近一个月修改的文件
- `-e` 按正则排除目录，如 `dust -e 'node_modules|\.git|target'` 
- `-f` 统计的是文件系统层面的实际占用（考虑块大小），比文件字节数更准确
- 配合 `watch` 命令可实时监控目录增长：`watch -n 2 dust -d 2`

**避坑指南：**

- `dust` 需要递归读取所有文件的元数据，对 NAS 或网络挂载目录会很慢
- 结果中百分比是相对于父目录的，不是根目录的
- 输出中，子目录可能加起来不如父目录大，这是因为父目录中还有未显示的直接文件

### 34. duf (Disk Usage/Free)

**前世今生**

`duf` 由 Christian Muehlhaeuser（@muesli）于 2020 年创建，Go 语言编写。在 `duf` 出现之前，查看磁盘挂载信息通常使用 `df -h`，输出是纯文本表格，不够美观，且对特殊文件系统（如 snap、Docker overlay）的过滤不够智能。`duf` 的定位是"更友好的 `df`"——它提供彩色终端表格、自动隐藏不重要的文件系统（如伪文件系统、snap 挂载）、按设备类型分组显示等功能。项目灵感部分来源于 `dust` 的成功，试图在磁盘容量查看这个细分领域做同样的事情。它在 2020 年底爆红 Hacker News，24 小时内获得数千 GitHub stars。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install duf

# Linux (Debian/Ubuntu)
sudo apt install duf

# Arch Linux
sudo pacman -S duf

# Windows (Scoop)
scoop install duf

# 通过 Go
go install github.com/muesli/duf@latest
```

**基础用法：**

```bash
# 列出所有挂载的设备
duf

# 只显示本地设备（不显示网络挂载）
duf --only local

# 只显示特定文件系统类型
duf --only-fs ext4,apfs

# 以 JSON 格式输出（方便脚本处理）
duf --json

# 隐藏特殊文件系统（snap、tmpfs 等）
duf --hide-special
```

**实战案例一：服务器磁盘健康检查**

```bash
# 查看所有磁盘使用情况，按使用率排序
duf --sort usage

# 只看本地物理磁盘（排除伪文件系统和网络存储）
duf --only local --hide-special

# 导出为 JSON 用于监控脚本
duf --json | jq '.[] | {device: .device, used: .used, usage: .usage}'
```

**实战案例二：开发容器内排查挂载问题**

```bash
# 在 Docker 容器中查看挂载卷
duf --only-fs overlay,ext4,xfs

# 查看 inode 使用情况（小文件过多会耗尽 inode）
duf --inodes

# 按挂载点过滤
duf / /home /var
```

**进阶技巧：**

- `--width` 参数可限制输出宽度，避免在窄终端中换行
- 结合 `watch` 命令监控磁盘变化：`watch -n 5 duf`
- 颜色编码：绿色（<50%）、黄色（50-80%）、红色（>80%），一眼识别风险
- `--theme light` 可在浅色终端背景上使用

**避坑指南：**

- `duf` 显示的是文件系统级别的使用量，与 `du`（目录级别）的结果可能不同——文件被删除但进程仍持有句柄时，空间在 `df`/`duf` 中仍显示占用
- 在 macOS 上，`duf` 会显示很多 APFS 快照卷，使用 `--hide-special` 过滤

### 35. bottom (btm)

**前世今生**

`bottom` 由 Clement Tsang（@ClementTsang）于 2020 年创建，Rust 语言编写。在 `bottom` 出现之前，系统监控工具领域由 `htop`、`glances`、`gtop` 等把持，这些工具各有局限：`htop` 不支持 GPU 监控、`gtop` 已停止维护、`glances` 依赖 Python 启动较慢。Clement 想要一个跨平台（Linux/macOS/Windows）、支持 GPU、带有现代化 TUI（终端用户界面）、启动快且可定制的监控工具。`bottom` 由此诞生——名字戏仿了"bottom"与"top"的对立。它使用 `tui-rs`（后迁移到 `ratatui`）构建界面，支持 CPU、内存、磁盘、网络、GPU、进程树等全面监控，还内置了基本的磁盘 I/O 和温度传感器读数。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install bottom

# Linux (Debian/Ubuntu)
sudo snap install bottom

# Arch Linux
sudo pacman -S bottom

# Windows (Scoop)
scoop install bottom

# 通过 cargo
cargo install bottom
```

**基础用法：**

```bash
# 启动交互式监控界面
btm

# 基本模式（类似 htop 的简洁布局）
btm -b

# 不显示内存和网络图表（更轻量）
btm --disable_memory --disable_network

# 指定刷新间隔（毫秒）
btm -r 500

# 温度单位用华氏度
btm --fahrenheit
```

**实战案例一：服务器性能基线采集**

```bash
# 以最小模式运行，导出 CPU/内存数据到 CSV（非交互模式需用监控导出）
btm -b

# 使用内置的进程搜索和排序：
# 在 btm 界面中：
#   - dd: 杀死选中进程
#   - /: 搜索进程
#   - s: 切换排序方式（CPU%/内存/进程名）
#   - e: 展开/折叠进程树
#   - h: 隐藏/显示帮助
```

**实战案例二：游戏/渲染时的 GPU 监控**

```bash
# 显示 CPU、内存和 GPU 信息
btm --enable_gpu

# 自定义布局：左侧 CPU + 内存，右侧 GPU + 进程
# 通过配置文件 ~/.config/bottom/bottom.toml 自定义：
# [row]
# [[row.child]]
# type="cpu"
# [[row.child]]
# type="mem"
```

**进阶技巧：**

- 配置文件 `bottom.toml` 支持高度自定义布局和颜色主题
- `--config` 参数指向自定义配置文件路径
- 在界面中按 `?` 显示快捷键帮助（注意不是 `h`）
- 进程树模式（默认）能清晰展示父子进程关系
- 支持电池监控（笔记本）：`btm --enable_battery`

**避坑指南：**

- GPU 监控需要 NVIDIA 驱动（Linux）或 Metal（macOS），Intel 集显不支持
- 温度传感器在虚拟机中通常不可用
- Windows 上某些指标（如磁盘 I/O per-process）可能缺失
- 以 snap 安装的版本可能因沙箱限制无法访问某些系统信息

### 36. broot

**前世今生**

`broot` 由 Denys Séguret（@Canop）于 2019 年创建，Rust 语言编写。Denys 是法国开发者，也是 `termimad`（终端 Markdown 渲染库）和 `lfs`（Git LFS 查看器）的作者。`broot` 的核心理念是"更好的目录树"——它不仅显示目录树，还允许你直接在树中进行模糊搜索和导航。它最大的创新在于"launch"机制：在 `broot` 中找到目标目录后，按回车不是进入该目录，而是执行预设的 shell 命令（如 `cd`、`vim`、`xdg-open`）。这个设计解决了传统文件管理器中"找到文件后还要手动打开"的痛点。`broot` 还内置了文件预览、大小分析和 Git 状态显示，被许多开发者用作 `tree` + `cd` + `fzf` 的替代。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install broot

# Linux (Debian/Ubuntu)
# 从 GitHub Releases 下载预编译二进制
# 或通过 cargo
cargo install broot

# Windows (Scoop)
scoop install broot

# 安装后初始化（添加 br shell 函数）
broot --install
```

**基础用法：**

```bash
# 启动 broot
br

# 查看指定目录
br ~/projects

# 显示隐藏文件和 Git 忽略文件
br -hgi

# 只显示文件（不显示目录）
br -f

# 按修改日期排序
br -s date

# 显示文件大小
br -s size

# 设置最大深度
br -d 3
```

**实战案例一：大型项目结构分析**

```bash
# 进入项目目录，按大小排序，快速找大文件
br -s size ~/projects/my-app

# 在 broot 交互界面中：
#   :gi         — 切换 Git 忽略文件的显示
#   :h          — 切换隐藏文件
#   <enter>     — 用默认程序（如 cd）进入目录
#   :e          — 用编辑器打开选中文件
#   /pattern    — 模糊搜索
#   :q          — 退出
#   :s size     — 按大小排序
#   :pt         — 显示文件总览信息
```

**实战案例二：配置 broot 实现快速跳转**

```bash
# 编辑配置文件 ~/.config/broot/conf.toml
# 添加快捷键：
# [[verbs]]
# invocation = "e"
# execution = "$EDITOR {file}"
# leave_broot = false

# [[verbs]]
# invocation = "ct"
# execution = "cd {directory}"
# leave_broot = true
```

**进阶技巧：**

- 竖排面板：在交互界面中按 `ctrl+→` 打开第二个面板，实现双面板文件管理
- `:fs` 命令检查磁盘空间
- `--cmd` 参数可在启动时自动执行命令：`br --cmd :gi`
- 配置文件中的 `verbs` 系统非常灵活，可以定义任意自定义操作
- 文件预览按 `:preview_binary` 可切换二进制文件预览

**避坑指南：**

- 首次使用必须执行 `broot --install` 安装 shell 集成函数，否则 `br` 无法实现 `cd` 跳转
- 大型仓库（如 Linux 内核源码树）首次扫描可能较慢，后续由于缓存会很快
- `.gitignore` 中的目录默认不显示，用 `:gi` 切换
- 某些终端模拟器对按键映射支持不完整，建议在 iTerm2/Windows Terminal/Alacritty 中使用

### 37. nnn (n³ - The Missing Terminal File Manager)

**前世今生**

`nnn` 由 Arun Prakash Jana（@jarun）于 2017 年创建，C 语言编写。Arun 是一位印度开发者，此前还创建了 `googler`（命令行 Google 搜索工具）。`nnn` 的设计哲学是"极小、极快、极其可扩展"——二进制文件不到 100KB，内存占用极低，即使在树莓派上也能流畅运行。它填补了 `ranger`（依赖 Python，较慢）和 `mc`（Midnight Commander，界面过时）之间的空白。`nnn` 使用 4 个核心插件（`preview-tui`、`fzopen`、`dragdrop`、`nmount`）提供预览、模糊打开、拖放和挂载管理功能，并通过大量环境变量实现行为定制。它已成为嵌入式系统和低配置服务器上的首选文件管理器。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install nnn

# Linux (Debian/Ubuntu)
sudo apt install nnn

# Arch Linux
sudo pacman -S nnn

# 安装插件（需要额外操作）
# 下载插件仓库到 ~/.config/nnn/plugins/
curl -Ls https://raw.githubusercontent.com/jarun/nnn/master/plugins/getplugs | sh
```

**基础使用：**

```bash
# 启动 nnn
nnn

# 键盘快捷键（在 nnn 界面中）：
#   q           — 退出（按两次）
#   ↑↓←→/hjkl  — 导航
#   Enter       — 打开文件/进入目录
#   /           — 过滤/搜索
#   d           — 切换详细模式
#   .           — 切换隐藏文件
#   t           — 切换排序方式
#   e           — 编辑文件（$EDITOR）
#   p           — 打开文件（$PAGER 或默认程序）
#   Space       — 选中文件
#   Ctrl+Space  — 全选
#   n           — 创建新文件/目录
```

**实战案例一：远程服务器的文件管理**


### 38. ranger

**前世今生**

`ranger` 由 Roman Zimbelmann（@hut）于 2009 年创建，Python 语言编写。Roman 是德国开发者，当时还在大学读书。他受到 `vim` 的键位哲学和 `mc`（Midnight Commander）双面板布局的启发，想创造一个"vim 风格的文件管理器"。`ranger` 使用三列布局：左列是父目录、中间是当前目录内容、右列是预览窗口，这种设计灵感来自 `miller columns`（macOS Finder 的分栏模式）。`ranger` 的一个核心特性是集成了 `rifle`（文件关联器），可以根据文件类型自动选择合适的程序打开。由于用 Python 编写，`ranger` 的扩展性极强，社区贡献了大量插件和配置方案。尽管较新的工具（如 `nnn`、`lf`）在性能上更优，`ranger` 至今仍是 Linux 终端文件管理器的事实标准之一。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install ranger

# Linux (Debian/Ubuntu)
sudo apt install ranger

# Arch Linux
sudo pacman -S ranger

# Windows (WSL 或 pip)
pip install ranger-fm
```

**基础使用：**

```bash
# 启动 ranger
ranger

# 指定起始目录
ranger ~/Documents

# 键盘快捷键：
#   hjkl       — vim 风格导航
#   gg / G     — 跳到列表首/尾
#   Space      — 选中/取消选中
#   v          — 反选
#   dd         — 剪切（标记为剪切）
#   yy         — 复制
#   pp         — 粘贴
#   dD         — 删除
#   zh / Ctrl+h — 显示/隐藏隐藏文件
#   /          — 搜索
#   :          — 进入命令模式
```

**实战案例一：项目文件批量重命名**

```bash
# 在 ranger 中：
# 1. 用 Space 选中多个文件
# 2. 输入 :bulkrename
# 3. 在 vim 中批量编辑文件名
# 4. 保存退出，确认修改

# 用命令模式重命名单个文件
# :rename 新文件名
```

**进阶技巧：**

- `:touch 文件名` 创建空文件
- `:mkdir 目录名` 创建目录
- `:shell 命令` 在当前目录执行 shell 命令
- `:travel` 回到上一个浏览的目录

### 39. zoxide

**前世今生**

`zoxide` 由 Ajeet D'Souza（@ajeetdsouza）于 2020 年创建，Rust 语言编写。Ajeet 是印度开发者，当时还在大学。`zoxide` 的名称来自"Z + oxide"（氧化物，呼应 Rust 语言），同时也是对 `z`（一个流行的目录跳转脚本）的致敬。传统的 `cd` 命令需要你知道完整路径，而 `z` 和 `autojump` 虽然支持模糊跳转，但依赖 shell 函数实现，跨 shell 体验不一致。`zoxide` 的定位是"更智能的 `cd`"——使用类似 `frecency`（频率+新近度）的算法记录你访问过的目录，允许用少量字符快速跳转到常用目录。它提供了统一的 CLI 工具 `zoxide`，然后通过 shell 集成暴露为 `z` 命令。目前 `zoxide` 已成为目录跳转领域最流行的工具，GitHub stars 超过 20k。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install zoxide

# Linux (Debian/Ubuntu)
sudo apt install zoxide

# Arch Linux
sudo pacman -S zoxide

# Windows (Scoop)
scoop install zoxide

# 通过 cargo
cargo install zoxide

# 安装后初始化 shell 集成（必须执行）
# 在 ~/.bashrc 或 ~/.zshrc 中添加：
eval "$(zoxide init bash)"   # bash 用户
eval "$(zoxide init zsh)"    # zsh 用户
eval "$(zoxide init fish)"   # fish 用户
```

**基础用法：**

```bash
# 跳转到最匹配的目录
z projects

# 跳转到具体目录（首次访问，自动记录）
z ~/Documents/work/reports

# 查询匹配的目录列表
zoxide query proj

# 交互式选择（需要 fzf）
zi

# 查看目录排名
zoxide query -l

# 删除某个目录的记录
zoxide remove ~/old-project
```

**实战案例一：多项目间的快速切换**

```bash
# 在多个项目间快速跳转
z my-app      # → ~/projects/my-app
z backend     # → ~/work/backend-service
z dotfiles    # → ~/.dotfiles
z desk        # → ~/Desktop

# 部分匹配：即使只记得路径片段
z my-app/src  # 跳转到 my-app 下的 src 目录
z api/test    # 跳转到 api 项目下的 test 目录

# 配合 fzf 交互选择
zi            # 弹出 fzf 界面，模糊搜索并选择
```

**实战案例二：配置 aliases 和工作流**

```bash
# 在 shell 配置中覆盖 cd 行为
alias cd='z'

# 定义项目快捷跳转
alias zp='z ~/projects'
alias zw='z ~/work'
alias zd='z ~/Downloads'

# 多终端同步：所有终端共享跳转数据库
# （默认就是全局数据库，无需配置）
```

**进阶技巧：**

- `z -` 跳转到上一个目录（类似 `cd -`）
- `z foo bar` 多个关键词匹配（AND 逻辑）
- 配置 `$_ZO_EXCLUDE_DIRS` 排除不需要记录的目录
- `zoxide query -i` 交互式查询（与 `zi` 功能相同）
- 数据库默认位于 `~/.local/share/zoxide/db.zo`，可备份和迁移

**避坑指南：**

- 安装后**必须**初始化 shell 集成，否则 `z` 命令不可用
- 新访问的目录需要至少被 `cd` 进入一次后才会被记录
- 在 fish shell 中初始化语法不同：`zoxide init fish | source`
- 多个关键词会做 AND 匹配，不是 OR
- 如果跳转到错误目录，用 `zoxide remove <目录>` 清除误记录

### 40. fdupes

**前世今生**

`fdupes` 由 Adrian Lopez 于 1999 年创建，C 语言编写，是 Linux/Unix 生态中最早的文件去重工具之一。Adrian 最早是为了清理自己的硬盘空间而开发这个工具。`fdupes` 采用智能的两阶段对比策略：首先比较文件大小，大小相同的再计算 MD5 哈希，哈希相同的再逐字节对比。这种策略在准确性和速度之间取得了很好的平衡。项目从最初发布到 SourceForge，到后来迁移至 GitHub（由社区维护），历经 20 余年仍在活跃。它曾在无数系统管理员和开发者的"磁盘空间告急"时刻救急。与后来的工具（如 `rmlint`、`dupeGuru`、`czkawka`）相比，`fdupes` 的优势在于简单直接和极低的依赖。

**使用方法与案例**

**安装方式：**

```bash
# macOS
brew install fdupes

# Linux (Debian/Ubuntu)
sudo apt install fdupes

# Arch Linux
sudo pacman -S fdupes

# Windows (WSL 中安装 Linux 版本)
# 或使用 scoop 安装 jdupes（fdupes 的增强 fork）
scoop install jdupes
```

**基础用法：**

```bash
# 在当前目录查找重复文件
fdupes .

# 递归查找
fdupes -r ~/Documents

# 显示每组重复文件后汇总
fdupes -r -m ~/Pictures

# 显示重复文件的总大小
fdupes -r -S ~/

# 不进入隐藏目录
fdupes -r -H .

# 比较时排除空文件
fdupes -r -n .
```

**实战案例一：照片库去重**

```bash
# 手机备份到电脑后，照片经常有重复
# 先找出所有重复照片，不删除
fdupes -r -m ~/Pictures/PhoneBackup

# 只保留每组中的第一个文件，将其余的用硬链接替换（节省空间）
fdupes -r -L ~/Pictures/PhoneBackup

# 交互式删除：每组重复文件逐一确认
fdupes -r -d ~/Pictures/PhoneBackup
# 交互模式中的选项：
#   1-9  — 保留对应编号的文件
#   r    — 重定向选择
#   s    — 跳过当前组
#   q    — 退出
```

**实战案例二：代码仓库的 node_modules 清理**

```bash
# 多个前端项目共享相同的依赖时，用硬链接节省空间
fdupes -r -H -n ~/projects

# 查看可以节省的空间（汇总模式）
fdupes -r -S ~/projects | tail -1

# 创建硬链接替代重复文件
fdupes -r -L ~/projects
```

**进阶技巧：**

- `-1` (或 `--sameline`) 将每组重复文件列在一行，方便用 `grep` 过滤
- `-q` 静默模式，只输出文件组，适合脚本处理
- `-o name` 按文件名排序输出结果
- 配合 `xargs` 批量删除：`fdupes -r -1 . | head -5 | xargs rm`（谨慎！）
- 排除特定目录：`fdupes -r . --exclude=node_modules --exclude=.git`

**避坑指南：**

- `-d` 删除模式会保留每组中的第一个文件，注意这个规则
- 硬链接（`-L`）只在同一文件系统内有效，跨分区无效
- 对大量文件运行时可能比较慢，因为需要逐字节对比
- `jdupes` 是 `fdupes` 的一个增强 fork，增加了 Btrfs 重删和更多优化
- 不要在生产服务器上直接使用 `-d` 删除模式，先用 `-m` 查看结果
