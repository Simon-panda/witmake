## 131. SQLite

**前世今生：** SQLite 由 D. Richard Hipp 于 2000 年创建。Hipp 当时在 General Dynamics 做军舰软件，需要一个小型嵌入式数据库，但当时的选项要么太重（MySQL/PostgreSQL）要么不够 ACID。他花了 10 天写了 SQLite 的原型。SQLite 的独特设计是"无服务器"——整个数据库是一个单文件，不依赖任何外部进程。它通过了航空级 DO-178B 认证测试，被用于空客 A350 的飞行软件。今天 SQLite 是全球部署最广的数据库——每个 Android/iOS 手机、每个 Chrome/Firefox 浏览器、每个 Python 安装包中都内置了它，部署量超过 1 万亿。

**使用方法与案例：**

安装：Python 自带 `import sqlite3`，CLI 工具 `apt install sqlite3`。

**案例1：命令行分析 CSV**
```bash
sqlite3 :memory: -csv -header << 'SQL'
.import production.csv data
SELECT line, AVG(oee) as avg_oee, COUNT(*) as records
FROM data
GROUP BY line
ORDER BY avg_oee DESC;
SQL
```
SQLite 可以直接导入 CSV 做聚合分析，零配置。

**案例2：嵌入式应用数据库**
```python
import sqlite3
conn = sqlite3.connect("mes_local.db")
conn.execute("""
  CREATE TABLE IF NOT EXISTS production (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    line TEXT, timestamp TEXT, output INTEGER,
    oee REAL, recorded_at TEXT DEFAULT (datetime('now'))
  )
""")
conn.execute("INSERT INTO production(line, timestamp, output, oee) VALUES (?,?,?,?)",
             ("A", "2026-07-05 08:00", 450, 88.5))
conn.commit()
```

**进阶技巧：**
- WAL 模式：`PRAGMA journal_mode=WAL;` 并发读不阻塞写
- JSON 函数：`SELECT json_extract(data, '$.oee') FROM events;`
- FTS5 全文搜索：中文分词搜索的轻量方案

## 132. DuckDB

**前世今生：** DuckDB 由荷兰 CWI（国家数学与计算机科学研究所）的 Hannes Mühleisen 和 Mark Raasveldt 于 2019 年创建，灵感来自 SQLite 的"嵌入式"理念，但目标是分析场景（OLAP）。传统上，SQLite 善于事务处理（OLTP），分析查询很慢；而 OLAP 数据库（ClickHouse、Redshift）需要独立部署。DuckDB 填补了中间地带——"分析用的 SQLite"，嵌入式、零配置、列式存储、向量化引擎。DuckDB 可以直读 CSV/Parquet/JSON/S3 文件，不依赖任何服务器。2023 年 DuckDB 1.0 发布，被 dbt Labs 和 MotherDuck 投资，成为数据工程领域最热的新星。

**使用方法与案例：**

安装：
```bash
pip install duckdb
brew install duckdb    # CLI
```

**案例1：直接查询 CSV 文件**
```sql
-- 不需要 import，直接查询
SELECT line, 
       AVG(oee) as avg_oee,
       PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY oee) as p50_oee
FROM 'production_2026*.csv'
WHERE date > '2026-06-01'
GROUP BY line
ORDER BY avg_oee DESC;
```

**案例2：Pandas 替代——百万行秒级聚合**
```python
import duckdb
result = duckdb.sql("""
    SELECT line, 
           date_trunc('week', timestamp) as week,
           AVG(output) as avg_output,
           SUM(defects) as total_defects,
           AVG(oee) as avg_oee
    FROM 'production.parquet'
    GROUP BY line, week
    ORDER BY week DESC, line
""").df()  # 直接输出 Pandas DataFrame
```

**案例3：跨源联邦查询**
```sql
-- 同时查询本地 CSV + S3 Parquet + PostgreSQL
SELECT 
    p.line,
    p.output,
    t.target_output,
    (p.output * 100.0 / t.target_output) as achieve_rate
FROM read_csv_auto('mes/daily.csv') p
JOIN read_parquet('s3://data/targets.parquet') t
  ON p.line = t.line AND p.date = t.date
```

**进阶技巧：**
- `duckdb -c "SELECT ..." --format markdown` 直接输出 Markdown 表格
- 列式压缩：100MB CSV → 15MB Parquet DuckDB 自动选择
- 扩展：httpfs 读 S3/HTTPS；spatial 做地理空间分析
- Python UDF：用 Python 函数做 SQL 中的自定义计算

## 133. PostgreSQL

**前世今生：** PostgreSQL 的前身是加州大学伯克利分校的 Michael Stonebraker 教授（2014 年图灵奖得主）于 1986 年启动的 POSTGRES 项目。Stonebraker 认为当时的数据库不够"可扩展"，于是设计了一种支持自定义类型、自定义函数、自定义索引的"对象-关系型"数据库。1996 年更名为 PostgreSQL（Post Ingres 的 SQL）。PostgreSQL 被称为"最先进的开源数据库"——ACID 严格、支持 JSON/全文搜索/地理空间/向量（pgvector）、扩展生态极强（PostGIS 是 GIS 行业标准，TimescaleDB 是时序扩展）。PG 的许可极宽松（类 MIT），商业友好。全球约 35% 的专业开发者使用 PG。

**使用方法与案例：**

安装：
```bash
brew install postgresql@16       # macOS
apt install postgresql           # Linux
# Windows: 官网下载安装包
```

**案例1：MES 生产数据建模**
```sql
CREATE TABLE production_records (
    id BIGSERIAL PRIMARY KEY,
    line VARCHAR(10) NOT NULL,
    recorded_at TIMESTAMPTZ DEFAULT NOW(),
    planned_output INTEGER,
    actual_output INTEGER,
    defects INTEGER,
    downtime_minutes INTEGER,
    oee NUMERIC(5,2) GENERATED ALWAYS AS (
        (actual_output::NUMERIC / NULLIF(planned_output, 0)) * 100
    ) STORED  -- 计算列自动维护
);

CREATE INDEX idx_production_line_time ON production_records(line, recorded_at DESC);

-- 物化视图做每日汇总
CREATE MATERIALIZED VIEW daily_summary AS
SELECT line, recorded_at::DATE as date,
       SUM(actual_output) as total_output,
       AVG(oee) as avg_oee
FROM production_records
GROUP BY line, recorded_at::DATE;
REFRESH MATERIALIZED VIEW CONCURRENTLY daily_summary;
```

**案例2：JSON 混合查询**
```sql
-- 灵活的 JSONB 字段 + 严格的关系约束
CREATE TABLE mes_events (
    id BIGSERIAL PRIMARY KEY,
    event_type VARCHAR(50),
    payload JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- JSON 查询
SELECT * FROM mes_events
WHERE payload->>'line' = 'A'
  AND (payload->>'oee')::numeric < 85;

-- JSON 索引
CREATE INDEX idx_payload_oee ON mes_events ((payload->>'oee'));
```

**案例3：向量搜索（pgvector）**
```sql
CREATE EXTENSION vector;
CREATE TABLE docs (id SERIAL, content TEXT, embedding VECTOR(1536));
-- 查找最相似的 5 条记录
SELECT content, 1 - (embedding <=> '[0.1, 0.2, ...]') AS similarity
FROM docs ORDER BY embedding <=> '[0.1, 0.2, ...]' LIMIT 5;
```

**进阶技巧：**
- `EXPLAIN ANALYZE` 分析慢查询执行计划
- Partitioning 按日期分区：`PARTITION BY RANGE (recorded_at)`
- `pg_stat_statements` 追踪最耗资源的查询
- Row Level Security 实现多租户数据隔离

## 134. Redis

**前世今生：** Redis 由意大利开发者 Salvatore Sanfilippo（antirez）于 2009 年创建。当时他在做一款实时 Web 分析产品 LLOOGG，发现 MySQL 撑不住高并发读写，于是写了 Redis（REmote DIctionary Server）。Redis 将数据完全放在内存中，实现了百微秒级延迟。它的数据结构远超 key-value：List（队列）、Set（去重）、Sorted Set（排行榜）、Hash（对象存储）、Stream（消息队列）、HyperLogLog（估算去重计数）。2015 年 Sanfilippo 将 Redis 移交给社区，2020 年 Redis Labs 改为商业许可（RSAL）。尽管有许可证争议，Redis 仍是全球最流行的缓存和实时数据库。

**使用方法与案例：**

安装：
```bash
brew install redis             # macOS
apt install redis-server       # Linux
docker run -d -p 6379:6379 redis:7
```

**案例1：API 缓存——减少数据库压力**

```python
import redis
r = redis.Redis(host='localhost', decode_responses=True)
import json, time

def get_daily_oee(line: str, date: str) -> float:
    cache_key = f"oee:{line}:{date}"
    cached = r.get(cache_key)
    if cached:
        return float(cached)
    
    oee = query_database(line, date)  # 昂贵的数据库查询
```

**案例2：排行榜（Sorted Set）**
```python
# 产量排行榜
r.zadd("production_leaderboard", {"line-A": 4500, "line-B": 4300, "line-C": 4800})
# Top 3
```

**案例3：分布式锁**

**进阶技巧：**
- Redis Streams 做轻量消息队列（替代 Kafka 的简单场景）

## 135. ClickHouse

**前世今生：** ClickHouse 由俄罗斯搜索巨头 Yandex 于 2009 年内部开发，2016 年开源。Yandex 的 Metrika（类似 Google Analytics）需要实时分析 PB 级的 Web 事件日志，传统数据库完全无法胜任。ClickHouse 的设计哲学是"极致的列式 OLAP"——数据按列存储（只读需要的列）、向量化执行（一次 CPU 指令处理一批数据）、数据实时摄入、SQL 方言极其强悍。它的查询性能通常比传统数据库快 100-1000 倍。ClickHouse 在日志分析、时序数据、用户行为分析领域是王者级产品。Cloudflare 用 ClickHouse 每秒处理 800 万事件。

**使用方法与案例：**

安装：
```bash
curl https://clickhouse.com/ | sh
clickhouse server
clickhouse client
```

**案例1：时序生产数据分析**
```sql
CREATE TABLE production_metrics (
    line LowCardinality(String),
    timestamp DateTime64(3),
    output UInt32,
    defects UInt16,
    oee Float32
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(timestamp)
ORDER BY (line, timestamp);
```
```sql
-- 千万行数据的聚合，秒级出结果
SELECT 
    line,
    toStartOfHour(timestamp) as hour,
    avg(oee) as avg_oee,
    quantile(0.95)(oee) as p95_oee,
    sum(output) as total_output
FROM production_metrics
WHERE timestamp >= now() - INTERVAL 30 DAY
GROUP BY line, hour
ORDER BY hour, line;
```

**案例2：物化视图实时聚合**
```sql
CREATE MATERIALIZED VIEW hourly_oee
ENGINE = SummingMergeTree()
ORDER BY (line, hour)
AS SELECT
    line,
    toStartOfHour(timestamp) as hour,
    avgState(oee) as oee_avg_state,
    sum(output) as total_output
FROM production_metrics
GROUP BY line, hour;
-- 查询时直接读物化视图，百万行 → 几千行
```

**进阶技巧：**
- `LIMIT 1 BY line` 每类取一条（类似窗口函数但更快）
- `arrayJoin` 将数组展开为行，处理嵌套日志
- 外部字典（External Dictionary）内存高速 JOIN 维表
- Kafka 引擎直接从 Kafka 消费数据写入 ClickHouse

## 136. MongoDB

**前世今生：** MongoDB 由 10gen（后改名 MongoDB Inc）的 Dwight Merriman、Eliot Horowitz 和 Kevin Ryan 于 2007 年创建。三人之前创办了 DoubleClick（被 Google 收购），在广告技术中深刻体会到关系型数据库处理半结构化数据的痛苦。MongoDB 的核心理念是"文档数据库"——JSON 格式存储，无需预设 schema，自动分片，水平扩展。2009 年开源后的 NoSQL 热潮中，MongoDB 成为 MEAN 栈（MongoDB-Express-Angular-Node）的 M。虽然早期因默认不安全的配置受批评，但 MongoDB 不断成熟：2017 年上市（IPO 估值 12 亿美元），2018 年 ACID 多文档事务，2020 年后时间序列、搜索、向量功能补齐。

**使用方法与案例：**

**案例：灵活的生产事件存储**
```javascript
db.production_events.insertOne({
    line: "A",
    timestamp: new Date("2026-07-05T08:00:00Z"),
    type: "shift_start",
    operator: "张三",
    metrics: {
        planned_output: 500,
        actual_output: 480,
        defects: 12
    },
    machine: { id: "M-001", rpm: 1500, temp: 42.5 },
    tags: ["production", "shift-a", "normal"]
});

// 查询灵活
db.production_events.find({
    "tags": "production",
    "machine.temp": { $gt: 40 },
    "metrics.actual_output": { $lt: 500 }
}).sort({ timestamp: -1 }).limit(10);
```

**进阶技巧：**
- MongoDB Atlas 云服务自动管理备份/扩容/安全
- Aggregation Pipeline 替代 MapReduce（性能更好）
- Change Streams 实时监听数据变化（类似 CDC）
- Schema Validation 在灵活和约束间平衡

## 137. Neo4j ### 138. etcd ### 139. MinIO ### 140. Apache Arrow

**Neo4j** 由 Emil Eifrem 于 2007 年在瑞典创建，是图数据库的事实标准。它用属性图模型（节点-关系-属性）和 Cypher 查询语言。特别适合社交网络、推荐引擎、供应链追溯等关系密集型场景。例如：追踪一批原材料 → 经过了哪些工序 → 组装到哪个产品 → 发给了哪个客户。

**etcd** 由 CoreOS 于 2013 年创建，名字来自 Linux `/etc` + distributed。etcd 用 Raft 共识协议实现强一致性的 key-value 存储。Kubernetes 用 etcd 存储所有集群状态（Pod、Service、ConfigMap）。3 或 5 节点集群，容忍少数节点故障。

**MinIO** 由 Anand Babu Periasamy 于 2014 年创建，是兼容 AWS S3 API 的开源对象存储。单二进制文件，高性能（Go 编写），支持纠删码。适合私有云中替代 S3，如存储 MES 历史数据、备份文件。`mc mb myminio/mes-data` 一行命令创建 bucket。

**Apache Arrow** 由 Wes McKinney（Pandas 创建者）于 2016 年发起，定义了列式内存格式标准。Arrow 让不同系统间零拷贝共享数据——Pandas/Spark/DuckDB/Parquet 之间不再需要序列化/反序列化。`pyarrow` 库是生态枢纽。

```python
import pyarrow as pa
table = pa.table({'line': ['A','B','A'], 'oee': [88.5, 92.1, 87.3]})
# 零拷贝转 Pandas
df = table.to_pandas()
# 存为 Parquet
pa.parquet.write_table(table, 'oee_2026.parquet')
```
