### 141. Apache Kafka

**前世今生**

Apache Kafka 由 LinkedIn 的三位工程师 Jay Kreps、Neha Narkhede 和 Jun Rao 于 2010 年创建，最初是为了解决 LinkedIn 内部海量用户活动流数据的传输问题。当时 LinkedIn 需要每天处理数万亿条消息，而传统的消息队列（如 ActiveMQ）无法满足这种规模的吞吐需求。Kafka 的设计灵感来源于数据库的预写日志（WAL），将消息以 append-only 的方式持久化到磁盘，实现了极高的写入吞吐量。2011 年开源后，Kafka 迅速成为分布式流处理的事实标准。2014 年 Jay Kreps 等人离开 LinkedIn 创立 Confluent 公司，围绕 Kafka 构建企业级生态。如今 Kafka 被 Uber、Netflix、Airbnb 等数千家企业使用，单集群可承载每日数万亿条消息，成为实时数据管道的核心基础设施。

**实战案例 1：Python 生产者/消费者**

```python
# producer.py — 订单生产者
from kafka import KafkaProducer
import json, time, random

producer = KafkaProducer(
    bootstrap_servers='localhost:9092',
    value_serializer=lambda v: json.dumps(v).encode('utf-8'),
    acks='all',              # 等待所有副本确认
    compression_type='gzip',  # 启用压缩
    retries=3                 # 失败重试
)

for i in range(1000):
    order = {'order_id': i, 'amount': round(random.uniform(10, 500), 2)}
    future = producer.send('orders', value=order)
    metadata = future.get(timeout=10)  # 同步等待确认
    print(f"Sent: {order} -> partition {metadata.partition}")

producer.flush()
producer.close()
```

```python
# consumer.py — 订单消费者
from kafka import KafkaConsumer
import json

consumer = KafkaConsumer(
    'orders',
    bootstrap_servers='localhost:9092',
    group_id='order-processor',
    auto_offset_reset='earliest',  # 从头消费
    enable_auto_commit=False,      # 手动提交偏移量
    value_deserializer=lambda v: json.loads(v.decode('utf-8'))
)

for message in consumer:
    order = message.value
    print(f"Processing: {order}")
    # 业务处理逻辑...
    consumer.commit()  # 手动提交偏移量
```

### 142. RabbitMQ

**前世今生**

RabbitMQ 由 Rabbit Technologies 公司于 2007 年发布，最初由 Alexis Richardson 和 Matthias Radestock 创立。它的核心实现了 AMQP（高级消息队列协议）0-9-1 标准，这是由摩根大通等金融机构推动的开放消息协议。RabbitMQ 使用 Erlang 语言编写，天生具备高并发和容错特性。2010 年，VMware 收购了 Rabbit Technologies，随后 RabbitMQ 成为 Pivotal Software（后并入 VMware Broadcom）旗下的关键开源项目。RabbitMQ 的最大贡献在于引入了灵活的 Exchange 路由机制——direct、topic、fanout、headers 四种交换机类型让消息路由变得极其灵活。十余年来，RabbitMQ 一直是微服务架构中最流行的消息代理之一，特别适合需要复杂路由逻辑和消息确认机制的业务场景。

**实战案例 1：Python 发布/订阅模式**

```python
# publisher.py — 发布者
import pika
import json

connection = pika.BlockingConnection(
    pika.ConnectionParameters(
        'localhost',
        credentials=pika.PlainCredentials('myuser', 'mypassword')
    )
)
channel = connection.channel()

# 声明持久化 Exchange
channel.exchange_declare(
    exchange='order_events',
    exchange_type='topic',
    durable=True
)

# 发布消息（带路由键）
routing_key = 'order.created.high_value'
message = json.dumps({'order_id': 1001, 'amount': 1500.00})
channel.basic_publish(
    exchange='order_events',
    routing_key=routing_key,
    body=message,
    properties=pika.BasicProperties(
        delivery_mode=2,  # 消息持久化
        content_type='application/json'
    )
)
print(f" [x] Sent '{routing_key}':'{message}'")
connection.close()
```

```python
# consumer.py — 消费者
import pika

connection = pika.BlockingConnection(
    pika.ConnectionParameters('localhost')
)
channel = connection.channel()

channel.exchange_declare(exchange='order_events', exchange_type='topic')

# 声明队列
result = channel.queue_declare(queue='high_value_orders', durable=True)
queue_name = result.method.queue

# 绑定：只接收 high_value 相关消息
channel.queue_bind(
    exchange='order_events',
    queue=queue_name,
    routing_key='order.*.high_value'
)

def callback(ch, method, properties, body):
    print(f" [x] Received {body}")
    # 手动确认（确保消息被处理）
    ch.basic_ack(delivery_tag=method.delivery_tag)

channel.basic_consume(
    queue=queue_name,
    on_message_callback=callback,
    auto_ack=False  # 手动确认模式
)

print(' [*] Waiting for messages. To exit press CTRL+C')
channel.start_consuming()
```

### 143. NATS

**前世今生**

NATS 由 Derek Collison 于 2012 年创建。Derek 曾是 TIBCO Rendezvous 的核心架构师，也在 Google 参与过云计算基础设施开发——他对高性能消息系统有极深的理解。NATS 的设计哲学是"简单、快速、永远在线"：核心代码仅数万行，追求极致的吞吐量和极低的延迟。最初的 NATS Server 用 Ruby 编写（后改为 Go 语言），专门为 Cloud Foundry 平台提供内部服务发现和消息传递。2018 年 NATS 2.0 发布，引入了 JetStream 持久化流引擎，补上了消息持久化能力。2022 年 Synadia 公司成立，商业支持 NATS 生态。如今 NATS 被用于边缘计算、IoT 设备通信和微服务架构，以不到 10MB 的二进制大小提供每秒数百万条消息的处理能力。

**实战案例 1：Go 语言微服务间 NATS 通信**

```go
package main

import (
    "encoding/json"
    "fmt"
    "github.com/nats-io/nats.go"
)

type Order struct {
    ID     int     `json:"order_id"`
    Amount float64 `json:"amount"`
}

func main() {
    // 连接 NATS
    nc, _ := nats.Connect("nats://localhost:4222")
    defer nc.Close()

    // 创建 JetStream 上下文
    js, _ := nc.JetStream()

    // 创建 Stream（持久化）
    js.AddStream(&nats.StreamConfig{
        Name:     "ORDERS",
        Subjects: []string{"orders.created"},
        Storage:  nats.FileStorage,
    })

    // 发布消息到 JetStream
    order := Order{ID: 1001, Amount: 150.00}
    data, _ := json.Marshal(order)
    ack, _ := js.Publish("orders.created", data)
    fmt.Printf("Published: seq=%d\n", ack.Sequence)

    // 订阅（持久化消费者）
    sub, _ := js.Subscribe("orders.created", func(msg *nats.Msg) {
        var o Order
        json.Unmarshal(msg.Data, &o)
        fmt.Printf("Processing order: %+v\n", o)
        msg.Ack() // 手动确认
    }, nats.Durable("order-processor"),
       nats.ManualAck(),
       nats.MaxDeliver(5))

    select {} // 阻塞
}
```

### 144. Apache Pulsar

**前世今生**

Apache Pulsar 最初由 Yahoo! 于 2013 年创建，内部代号为"Kopi"，旨在统一消息传递和流处理管道。2015 年，Yahoo! 将 Pulsar 用于其内部广告平台，处理每日数十亿条消息。2016 年开源并捐赠给 Apache 基金会，2018 年成为顶级项目。Pulsar 的核心创新是其分层架构：Broker 层（无状态，处理消息路由）和 BookKeeper 层（有状态，处理持久化存储）分离，实现了独立的水平扩展。这种架构下的多租户设计、跨地域复制（Geo-Replication）和原生的分层存储（Tiered Storage）能力使其在云原生环境中颇具竞争力。2020 年，Splunk 将 Pulsar 作为其下一代数据平台的基础。目前 Pulsar 由 StreamNative 等公司主导商业化，在腾讯、Yahoo! Japan、Narvar 等企业中得到大规模部署。

**实战案例 1：Java 生产者/消费者**

```java
// 生产者
PulsarClient client = PulsarClient.builder()
    .serviceUrl("pulsar://localhost:6650")
    .build();

Producer<String> producer = client.newProducer(Schema.STRING)
    .topic("persistent://my-tenant/my-namespace/orders")
    .compressionType(CompressionType.ZSTD)
    .sendTimeout(10, TimeUnit.SECONDS)
    .create();

for (int i = 0; i < 100; i++) {
    String msg = String.format("{\"order_id\": %d, \"amount\": %.2f}", i, Math.random() * 500);
    MessageId msgId = producer.newMessage()
        .key(String.valueOf(i % 4))  // 分区键
        .value(msg)
        .send();
    System.out.println("Sent: " + msgId);
}

// 消费者 — 使用 Shared 订阅模式
Consumer<String> consumer = client.newConsumer(Schema.STRING)
    .topic("persistent://my-tenant/my-namespace/orders")
    .subscriptionName("order-processor")
    .subscriptionType(SubscriptionType.Shared)
    .ackTimeout(30, TimeUnit.SECONDS)
    .subscribe();

while (true) {
    Message<String> msg = consumer.receive();
    System.out.printf("Received: key=%s, value=%s\n", msg.getKey(), msg.getValue());
    consumer.acknowledge(msg);
}
```

### 145. Redpanda

**前世今生**

Redpanda 由 Alex Gallego 于 2019 年创立，定位为"Kafka API 兼容但更快更简单的流处理平台"。Alex 在 Akamai 和 Quantcast 工作期间积累了大规模流处理系统的经验，他深知 Kafka 的运维复杂性和性能瓶颈问题。Redpanda 使用 C++ 从头编写，避免了 JVM 的 GC 停顿问题，采用 Raft 协议替代 ZooKeeper 进行元数据管理，使用 Seastar 异步框架实现线程-per-core 架构，在同等硬件条件下可提供 10 倍以上的延迟优势。2021 年，Redpanda 从 Lightspeed 和 GV 获得 5000 万美元融资。Redpanda 完全兼容 Kafka API，意味着现有 Kafka 生态的工具（Connect、Streams）可以无缝切换。2023 年 Redpanda 推出了 Serverless 产品，进一步降低流处理的入门门槛。

**实战案例 2：Redpanda + Spark 实时流处理**

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder \
    .appName("RedpandaStreaming") \
    .getOrCreate()

# 读取 Redpanda 流（使用标准 Kafka Source）
df = spark.readStream \
    .format("kafka") \
    .option("kafka.bootstrap.servers", "localhost:9092") \
    .option("subscribe", "orders") \
    .option("startingOffsets", "earliest") \
    .load()

# 实时聚合
from pyspark.sql.functions import from_json, col, window
schema = "order_id INT, amount DOUBLE"
parsed = df.select(from_json(col("value").cast("string"), schema).alias("data"))
result = parsed.select("data.*") \
    .groupBy(window(col("timestamp"), "1 minute")) \
```

```java
import org.apache.flink.api.common.functions.AggregateFunction;
import org.apache.flink.streaming.api.datastream.DataStream;
import org.apache.flink.streaming.api.environment.StreamExecutionEnvironment;
import org.apache.flink.streaming.api.windowing.assigners.TumblingEventTimeWindows;
import org.apache.flink.streaming.api.windowing.time.Time;
import org.apache.flink.streaming.connectors.kafka.FlinkKafkaConsumer;
import org.apache.flink.streaming.connectors.kafka.FlinkKafkaProducer;

public class OrderStreaming {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env = 
            StreamExecutionEnvironment.getExecutionEnvironment();
        
        // 开启 Checkpoint，保证 exactly-once
        env.enableCheckpointing(60000);

        FlinkKafkaConsumer<String> consumer = new FlinkKafkaConsumer<>(
            "orders",
            new SimpleStringSchema(),
            KafkaConfig.getProperties()
        );

        DataStream<Order> orders = env
            .addSource(consumer)
            .map(json -> JsonParser.parse(json))
            .assignTimestampsAndWatermarks(
                WatermarkStrategy.<Order>forBoundedOutOfOrderness(
                    Duration.ofSeconds(5))
                .withTimestampAssigner((event, ts) -> event.timestamp)
            );

        // 1分钟滚动窗口聚合
        DataStream<OrderSummary> summary = orders
            .keyBy(Order::getRegion)
            .window(TumblingEventTimeWindows.of(Time.minutes(1)))
            .aggregate(new AggregateFunction<Order, Accumulator, OrderSummary>() {
                @Override
                public Accumulator createAccumulator() {
                    return new Accumulator();
                }
                @Override
                public Accumulator add(Order order, Accumulator acc) {
                    acc.count++;
                    acc.totalAmount += order.amount;
                    return acc;
                }
                @Override
                public OrderSummary getResult(Accumulator acc) {
                    return new OrderSummary(acc.count, acc.totalAmount);
                }
                @Override
                public Accumulator merge(Accumulator a, Accumulator b) {
                    a.count += b.count;
                    a.totalAmount += b.totalAmount;
                    return a;
                }
            });

        summary.print();
        env.execute("Real-time Order Aggregation");
    }
```

```python
import apache_beam as beam
from apache_beam import pvalue

class ParseOrderFn(beam.DoFn):
    """解析并过滤无效订单"""
    def process(self, element):
        import json
        try:
            order = json.loads(element)
            if order.get('amount', 0) > 0 and order.get('region'):
                yield beam.pvalue.TaggedOutput('valid', order)
            else:
                yield beam.pvalue.TaggedOutput('invalid', order)
        except:
            yield beam.pvalue.TaggedOutput('invalid', {'raw': element, 'error': 'parse'})

class EnrichOrderFn(beam.DoFn):
    """调用外部服务充实订单信息"""
    def process(self, order):
        # 模拟：调用汇率服务
        order['amount_usd'] = order['amount'] * 0.14
        order['tax_rate'] = 0.08
        order['total'] = order['amount_usd'] * 1.08
        yield order

with beam.Pipeline() as p:
    raw = p | 'ReadKafka' >> beam.io.ReadFromKafka(
        consumer_config={'bootstrap.servers': 'localhost:9092'},
        topics=['raw_orders']
    )
    
    # 多路输出：有效和无效订单分开处理
    results = (
        raw
        | 'ParseJSON' >> beam.ParDo(ParseOrderFn()).with_outputs(
            'invalid', main='valid'
        )
    )
    
    valid_orders = (
        results['valid']
        | 'Enrich' >> beam.ParDo(EnrichOrderFn())
        | 'SerializeToJSON' >> beam.Map(lambda o: json.dumps(o))
        | 'WriteValid' >> beam.io.WriteToKafka(
            producer_config={'bootstrap.servers': 'localhost:9092'},
            topic='enriched_orders'
        )
    )
    
    # 无效消息写入死信队列
    _ = (
        results['invalid']
        | 'WriteDeadLetter' >> beam.io.WriteToKafka(
            producer_config={'bootstrap.servers': 'localhost:9092'},
            topic='dead_letter_orders'
        )
    )
```

```python
# tasks.py — 任务定义
from celery import Celery
import smtplib
from email.mime.text import MIMEText

app = Celery('tasks',
    broker='redis://localhost:6379/0',
    backend='redis://localhost:6379/1',  # 结果存储
)

# 基础异步任务
@app.task(bind=True, max_retries=3, default_retry_delay=60)
def send_welcome_email(self, user_email, username):
    """发送欢迎邮件（带重试机制）"""
    try:
        msg = MIMEText(f'Welcome, {username}!')
        msg['Subject'] = 'Welcome to Our Platform'
        msg['From'] = 'noreply@example.com'
        msg['To'] = user_email
        
        with smtplib.SMTP('smtp.example.com', 587) as server:
            server.starttls()
            server.login('user', 'password')
            server.send_message(msg)
        return f"Email sent to {user_email}"
    except Exception as exc:
        raise self.retry(exc=exc)

# 任务链 — 多步骤流水线
@app.task
def generate_report(user_id):
    # 耗时报表生成
    import time; time.sleep(10)
    return {'user_id': user_id, 'report_url': f'/reports/{user_id}.pdf'}

@app.task
def notify_user(report_result):
    # 报表生成后通知用户
    print(f"Report ready: {report_result['report_url']}")
    return f"User {report_result['user_id']} notified"

# 使用 Chord：并行任务 + 回调
from celery import chord

@app.task
def process_order(order_id):
    return f"Order {order_id} processed"

@app.task
def send_order_confirmation(results):
    # results 是前面所有任务的结果列表
    return f"Confirmed: {results}"
```

**实战案例 2：定时任务配置**

```python
# celeryconfig.py
from celery.schedules import crontab

app.conf.beat_schedule = {
    'daily-report': {
        'task': 'tasks.generate_daily_report',
        'schedule': crontab(hour=2, minute=0),  # 每天凌晨2点
        'args': ('all',),
    },
    'cleanup': {
        'task': 'tasks.cleanup_expired_data',
        'schedule': crontab(hour=3, minute=30, day_of_week='sunday'),
        'kwargs': {'max_age_days': 90},
    },
    'heartbeat': {
        'task': 'tasks.health_check',
        'schedule': 60.0,  # 每60秒
    },
}

# 任务优先级和路由
app.conf.task_routes = {
    'tasks.send_welcome_email': {'queue': 'low_priority'},
    'tasks.process_order': {'queue': 'high_priority'},
}

app.conf.task_acks_late = True
app.conf.task_reject_on_worker_lost = True
app.conf.task_time_limit = 300  # 5分钟硬超时
app.conf.task_soft_time_limit = 240  # 4分钟软超时（抛出SoftTimeLimitExceeded）
```

**进阶技巧：**

- 使用 Flower (`celery -A tasks flower`) 提供 Web 监控面板
- `task_acks_late=True` 确保任务在完成后才确认，防止 Worker 崩溃丢失任务
- Canvas 原语（chain、group、chord、map、starmap）构建复杂工作流
- 利用 `Rate Limit` 控制 API 调用频率：`@app.task(rate_limit='100/m')`
- 生产环境使用 Redis Sentinel 或 RabbitMQ Cluster 实现 Broker 高可用
