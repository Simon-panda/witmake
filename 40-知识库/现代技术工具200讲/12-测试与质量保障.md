# 第12组: 测试与质量保障

软件质量不是测出来的，而是设计出来的——但测试是质量防线的最后一道关。本组涵盖10个核心测试与质量保障工具，从单元测试框架、端到端测试、性能基准到代码规范检查，构成现代软件工程的完整质量保障体系。

### 111. pytest

**前世今生**

pytest 由 Holger Krekel 于 2004 年创建，最初名为 `py.test`，是 Python 社区对 JUnit 风格的 `unittest` 模块的颠覆性改进。在 pytest 之前，Python 开发者只能使用标准库中的 `unittest`（源于 Java 的 JUnit 模式）——需要继承 `TestCase` 类、以 `self.assertEqual()` 方式编写断言、通过 `setUp/tearDown` 管理 fixture。Krekel 敏锐地意识到测试框架应该更 Pythonic：pytest 利用 Python 的 `assert` 语句代替自定义断言方法，通过强大的 fixture 系统替代显式的 setUp/tearDown，用自动发现机制消除样板代码。2015 年 pytest 2.0 引入插件架构后，生态爆发式增长——pytest-cov（覆盖率）、pytest-xdist（并行执行）、pytest-mock、pytest-asyncio 等插件彻底改变了 Python 测试的格局。2024 年 pytest 8.x 发布，已成为 Python 事实上的标准测试框架，被 Django、Flask、NumPy、pandas 等几乎所有主流项目采用，GitHub 超过 11,000 星。

**使用方法与案例**

```bash
# macOS/Linux/Windows
pip install pytest pytest-cov pytest-xdist
```

**常用命令：**

```bash
pytest                           # 运行所有测试
pytest tests/ -v                 # 详细输出
pytest -x                       # 首次失败后停止
pytest -k "pattern"             # 只运行名称匹配的测试
pytest --lf                     # 只运行上次失败的测试
pytest --cov=src --cov-report=html  # 生成覆盖率报告
pytest -n auto                  # 并行执行（pytest-xdist）
pytest --maxfail=3              # 失败 3 次后停止
```

**实战案例 1：参数化测试——减少重复代码**

```python
# test_math.py
import pytest

def add(a, b):
    return a + b

@pytest.mark.parametrize("a,b,expected", [
    (1, 2, 3),
    (-1, 1, 0),
    (0, 0, 0),
    (1.5, 2.5, 4.0),
    (100, 200, 300),
])
def test_add(a, b, expected):
    assert add(a, b) == expected

@pytest.mark.parametrize("a,b", [
    ("hello", "world"),
    pytest.param(None, 1, marks=pytest.mark.xfail(reason="None not supported")),
])
def test_add_strings(a, b):
    assert isinstance(add(a, b), str)
```

**实战案例 2：Fixtures 与依赖注入**

```python
# conftest.py（自动被同目录测试文件使用）
import pytest
import tempfile
import os

@pytest.fixture(scope="session")
def temp_db():
    """创建临时数据库，整个测试会话共享"""
    db_path = os.path.join(tempfile.mkdtemp(), "test.db")
    # 初始化数据库...
    yield db_path
    # teardown: 清理数据库
    import shutil
    shutil.rmtree(os.path.dirname(db_path))

@pytest.fixture
def api_client(temp_db):
    """每个测试函数获得独立的客户端实例"""
    from myapp import create_app
    app = create_app(database_url=temp_db)
    return app.test_client()

@pytest.fixture
def auth_headers(api_client):
    """登录后返回带认证头的客户端"""
    resp = api_client.post("/login", json={"user": "admin", "pass": "secret"})
    token = resp.json["token"]
    return {"Authorization": f"Bearer {token}"}

# test_api.py
def test_get_users(api_client, auth_headers):
    resp = api_client.get("/api/users", headers=auth_headers)
    assert resp.status_code == 200
    assert len(resp.json) > 0
```

**实战案例 3：Mock 外部依赖**

```python
from unittest.mock import patch, Mock
import requests

def fetch_weather(city):
    resp = requests.get(f"https://api.weather.com/{city}")
    return resp.json()["temperature"]

def test_fetch_weather():
    mock_response = Mock()
    mock_response.json.return_value = {"temperature": 25, "humidity": 60}

    with patch("requests.get", return_value=mock_response) as mock_get:
        temp = fetch_weather("Beijing")
        assert temp == 25
        mock_get.assert_called_once_with("https://api.weather.com/Beijing")
```

**进阶技巧：** 使用 `pytest.mark.skipif` 按条件跳过测试；`conftest.py` 支持层级继承，子目录的测试自动获取父目录的 fixture；`pytest --durations=10` 显示最慢的 10 个测试；`pytest.ini` 或 `pyproject.toml` 统一配置；`@pytest.fixture(autouse=True)` 隐式注入 fixture。

### 112. vitest

**前世今生**

vitest 由 Anthony Fu 和 Vladimir Sheremet 于 2021 年底创建，是 Vite 生态系统中对标 Jest 的测试框架。在 vitest 出现之前，前端测试的标配是 Jest（2014 年由 Facebook 创建）。但随着 Vite 在 2020 年崛起并成为 Vue/React 项目的首选构建工具，Jest 与 Vite 的兼容性问题日益突出——Jest 运行在 Node.js 环境中使用 `jest-haste-map` 和自定义的模块解析，需要复杂的 `transform` 配置才能处理 ESM、TypeScript 和 JSX。vitest 的设计目标简单而雄心勃勃：将 Vite 的极速开发体验带到测试中——利用 Vite 的转换管道（esbuild/SWC）实现原生 ESM 支持、热模块替换（HMR）级别的测试重跑、与 Vite 配置文件完全兼容。2022 年 vitest 1.0 发布后迅速成为 Vite 项目的默认测试方案，并在 2024 年 2.0 版本中引入了浏览器模式（`@vitest/browser`），GitHub 超过 13,000 星，被 Nuxt 3、Slidev 等项目采用。

**使用方法与案例**

```bash
# npm
npm install -D vitest

# pnpm
pnpm add -D vitest

# yarn
yarn add -D vitest
```

**常用命令：**

```bash
npx vitest                    # 运行测试（watch 模式）
npx vitest run                # 单次运行
npx vitest --ui               # 打开 Web UI
npx vitest --coverage         # 覆盖率（需 @vitest/coverage-v8）
npx vitest related src/App.tsx  # 只测相关文件
npx vitest --reporter=verbose # 详细报告
```

**实战案例 2：API Mock 与计时器控制**

```typescript
// api.test.ts
import { describe, it, expect, vi, beforeEach } from 'vitest'

// Mock 整个模块
vi.mock('./api', () => ({
  fetchUser: vi.fn()
}))

import { fetchUser } from './api'
import { getUserName } from './user'

beforeEach(() => {
  vi.clearAllMocks()
})

it('returns user name on success', async () => {
  vi.mocked(fetchUser).mockResolvedValue({ id: 1, name: 'Alice' })
  const name = await getUserName(1)
  expect(name).toBe('Alice')
})

it('handles fetch timeout', async () => {
  vi.useFakeTimers()
  vi.mocked(fetchUser).mockImplementation(() =>
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('Timeout')), 5000)
    )
  )
  const promise = getUserName(1)
  vi.advanceTimersByTime(5000)
  await expect(promise).rejects.toThrow('Timeout')
  vi.useRealTimers()
})
```

### 113. cypress

**前世今生**

Cypress 由 Brian Mann 于 2014 年创建，2017 年首次公开发布。在 Cypress 之前，端到端（E2E）测试领域被 Selenium（2004 年）主导。Selenium 通过 WebDriver 协议驱动浏览器，虽然覆盖面广但存在根本性的架构缺陷：测试代码在 Node.js 进程运行，通过 HTTP 发送命令到浏览器驱动，再转发到浏览器——这种多层网络通信导致测试既慢又不可靠（flaky）。Brian Mann 的洞察是：将测试代码与应用程序运行在同一个浏览器事件循环中，消除网络延迟，获得对 DOM、网络请求、计时器的原生控制能力。Cypress 运行在浏览器内部，可以直接拦截和修改 XHR/Fetch 请求（无需额外代理）、实时截图和录屏、提供时光旅行式的调试体验。2021 年 Cypress 10.x 引入组件测试模式，使其成为同时支持 E2E 和组件测试的全栈框架。截至 2025 年，Cypress 在 GitHub 上拥有超过 47,000 星，下载量超过每周 600 万次。

**使用方法与案例**

```bash
# macOS/Linux/Windows
npm install -D cypress
# 或
yarn add -D cypress
```

**常用命令：**

```bash
npx cypress open              # 打开交互式测试运行器
npx cypress run               # 无头模式运行所有测试
npx cypress run --spec "**/login.cy.js"  # 运行特定文件
npx cypress run --browser chrome         # 指定浏览器
npx cypress run --headed                 # 有头模式
```

**实战案例 1：用户登录流程 E2E 测试**

```javascript
// cypress/e2e/login.cy.js
describe('Login Flow', () => {
  beforeEach(() => {
    cy.visit('/login')
  })

  it('successfully logs in with valid credentials', () => {
    // cy.get 自动等待元素出现（内置重试）
    cy.get('[data-cy="email-input"]')
      .type('user@example.com')
    cy.get('[data-cy="password-input"]')
      .type('Password123!')
    cy.get('[data-cy="login-button"]')
      .click()

    // 断言跳转到仪表盘
    cy.url().should('include', '/dashboard')
    cy.get('[data-cy="welcome-message"]')
      .should('contain', 'Welcome back')
    // 检查 localStorage 中存储了 token
    cy.window().its('localStorage')
      .invoke('getItem', 'auth_token')
      .should('exist')
  })

  it('shows error for invalid credentials', () => {
    cy.get('[data-cy="email-input"]').type('wrong@example.com')
    cy.get('[data-cy="password-input"]').type('wrong')
    cy.get('[data-cy="login-button"]').click()

    cy.get('[data-cy="error-alert"]')
      .should('be.visible')
      .and('contain', 'Invalid credentials')
  })
})
```

**实战案例 3：自定义命令封装复用逻辑**

```javascript
// cypress/support/commands.js
Cypress.Commands.add('loginByApi', (email, password) => {
  cy.request('POST', '/api/auth/login', { email, password })
    .its('body.token')
    .then(token => {
      window.localStorage.setItem('auth_token', token)
    })
})

Cypress.Commands.add('dataCy', (selector) => {
  return cy.get(`[data-cy="${selector}"]`)
})

Cypress.Commands.add('shouldBeLoading', () => {
  cy.dataCy('loading-spinner').should('be.visible')
})

// 在测试中使用
cy.loginByApi('admin', 'pass')
cy.dataCy('submit-btn').click()
cy.shouldBeLoading()
```

**进阶技巧：** 使用 `data-cy` 属性代替 CSS 选择器，让测试更稳定且不受样式变更影响；`cy.session()` 缓存登录状态，避免每个测试重复登录；`cypress.config.js` 中设置 `defaultCommandTimeout` 调整等待超时；`cy.task()` 在 Node.js 环境中执行数据库操作或文件 I/O。

### 114. playwright

**前世今生**

Playwright 由微软于 2020 年 1 月开源，核心团队来自 Google 的 Puppeteer 项目（包括 Andrey Lushnikov 等原 Puppeteer 主要维护者）。Puppeteer（2017 年）开创了通过 Chrome DevTools Protocol 以编程方式控制浏览器的范式，但它只支持 Chromium。Playwright 的设计目标更为宏大：通过单一 API 同时支持 Chromium、Firefox 和 WebKit 三大浏览器引擎，打通跨浏览器测试的最后壁垒。Playwright 的架构创新在于使用浏览器厂商支持的调试协议（CDP for Chromium、Juggler for Firefox、Playwright 自定义协议 for WebKit），而不是 WebDriver 标准，从而获得更底层、更可靠的控制能力。Playwright 还首创了自动等待（auto-waiting）机制——在执行点击、输入等操作前自动检查元素是否可操作，大幅减少了测试中的 `sleep()` 调用和 flaky。2023 年 Playwright 引入组件测试模式和 UI 模式，2024 年推出 Codegen 2.0 录制器。截至 2025 年，Playwright 在 GitHub 上拥有超过 67,000 星，已成为跨浏览器 E2E 测试的行业标准。

**使用方法与案例**

```bash
# npm
npm init playwright@latest

# 或手动安装
npm install -D @playwright/test
npx playwright install  # 安装浏览器
```

**常用命令：**

```bash
npx playwright test                    # 运行所有测试
npx playwright test --ui               # UI 模式
npx playwright test --headed           # 有头模式
npx playwright test --project=chromium # 指定浏览器
npx playwright test --debug            # 调试模式
npx playwright codegen                 # 录制测试代码
npx playwright show-report             # 查看 HTML 报告
```

**实战案例 3：API 测试（直接发 HTTP 请求）**

```typescript
import { test, expect } from '@playwright/test';

test.describe('REST API', () => {
  const API_URL = process.env.API_URL || 'http://localhost:3000';

  test('CRUD operations for users', async ({ request }) => {
    // Create
    const createResp = await request.post(`${API_URL}/api/users`, {
      data: { name: 'Alice', email: 'alice@test.com' }
    });
    expect(createResp.status()).toBe(201);
    const user = await createResp.json();

    // Read
    const getResp = await request.get(`${API_URL}/api/users/${user.id}`);
    expect(await getResp.json()).toMatchObject({ name: 'Alice' });

    // Update
    const updateResp = await request.put(`${API_URL}/api/users/${user.id}`, {
      data: { name: 'Alice Smith' }
    });
    expect(updateResp.status()).toBe(200);

    // Delete
    const deleteResp = await request.delete(`${API_URL}/api/users/${user.id}`);
    expect(deleteResp.status()).toBe(204);
  });
});
```

**进阶技巧：** `playwright.config.ts` 中配置 `retries` 和 `workers` 实现失败重试和并行执行；`test.use({ storageState: 'auth.json' })` 复用登录状态；`page.waitForResponse()` 等待特定网络请求完成；使用 `trace: 'on-first-retry'` 在失败重试时自动生成 Playwright Trace 用于调试。

### 115. k6

**前世今生**

k6 由瑞典公司 Grafana Labs（前身为 Load Impact）于 2017 年开源。它的前身是 Load Impact 的 SaaS 性能测试平台（2009 年创立），经过多年商业运营积累的经验被重新设计为开发者优先的开源工具。k6 的核心创新在于用 Go 编写性能引擎（保证高并发下的低资源消耗），同时允许测试脚本使用 JavaScript 编写——兼顾了性能与开发体验。与传统的 JMeter（1998 年，Java/GUI 驱动）相比，k6 的脚本化、代码化（as-code）方法完美融入了现代 CI/CD 管道。k6 采用事件循环模型而非每个虚拟用户一个线程，单个实例即可模拟数万并发用户。2021 年 k6 被 Grafana Labs 收购后，与 Grafana 可观测性栈深度集成（k6 Cloud、Grafana 仪表盘），并推出了 `xk6` 扩展框架支持自定义协议。截至 2025 年，k6 在 GitHub 上拥有超过 25,000 星，被 GitLab、Netflix、Adidas 等公司用于生产环境的负载测试。

### 116. hyperfine

**前世今生**

hyperfine 由 David Peter（sharkdp，也是 fd 和 bat 的作者）于 2018 年创建。在 hyperfine 之前，命令行基准测试通常依赖 `time` 命令或 hand-rolled bash 循环，但这些方法存在严重的统计缺陷：单次运行受系统抖动影响巨大、无法排除冷启动效应、缺乏统计分析、输出格式不友好。David Peter 敏锐地发现了这个领域的需求缺口——开发者需要一个类似科学实验的基准测试工具，具备预热运行（warm-up）、多轮统计、异常值检测和友好的输出格式。hyperfine 用 Rust 编写以保证计时精度，自动计算均值、标准差、最小/最大值，还内置了统计显著性检验。它填补了 `perf` 等底层性能分析工具和手写脚本之间的空白，成为命令行工具基准测试的事实标准。截至 2025 年，hyperfine 在 GitHub 上拥有超过 22,000 星。

### 117. eslint

**前世今生**

ESLint 由 Nicholas C.     docs: {
```javascript
      description: '禁止使用已弃用的旧 API',
    },
    schema: [
      {
        type: 'object',
        properties: {
          deprecatedAPIs: { type: 'array', items: { type: 'string' } },
        },
      },
    ],
  },

    return {
      CallExpression(node) {
        if (node.callee.type === 'MemberExpression') {
          const objectName = node.callee.object.name;
          const methodName = node.callee.property.name;

            context.report({
              node,
              message: `'${fullName}' is deprecated. Use new API instead.`,
            });
          }
        }
      },
    };
  },
};
```

### 120. faker

**前世今生**

Faker 起源于 2004 年 Ruby 社区的 `faker` gem（由 Benjamin Curtis 创建），用于在测试中生成逼真的假数据。2009 年 PHP 版 `Faker`（由 François Zaninotto 创建）将其发扬光大，支持几十种语言的本地化数据。2013 年 JavaScript 版 `faker.js` 由 Marak Squires 创建，迅速成为 npm 生态中最受欢迎的测试数据生成库。然而 2022 年 1 月发生了著名的"faker.js 事件"——作者 Marak 因财务困境故意破坏了自己的库（发布空包版本 6.6.6），导致数千个项目受损。社区迅速 fork 并创建了 `@faker-js/faker`，由 8 名核心维护者共同管理，建立了透明的治理机制和可持续的发展模式。新组织在 9 个月内发布了 v8，引入了模块化架构、TypeScript 重写和更好的树摇（tree-shaking）支持。Faker 的独特之处在于它不仅能生成随机数据，还能生成语义上一致的数据——一个 `firstName` 的性别与 `prefix` 匹配，`zipCode` 与 `state` 对应。截至 2025 年，`@faker-js/faker` 每月下载量超过 1500 万次。

```typescript
// src/mocks/handlers.ts
import { faker } from '@faker-js/faker';

export function createMockProduct() {
  return {
    id: faker.string.alphanumeric(10),
    name: faker.commerce.productName(),
    description: faker.commerce.productDescription(),
    price: parseFloat(faker.commerce.price({ min: 10, max: 500 })),
    category: faker.commerce.department(),
    inStock: faker.datatype.boolean({ probability: 0.85 }),
    rating: faker.number.float({ min: 1, max: 5, fractionDigits: 1 }),
    tags: faker.helpers.multiple(() => faker.commerce.productAdjective(), { count: 3 }),
    createdAt: faker.date.recent({ days: 30 }),
  };
}

export function createMockOrder() {
  const items = faker.helpers.multiple(createMockProduct, {
    count: faker.number.int({ min: 1, max: 5 })
  });
  const subtotal = items.reduce((sum, item) => sum + item.price, 0);

  return {
    id: faker.string.uuid(),
    customer: {
      name: faker.person.fullName(),
      email: faker.internet.email(),
    },
    items,
    subtotal: parseFloat(subtotal.toFixed(2)),
    tax: parseFloat((subtotal * 0.08).toFixed(2)),
    total: parseFloat((subtotal * 1.08).toFixed(2)),
    status: faker.helpers.arrayElement(['pending', 'shipped', 'delivered']),
    orderDate: faker.date.recent({ days: 7 }),
  };
}

// 在 MSW (Mock Service Worker) 中使用
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/products', () => {
    const products = faker.helpers.multiple(createMockProduct, { count: 20 });
    return HttpResponse.json({ data: products, total: 100 });
  }),

  http.get('/api/orders/:id', ({ params }) => {
    const order = createMockOrder();
    order.id = params.id as string;
    return HttpResponse.json(order);
  }),
];
```

```python
from faker import Faker
import json

fake = Faker('zh_CN')

def generate_test_data(n: int) -> list[dict]:

# 生成 SQL 插入语句
def generate_sql_inserts(table: str, rows: int) -> str:
    statements = []
    for _ in range(rows):
        statements.append(
            f"INSERT INTO {table} (name, email, city) VALUES "
            f"('{fake.name()}', '{fake.email()}', '{fake.city()}');"

    return "\n".join(statements)
```
